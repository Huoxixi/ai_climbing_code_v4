# 试运营部署包

2026-10-18 现行发布以 `browser-only` 配置和 [完整 App/轻量网页发布说明](../docs/完整App入库与轻量网页发布_2026-10-18.md) 为准。GitHub 保存完整 App，服务器仅装独立网页和轻量静态后台；仍使用原固定发布入口、门禁、备份和原子切换。用户已授权退役原服务器完整项目，数据与配置保留。下文私有试运营是历史建设记录。

本目录用于 1–5 人、30 天私有试运营。当前通过独立 SSH 密钥和本地端口转发访问，不得把 Nginx、FastAPI 或 Vite 开发端口直接暴露到公网。域名、备案和公网 HTTPS 留到正式上线阶段。

## 目录内容

- `nginx/`：操作入口只监听 `127.0.0.1:8080`，只读入口只监听 `127.0.0.1:8081`。
- `systemd/`：单进程后端、每日备份和五分钟健康记录。
- `scripts/`：服务器门禁、数据迁移、发布、备份、恢复、回退及每日检查。
- `env/`：不含密钥的生产配置模板。
- `ssh/`：试运营 SSH 隧道账号的最小权限策略。
- `tailscale/`：将来改为私有网络访问时可选的最小权限策略示例。
- `journald/`：30 天日志保留上限。

## 安全原则

1. `/root/ai_climbing_code` 只用于 GitHub 同步和构建。
2. `/opt/ai-climbing/releases` 保存不可变程序版本。
3. `/var/lib/ai-climbing/data` 保存真实数据，发布脚本不会覆盖它。
4. `/etc/ai-climbing` 保存生产配置，权限受限且不进入 Git。
5. 数据恢复必须交互输入准确的 `确认执行`；程序回退不回退数据。
6. 每日和发布前备份必须上传并重新下载校验，缺少对象存储配置时任务失败。
7. 每位参与者使用独立的 SSH 密钥和隧道账号；老师的账号仅能转发到只读入口。

完整执行顺序见 `docs/试运营上线运维手册.md`，参与者连接方法见 `docs/SSH隧道试运营接入说明.md`。
