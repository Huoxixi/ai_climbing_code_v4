# 前端企业级改版设计报告

生成时间：2026-05-21

## 1. 改版目标

本次改版目标是将原有“所有功能集中在单一工作台页面”的前端，升级为更接近企业级 SaaS / 控制台产品的使用体验。

核心目标包括：

- 降低页面信息密度，避免所有功能挤在同一页中。
- 建立清晰的功能页导航，让用户按任务进入不同工作区。
- 引入成熟企业级 UI 框架 Element Plus，为后续表单、弹窗、卡片、导航等组件化升级打基础。
- 强化视觉层级、状态表达、卡片分区和专业控制台质感。
- 保留原有核心能力：登录、AI 生成、岩点库管理、岩点池、岩板编辑、动作序列、保存岩板、属性编辑等。

## 2. 原有问题分析

### 2.1 信息架构问题

原有 `frontend/src/App.vue` 承载了几乎全部功能：

- 岩点库上传与管理
- 攀爬者画像配置
- 收藏岩板列表
- 定线岩点选择
- 岩点池
- AI 生成按钮与状态
- 岩板画布
- 岩板快捷岩点池
- 动作序列编辑
- 岩板属性与选中岩点属性

这些功能集中在一个页面内，会造成用户认知负担过高，且缺乏企业级应用常见的“工作区切换”和“任务分流”。

### 2.2 视觉问题

原有页面虽然具备暗色风格，但更接近功能原型：

- 页面缺少明确的导航体系。
- 卡片层级与全局视觉系统不统一。
- 资源管理、AI 配置、路线设计、资产管理混杂在同一视觉区域。
- 状态信息缺少仪表盘式展示。

### 2.3 可维护性问题

当前 `App.vue` 文件体量很大，模板、状态、业务逻辑、样式耦合严重。长期看建议继续拆分为页面组件和通用 UI 组件。

## 3. 设计策略

### 3.1 采用“多工作区控制台”模式

本次改版采用顶部功能导航，将系统划分为以下工作区：

1. **总览**：展示系统状态、关键指标、快捷入口和最近岩板。
2. **路线设计**：承载岩板画布、岩点池、动作序列和属性编辑。
3. **AI 定线**：聚焦攀爬者画像、目标难度、特殊要求与生成入口。
4. **岩点资源**：聚焦岩点上传、资源查看和删除。
5. **岩板资产**：聚焦已保存岩板、重命名、删除和载入。

### 3.2 视觉方向

本次设计参考了企业级控制台常见范式：

- 深色专业控制台背景。
- 科技蓝作为主色，暖橙作为攀岩/岩点相关强调色。
- 卡片化信息承载。
- 顶部状态栏 + 工作区导航 + 内容区域。
- Dashboard 仪表盘式入口。

### 3.3 UI 框架策略

已引入：

- `element-plus`
- `@element-plus/icons-vue`

当前阶段主要完成框架接入和可用基础，后续可继续用 Element Plus 重构表单、抽屉、表格、消息提示和弹窗。

## 4. 页面结构说明

### 4.1 顶部栏

顶部栏展示：

- 产品品牌：智能定线企业工作台
- 当前编辑模式
- 当前岩点数量
- 未保存状态
- 用户登录入口或用户信息

### 4.2 工作区导航

新增 `workspace-switcher`，通过 `activeWorkspace` 控制不同工作区展示。

导航项包括：

- 总览
- 路线设计
- AI 定线
- 岩点资源
- 岩板资产

### 4.3 Dashboard 总览页

新增总览页用于承载：

- 当前岩点数
- Beta 动作数
- 已保存岩板数
- 资源岩点数
- 当前难度
- 编辑状态
- 候选岩点池数量
- 快速开始入口
- 最近岩板预览

该页面用于提升产品完整度，让系统不再直接进入高复杂度编辑区。

### 4.4 路线设计页

保留原有核心编辑工作台能力，主要用于：

- 岩板画布编辑
- 岩点拖拽/放置
- 岩点池选择
- 保存、清空、新建、AI 生成
- Beta 动作序列查看与编辑
- 岩板与岩点属性编辑

### 4.5 AI 定线页

通过工作区过滤显示与 AI 生成相关的配置内容，弱化不相关区域，降低用户在生成任务中的干扰。

### 4.6 岩点资源页

通过工作区过滤突出岩点库管理模块，让上传和管理成为独立任务。

### 4.7 岩板资产页

通过工作区过滤突出收藏岩板管理模块，让已保存资产的加载、重命名和删除更加明确。

## 5. 成功标准

本次改造满足以下标准：

- 已新增多工作区导航。
- 已新增 Dashboard 总览页。
- 已引入 Element Plus。
- 已保留原有业务逻辑和接口调用。
- 已完成生产构建验证。
- 已保存设计报告和修改报告到本地。

## 6. 构建验证结果

执行命令：

```bash
npm --prefix frontend run build
```

结果：构建成功。

构建输出摘要：

- `✓ 1623 modules transformed.`
- `✓ built in 1.71s`

构建警告：

```text
Some chunks are larger than 500 kB after minification.
```

原因：当前 Element Plus 采用全量注册方式接入，构建产物中的 JS chunk 较大。

后续建议：

- 使用 Element Plus 按需导入。
- 使用动态 `import()` 拆分 Dashboard、Studio、Library 等页面。
- 配置构建分包策略。

## 7. 后续优化建议

建议下一阶段继续做以下工程化重构：

1. 将 `App.vue` 拆分为 `pages/DashboardPage.vue`、`pages/StudioPage.vue`、`pages/GeneratorPage.vue`、`pages/HoldLibraryPage.vue`、`pages/BoardsPage.vue`。
2. 抽取 `AppTopbar`、`WorkspaceSwitcher`、`MetricCard`、`PanelCard`、`HoldPoolPanel` 等组件。
3. 将业务逻辑拆入 composables，例如 `useHoldLibrary`、`useRouteGeneration`、`useBoardPersistence`。
4. 将 `alert/confirm/prompt` 替换为 Element Plus 的 `ElMessage`、`ElMessageBox`。
5. 为资产页增加表格、搜索、筛选和分页。
6. 为 AI 定线页增加更完整的任务进度时间线。

## 8. 追加设计决策：模拟系统优先与 AI 软封印

追加时间：2026-05-21 晚

### 8.1 产品主叙事调整

在本轮追加改造后，前端主叙事从“智能定线企业工作台”进一步调整为：

> 攀岩岩板模拟设计系统。

新的默认用户路径为：

1. 选择底层岩板模板。
2. 创建空白模拟岩板。
3. 组合岩点池。
4. 点击孔位或拖拽岩点上墙。
5. 编辑岩板属性与 Beta 动作序列。
6. 保存并管理岩板资产。

AI 定线不再是 Dashboard 或 Studio 的主操作入口。

### 8.2 新工作区结构

新的工作区结构为：

| 工作区 | 定位 |
| --- | --- |
| 总览 | 模拟系统入口、模板选择、资源统计、最近岩板 |
| 岩板设计 | 主编辑器：规格选择、岩点池、岩板画布、属性与动作序列 |
| 岩点资源 | 岩点素材上传与管理 |
| 岩板资产 | 已保存岩板的载入、重命名、删除 |
| AI 实验室 | 封印态说明页，保留未来恢复空间 |

### 8.3 AI 软封印策略

采用“软封印”而不是彻底删除：

- 导航中保留 `AI 实验室`。
- AI 页面显示“功能暂时封印”的说明。
- 生成按钮与主 CTA 不再引导用户调用 AI 定线。
- `generateRoute()` 保留为未来恢复点，但当前只触发封印提示。

该策略降低了对旧代码的破坏，同时让产品当前版本明确聚焦模拟设计。

### 8.4 岩板模板抽象

本轮新增 `boardTemplates` 抽象层，将岩板规格从固定 `11 × 18` 提升为模板系统：

```js
{
  id: 'studio-14x20',
  template_key: 'spray-medium',
  label: '扩展训练板',
  columns: 14,
  rows: 20,
  width: 560,
  height: 760,
  xLabels: ['A', 'B', ...],
  yLabels: [1, 2, ...]
}
```

设计收益：

- 保存的岩板可以携带自己的 `board_spec`。
- 旧岩板缺少规格时可回落到 `classic-11x18`。
- 坐标轴、孔位、落点映射、新建空白板都可以由规格驱动。
- 后续支持倾角、训练墙、比赛墙等扩展会更自然。

### 8.5 当前设计边界

当前阶段仍属于渐进式重构：

- `App.vue` 仍是主容器，尚未完成页面级组件拆分。
- Dashboard 已接入 `BoardTemplatePicker`，但 Studio 画布仍未独立为 `BoardCanvas`。
- 旧 `Wall.vue` / `WallDisplay.vue` 仍保留固定规格逻辑，后续需要统一升级或废弃。
- 本轮按用户要求未执行构建验证，因此设计报告仅记录结构审查，不新增构建结论。

### 8.6 更新后的后续优化优先级

建议后续按以下顺序推进：

1. 页面拆分：`DashboardPage`、`StudioPage`、`HoldLibraryPage`、`BoardsPage`、`AILabSealedPage`。
2. 画布拆分：抽出 `BoardCanvas`，统一动态规格与拖拽落点。
3. 资源拆分：抽出 `HoldPoolPanel`、`HoldLibraryPanel`。
4. 属性拆分：抽出 `InspectorPanel` 与 `BetaSequencePanel`。
5. 旧组件治理：升级或移除仍写死 `11 × 18` 的旧墙体组件。
6. 在允许时补充构建验证与浏览器回归。
