# 抱石知识库 Agent：建设与执行计划书

日期：2026-09-25；执行方式：本地、按需启动、按批交付。

## 目标

搭建可重复调用的知识库建设 Agent，持续完成“读取缺口—检索原始资料—核查主张—编写知识单元—校验入库—保存进度”。第一轮同时交付工具和真实知识内容，以“落脚与身体转移”为试运行主题。

知识内容继续采用[抱石知识库完善计划](AI攀岩复盘_抱石知识库完善计划_2026-09-25.md)中的框架。本计划改用里程碑推进，替代此前按工作日估算的排期；每批都交付可查看的成果。

| 组成 | 实现与用途 |

| 行为验证 | 用实际检索入库和独立模拟复盘检验工作流程；记录不足，不以文件格式通过代替内容正确 |

自定义 Agent 与技能分别采用官方说明的[项目级配置](https://learn.chatgpt.com/docs/agent-configuration/subagents)和[技能目录](https://learn.chatgpt.com/docs/build-skills)。技能也可在当前主任务直接调用；配置文件是否被客户端发现和实际运行效果分别验证。此版本依赖运行中的 Codex，不是无人值守服务。

## 本轮交付顺序

1. 写完本计划，建立来源/知识格式、Agent、技能和进度结构。
2. 对“脚部接触与转移”检索原始资料，编写 6 个知识单元：落脚、内外侧踩点、踩墙、换脚、Rock over、高抬脚。
3. 运行结构与证据引用校验、问题检索、进度读取，生成阅读手册。
4. 用独立 Agent 对技能做一次有限范围的行为试用；据结果修订。
5. 保存批次日志与下一批入口，交付实际完成数量、验证结果和剩余缺口。

本轮不接入视频业务代码，不调用额外付费分析服务，不上传用户图片、视频、`.local/` 或密钥。未来需要自动执行或产品接入时再建立相应运行任务。

## 知识单元与证据

每个单元包含：名称和别名、所解决的问题、动作目的与配合、适用/不适用条件、应观察的视频事件、不同可能解释、补信息或调整方向、复盘要点、来源与具体定位。

来源中的原始说法、适用于抱石的迁移解释、我们提出的观察/教学假设分别保存。资料获取、AI 核对、专业人员复核、真实视频验证和产品启用各有独立状态。第一批内容用于解释与辅助复核，自动技术建议保持关闭。

来源台账记录原始 URL、作者或机构、访问日期、版本/时间、具体章节/段落、实际支持的主张及不能支持的结论。未取得全文或示范仅为图片时保留待核，不虚构页码、实验结论或已审核状态。

## 一轮任务如何续做

- 启动时先读状态，选择用户指定主题；无指定主题时处理最早的待办批次。
- 每轮以一个主题为边界，通常产出 5—10 条；依据不足时记录缺口，数量不作为强制凑齐的要求。
- 检索过程保留查询、来源、采纳理由和排除项，避免下轮重复搜集同一材料。
- 完成后先校验，再更新状态和日志；中断时保存已完成内容与下一项，下一轮重新检查文件。
- 资料矛盾保留双方适用条件；没有来源的具体主张不得改写为“公认原理”。

## 验收与完成含义

- Agent 和技能有明确入口，能读取持久进度并查询既有内容。
- 首批知识不是空模板；每条运动知识主张有可定位的来源，原创规则有明确标记。
- 编号、来源引用和调用范围通过工具检查；缺失证据与未经验证的自动建议被拦截。
- 至少有一次实际检索编写过程和一次独立行为试用记录。
- 手册、来源和进度相互一致；后续任务能据此继续。

“本轮完成”表示本地工作流程和首批内容可用，不表示所有抱石知识已补完、专业审核已完成，或视频 AI 已获得可靠技术诊断能力。
