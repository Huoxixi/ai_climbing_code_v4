# 个性化攀岩复盘：修改报告与建议边界

日期：2026-09-26
适用范围：成人室内抱石，新手与进阶者，单次录像复盘。
文档性质：基于当前本地实现与一次真实报告检查形成的修改方案。文中“已完成”仅指已实现并检查的程序行为；“拟修改”“放行目标”均不代表已经交付或达到效果。本文不批准知识条目、不替代专业审核、不安排生产部署。

## 一、修改结论

第一版应收紧为：**找出一处值得核对的现象；只有画面、知识和适用条件都通过检查时，才给出一项下次可验证的调整。**

优先提升“实际输出建议中正确且适用的比例”，同时公开能给建议的覆盖率。允许暂时没有建议，但不能把空报告算作建议正确，也不能用免责声明掩盖错误结论。

具体收紧方向：

1. 默认零至一项技术建议。取消首版自动输出三项的目标，后续经验证再扩展。
2. “值得回看”与“应该改善”分开。停顿、重复调整和掉落只用于选择核对片段，不直接判为问题。
3. 不输出数字置信度。先展示可核验的证据状态，模型自评分不能作为准确率。
4. 暂停个性化伤害风险判断，以及要求新增复杂技术的动作处方。
5. 每项建议都要经过独立画面复核、知识主张匹配、条件检查和边界检查；任一关键项未知则降级或不输出。
6. 在付费生成前告知本次可能只有观察、费用范围与上限；生成后分别列出姿态和个性化分析费用。

这是一项产品取舍：先把少量、具体、能核对的建议做可靠，再扩大能力范围。收紧边界本身并不证明准确率提高，必须以独立素材的评估结果验证。

## 二、现状与问题诊断

### 2.1 已核实的事实

| 项目 | 当前情况 | 对用户的影响 |
|---|---|---|
| 真实报告样本 | 本次检查的录像约 14.1 秒，64 张抽样画面，8 项观察，0 项技术建议 | 只能代表这一份报告，不能推断总体准确率 |
| 知识审核 | 本地 24 个知识单元尚无通过自动技术建议门槛的条目 | 当前不能交付经过专业审核的个性化动作建议 |
| 视觉输入 | 图片序列抽样，默认最多 64 帧、最长边 768 像素 | 不是逐帧完整审阅；局部细节和快速过程可能缺失 |
| 观察质量 | 旧报告部分内容依赖叠加标注，存在单帧描述动作过程及与现有记录不一致的问题 | 看似具体，不代表事实正确 |
| 首要重点 | 旧逻辑把最早的观察作为回看方向 | 普通起步会被误读为最需要改进的地方 |
| 知识解释 | 用单元内的来源摘要解释具体片段，部分内容过长且不贴合情境 | 用户难以分辨概念介绍与个人原因判断 |
| 费用 | 旧报告只存两次调用的合计用量 | 可以估范围，不能恢复逐次准确档位 |

### 2.2 已完成的修正

- 首页突出有依据的首要重点；缺少可用建议时明确说明，不再默认推荐最早动作。
- 其他观察折叠展示，长知识说明收进依据，时间文字去除无意义长小数。
- 生成提示明确禁止把骨架、接触标签和岩点编号当作独立画面事实。
- 增加对明显标注依赖、部分单帧动作叙述和非法时间引用的过滤。
- 新报告记录逐次模型用量并估算费用；历史报告按合计用量显示范围，缺失数据不显示零元。
- 生成规则版本参与去重，用户主动重新生成可使用新规则，旧报告不被静默改写。

针对上述修正，相关后端 50 项、前端展示与浏览器 13 项检查通过，生产构建通过。检查证明程序行为符合测试条件，**不证明动作观察、重点选择或技术建议已经准确**；修正后尚未重新生成真实视频报告做效果验证。

### 2.3 尚存的关键缺口

1. **提示与文本过滤不能验证画面事实。** 模型不提“标注”两字，也可能照抄标注；换一种说法可能绕过正则过滤。
2. **两个时间点只是最低引用要求。** 两帧之间发生什么仍可能不可见，不能据此证明动作顺序、次数、完整接触过程或因果关系。
3. **观察阶段已接收个人背景和目标。** 可能把“用户想改脚法”变成“画面一定有脚法问题”，或受身材信息影响而解释动作。
4. **检索是词语匹配。** 命中一个技术名、标题或单元，不等于其适用于成人抱石、本次墙面和当前动作。
5. **审核门槛主要位于知识单元层级。** 一个单元同时含研究摘要、产品规则和教学假设；单元获准不应让所有主张自动变成建议。
6. **建议的条件目前主要是模型生成的文字。** 非空并不等于条件已成立；程序未逐项核对其证据与未知状态。
7. **第二阶段整理建议时不重新查看画面。** 如果第一阶段事实错误，后续可以生成引用完整但前提错误的建议。
8. **模型排序缺少独立验收。** 目标相关、现象显著与“对表现影响最大”不是一回事。
9. **费用记录主要在成功报告生成末尾汇总。** 前一步已经收费、后一步失败或撤回时，完整用量与费用可能无法展示。

上述问题是后续修改的对象，不应通过扩大知识权限或换更强模型来跳过。

## 三、收紧后的输出合同

### 3.1 三种正常结果

| 结果 | 可以告诉用户什么 | 不可以告诉用户什么 |
|---|---|---|
| 可提出一项尝试 | 经核实的现象、适用条件、一个调整方向及验证方式 | “这是你的根本问题”“一定更省力”“这样不会受伤” |
| 只能核对片段 | 为什么值得回看、需要确认哪件可见事实 | 把核对问题写成隐含动作指令 |
| 资料不足 | 哪一段或哪个部位看不清，补充什么有帮助 | 为满足报告格式凑建议、把无提醒写成安全 |

“没有建议”要给出具体原因：画面不可见、事件采样不足、记录冲突、条件未知、没有获准知识，或候选未通过复核。不能全部写成“置信度低”。

### 3.2 第一批技术建议的候选范围

以下仅是**待验证白名单**，不是现阶段可以开放的能力。每一类须单独通过教练审核和视频验收。

首批仅验证固定机位、相关手脚与下一目标清晰、以缓慢连续移动为主的片段。多墙面、强透视、人物交叠、关键鞋部被挡以及快速协调过程暂限于观察；不能仅以“成人室内抱石”符合范围就开放建议。墙面倾角和岩点握持条件看不清时，不采用依赖这些条件的主张。

| 候选类型 | 必要条件 | 可以形成的建议方向 | 不允许外推 |
|---|---|---|---|
| 已有脚序的预先确认 | 前后脚部和相关落点可见，目标动作明确，调整现象经确认 | 在保留已有动作方案的前提下，先确认下一步脚序，再验证是否仍需反复调整 | 调整多就是脚法差；强行指定模型猜测的新脚点 |
| 同一落点的落脚准备 | 鞋与落点过程清晰，接触身份可靠，后续动作可见 | 核对落脚前的瞄准或准备，按已审核方案尝试一项变化 | 凭单帧判断踩点受力、摩擦力或脚尖角度 |
| 已有动作的衔接准备 | 前一动作、停顿及后一动作可见；未改变线路任务 | 检查执行前是否已确认下一目标，验证衔接变化 | 停顿一定是错误；规定必须更快或不能休息 |

这类建议也不能凭“通常正确”直接输出。若片段不足以说明调整与用户目标有关，则保留为观察。

### 3.3 第一版暂停的内容

- 新增或改变动态跳跃、协调动作、勾脚／挂脚、强制转膝、极端转体、抓握方式等技术处方。
- 指定看不清的下一岩点，规划整条线路唯一解，计算真实可达距离。
- 从二维姿态推断承重、重心的真实三维位置、关节负荷、拉力或精确角度。
- 从一次停顿或失败推断力量不足、恐惧、疲劳；用户自述这些情况也不能自动成为失败原因。
- 按身高、体重、性别或攀龄评价能力、身材，安排减重、康复或长期训练。
- 诊断伤病、预测个人受伤概率、宣称某项调整降低个人受伤风险，或把某类技术一概判为危险。
- 因少输出或表达更流畅而宣称建议准确率、完攀率或体力节省得到提升。

### 3.4 伤害相关边界

本次建议进一步收紧：**第一版不开放针对画面生成的个性化伤害风险结论。** 经专业审核的通用安全说明可以独立展示，但不能包装成“已识别你会受伤的动作”。用户自述不适或活动限制时，暂停针对相关部位的动作调整建议；展示经审核的处理提示，具体诊疗与康复仍交由专业人员判断。

画面事实、用户自述、研究中的群体关联须分别记录。群体关联不能换算成个人概率，也不能直接证明这次动作的原因。成人攀岩过度使用损伤综述指出，部分风险因素的证据存在分歧；该研究讨论的过度使用损伤也不能直接作为落地或急性损伤的判断依据。[研究综述](https://pubmed.ncbi.nlm.nih.gov/38162697/)

没有风险提醒始终不表示已经确认安全。

## 四、证据与生成链路修改

### 4.1 先检查是否值得启动付费分析

生成前检查视频可读性、时长、目标片段范围、当前标注版本、知识可用情况与费用预算。

- 没有视频，不调用视觉模型。
- 获准知识为零，提前说明“本次仅能整理画面观察，不能生成技术建议”；用户明确选择后才启动该模式，不以“生成改进建议”诱导付费。
- 已有相同输入与版本的成功结果，优先直接复用；进行中的同一任务不重复创建。
- 输入不符合成人室内抱石范围，结束建议生成，不迁移到其他运动或医疗场景。

### 4.2 将“看到了什么”与“解释什么”分开

推荐流程：

**资料检查 → 无个人背景的画面观察 → 候选片段复核 → 按主张检索 → 适用条件检查 → 一项建议 → 独立边界核验 → 报告。**

观察阶段仅接收必要画面和定位信息，不接收身高体重、用户对原因的猜测或教学结论。用户选择的时间范围可以决定重点采样；其目标在排序阶段使用，不能改变画面事实。

第二次看画面时以“找反证”为任务：所述肢体是否可见、接触是否成立、是否还有正常解释、视频标签是否造成误导。相同模型的第二次检查仍可能与第一次一起出错，因此它只是附加过滤，不能替代独立人工验收。

### 4.3 保留标注用于定位，优先用无叠加画面核对

不重新运行原有姿态和岩点识别。拟新增与复盘时间对应的无叠加核对画面：只使用已有、授权且可对应时间的分析副本。原视频已删或缺失时，不悄悄恢复、延长保留或改变删除策略。

只有叠加视频时，继续保留其播放能力；对标注覆盖的关键部位或依赖标签的候选降低输出等级。裁切、遮盖不能恢复已被标注遮住的细节，不把处理后的画面当成原始证据。

应记录实际媒体类型、时间对应关系、修订版本和遮挡情况。人工修正与旧标注冲突时，动作记录用于定位，结论仍需画面支持；不能自动选择“更新的记录一定正确”。

### 4.4 按现象追加局部采样，设定停止条件

全段抽样只用于寻找候选。对候选局部检查动作前、动作中、动作后；是否足够由现象决定，而不是固定“已有两帧即可”。

- 静止位置：单帧可用于有限描述，不能证明动作过程。
- 可见位置变化：需前后画面，并核对中间遮挡或离开画面。
- 重复次数、先后顺序、接触过程：必须有覆盖这些事件的时序证据；只允许描述实际可见部分。
- 快速动作：局部采样仍缺失关键时刻时，标记无法判断，不用插值补事实。

追加采样须受画面数、请求次数和费用预算限制。达到限制仍不能核实时结束该候选，不无限请求直到模型给出肯定回答。

## 五、知识库与条件门槛

### 5.1 从“单元可用”改为“具体主张可用”

保留现有审核状态，不批量开启 24 个单元。优先选少量候选类别，由抱石教练完成可追溯审核。

每条可执行主张须明确：适用人群与场景、必要可见条件、排除条件、允许的调整模板、不能推出的结论、验证方法、来源对应段落、审核人与记录、版本及停用状态。

研究摘要只能支持其原始结论；产品规则不是专业证据；教学假设必须保留“待验证”状态。单元内一个主张获准不能连带批准其他主张。

审核记录不能只检查字符串非空，应核验对应记录真实存在、批准了该主张与版本，且未撤回。模型不能编造审核编号或改变权限。

### 5.2 检索命中之后仍须检查适用性

先按成人抱石、动作类别、场景和审核权限筛选，再做词语或语义检索。首版运行时继续只用本地知识，不开放实时网络补结论。

逐项确认候选观察是否满足该主张的必要条件。顶绳、竞赛动态、一般生物力学或群体研究不能因为术语相同就直接套到当前室内抱石片段。

条件采用三种状态：已满足、已不满足、未知。每个“已满足”都要引用画面事实或当前用户自述；自述仅能证明其报告的情况，不能证明身体能力或画面事件。必要条件未知或不满足则不输出该建议，不能让模型用一句“如果适用”代替检查。

## 六、个人信息与首要重点

### 6.1 个人信息只在确有用途时使用

| 信息 | 允许用途 | 禁止用途 |
|---|---|---|
| 本次目标、关注片段 | 决定分析范围与合格候选的排序 | 为迎合目标而编造问题 |
| 身高、臂展 | 经知识支持时筛选条件性替代解释，注明自述与未校准 | 精确计算可达距离、保证某个动作能做到 |
| 攀龄、常爬难度 | 调整术语和解释深度，核对建议是否超出经验范围 | 推断实际力量、体能或掌握某技术 |
| 体重 | 首版保留选填与本次快照，不作为常规建议输入 | 判定动作原因、关节负荷、身材或减重需求 |
| 疲劳、不适、活动限制 | 保留自述来源；限制相关建议的输出 | 替代诊断，或直接归因本次失败 |

字段可跳过；缺填不等于没有不适。报告列明真正使用了哪些信息；未使用的敏感字段不发送给模型。已填写体重也不意味着必须用于分析。

“对线路熟悉程度”继续不恢复为输入项。若某条未来建议确实依赖动作意图，可在该片段提出一个具体核对问题，不增加常驻问卷。

### 6.2 首要重点先过门槛，再排序

先过滤事实不可靠、条件不成立、知识不合格和超范围的候选。只在剩余候选中，依次比较：与本次目标是否有关、是否有具体可验证的一项改变、对当前衔接是否有明确关联、证据是否充分。

排序规则需要教练在独立视频上验证；模型不得因为候选出现早、持续久、听起来严重或容易写建议而优先。

若多个候选无法合理区分，说明“目前无法判断哪一项更优先”，可给一个回看问题，不宣称“最大短板”。没有目标时，只选画面支持的核对点，不能承诺“对你最重要”。

## 七、报告表达与交互

### 7.1 默认阅读顺序

1. 结果状态：可以尝试／先核对／资料不足。
2. 唯一首要重点：一段时间、一句现象、一项调整或核对问题。
3. 下次验证：要观察什么；必要时列明不适用条件，避免强行执行。
4. 本次费用：个性化分析与原有姿态费用分别显示，可查看合计范围。
5. 可展开依据：前中后画面、知识主张、个人信息用途和不确定性。

静态“置信度高／低”标签改为证据状态，例如“脚部被遮挡，不能判断换脚过程”“有前后画面，接触仍需确认”“观察与建议条件已通过复核”。最后一种状态只有新增复核流程真正通过后才可使用。

### 7.2 语言规则

- 每项只有一个主要现象和一个尝试方向，避免“多注意脚法、放松、减少用力”这类无法执行的总结。
- 用“哪只手／脚、在哪段时间、发生什么变化”描述事实，避免大段术语和论文原文。
- 可能原因最多保留一个最相关且有依据的解释，并写清不能排除的情况；没有证据时不解释原因。
- 字数以一句观察、两三句调整与验证为目标，不靠省略关键条件换取简短。
- 专业来源收进依据；不把不相关研究摘要挂到个人观察下，造成已被研究证明的错觉。

构造示例，仅示范表达，不代表当前视频事实或已获准建议：

> **先核对 6–8 秒的脚部调整。** 画面候选显示，下一次出手前同一只脚的位置有两次变化。请先回看确认它是在重新落脚，还是为转身做准备。现在不能据此判断脚法有问题，也不能直接建议减少调整。

通过全部建议门槛后，才使用这种结构：

> 对应片段 → 已核实的现象 → 为什么这项调整与本次目标有关 → 一个获准调整及必要条件 → 下次可见验证指标。

### 7.3 反馈用于定位错误，不直接学习

保留“看错了／不适用／有帮助”。增加可选具体原因：部位看错、时间错误、知识不相关、条件不成立、表达不清或重点不对。

“有帮助”是体验反馈，不等于建议正确或有效；“看错了”进入人工审核队列，不自动改知识、模型或历史报告。修改事实后，旧报告标示依据变化，由用户主动重新生成。

## 八、费用与运行可靠性

### 8.1 费用显示

按每一次请求的模型、地域、输入档位、输入／输出 token 计算公开价估算，并保存价格版本。北京 Qwen3-VL-Plus 当前公开档位按单次输入量分段：≤32K 为每百万输入 ¥1、输出 ¥10；32K–128K 为 ¥1.5／¥15；128K–256K 为 ¥3／¥30。超过支持范围或未知模型时显示无法估算，不套用其他模型价格。[官方计价说明](https://help.aliyun.com/zh/model-studio/model-pricing)

生成前的预估与生成后的用量估算分开标识；历史合计用量只报范围。另列免费额度／优惠未计入，不承诺与最终账单一致。

建议初期本地实验每次总调用预算设为 ¥0.20，作为**待实测调整的内部上限**，并非固定用户价格。新增局部复核会改变费用，应先测量用量再制定正式上限，不根据这一份样本承诺所有录像都只需几分钱。

### 8.2 失败、取消与预算

- 每次响应返回后立即记录最小用量信息，不等报告完全成功；失败报告也展示已知调用费用。
- 超时或连接断开不能确认供应商是否已计费时，标记“费用可能不完整”，不显示免费。
- 禁止隐式自动重试付费请求；用户重试前说明可能追加费用。
- 发起下一次调用前检查剩余预算与请求次数。对已发出的调用不能保证精确硬停费，需以最大输出、输入限额和预留预算控制风险。
- 取消后停止后续调用，保留必要状态与已知用量；已发送内容不能宣称从供应商端撤回。
- 无合格观察时停止技术建议整理；无合格知识时采用简短观察报告，不进行无意义的建议生成调用。

## 九、隐私、版本与异常

沿用所属账号可见和删除机制，不上传真实视频、个人信息、密钥或模型原始内容用于公开调试。

本次云端说明须对应实际接收方、画面类型、必要字段和用途。新增发送无叠加画面、局部截图或新个人信息时检查是否超出原告知范围；超出则更新说明与本次选择，不能用原姿态服务授权代替。

临时画面随任务清理；报告保存必要的帧时间、媒体／数据／知识／模型／规则版本，不为审计额外永久保存全部截图。删除复盘时继续一并清理报告、历史与背景。付费用量记录按既定删除与留存规则处理，不以记账为由无限保留可识别信息。

新增异常要求：

| 情况 | 必须行为 |
|---|---|
| 媒体删除或版本改变 | 中止依赖它的后续步骤，旧报告明确失效或待更新 |
| 视频标签与人工修正冲突 | 冲突候选不进入建议，展示具体疑问 |
| 模型只给流畅总结、没有有效证据 | 返回资料不足，不用后续文字模型补画面事实 |
| 字段或条件无效 | 拒绝该条目并记录不含敏感内容的原因码 |
| 知识审核撤回 | 禁止继续使用该版本；旧建议提示依据不可继续使用 |
| 同账号重复点击、页面切换、服务重启 | 不产生隐式重复付费任务；状态可恢复或明确失败 |
| 跨账号访问、外链素材、视频中或用户文字的指令 | 不越权，不让数据中的指令改变模型规则或知识权限 |

旧报告保留原文与版本，不静默改写为新版正确结果。明显越界的旧条目默认不作为行动建议展示，并提示重新核对；显示费用补算也须标注为估算。

## 十、效果验收：证明建议更准确，而非看起来更自信

### 10.1 建立两套独立材料

开发素材用于修规则、提示和采样；验收素材在规则冻结后使用，不能反复调参后仍称独立验收。同一用户、同一线路或同次尝试的近似片段避免跨集合泄漏。

覆盖清晰与遮挡、快与慢、正常与确有改进空间、无目标与指定目标、不同身材与经验、未填写背景、自述不适、旧标注冲突、无匹配知识。用于效果评价的片段必须明确授权，构造测试只检查程序。

两名有成人抱石教学经验的审核者先独立标注画面事实、建议是否适用和可接受的首要重点范围，不要求唯一正确动作；分歧经讨论或第三人复核。高分歧的类别暂缓自动建议，不让多数投票掩盖证据不足。

### 10.2 指标定义

| 指标 | 计算与用途 |
|---|---|
| 关键观察正确率 | 关键事实经人工核实正确的比例；时间、肢体和实际可见变化均计入 |
| 已输出建议正确且适用率 | 同时通过事实、知识主张、适用条件、调整方向与验证方法审核的建议数／输出建议数 |
| 建议覆盖率 | 输出至少一项建议的录像数／全部范围内验收录像数；另列清晰片段等分组覆盖率 |
| 合格机会覆盖率 | 对人工认为存在可支持建议的录像，系统给出合格建议的比例；不能把正常录像的无建议算漏检 |
| 首要重点可接受率 | 人工认为系统第一项属于合理优先范围的比例，不只检查有没有第一项 |
| 正常动作误判率 | 人工认为无须改善的动作被系统标为技术问题的比例 |
| 应拒绝时的误建议率 | 遮挡、冲突、必要条件未知等场景仍输出动作建议的比例 |
| 理解与可用性 | 用户能否说出要验证的一项变化，并找到对应视频依据 |
| 成本与延迟 | 每次尝试的费用，包括失败、无建议和重试；中位数与高分位耗时 |

每类单独报告分母、样本量与不确定区间。拒绝样本不计为建议正确，不能通过删掉困难素材或合并大量同视频片段抬高结果。

### 10.3 建议的试点放行目标

以下为拟定验收目标，需要在采样计划冻结时确认，**不是当前结果或对外承诺**：

- 每个开放建议类别至少覆盖 60 次独立尝试的验收材料，包含正常及需拒绝场景；某类输出建议过少、无法估计正确率时继续补样，不能仅凭录像总数放行。
- 已输出建议正确且适用率点估计至少 95%，95% 不确定区间下界至少 90%；按独立尝试计数，若有同用户／线路相关性则用适当分组估计，不能当作独立样本。
- 关键观察正确率至少 95%，首要重点可接受率至少 90%；同时公布正常动作误判、拒绝场景误建议和各分组覆盖率。
- 预设禁止内容、越权访问及关键条件未知仍给处方的验收案例不得出现违规；有限样本中的零错误不代表真实世界风险为零。
- 用户理解测试中至少 90% 能指出唯一尝试重点并找到依据；收集失败原因，不能只问“是否满意”。

样本不足、教练分歧明显或某个场景表现不达标，只关闭对应类别／场景，不把其他类别的平均值作为放行理由。是否应提高阈值由实际误差后果和试点结果决定。

### 10.4 对照与回归

在同一独立集合比较旧流程与收紧流程，分别检查无叠加画面、局部复核、按主张匹配和条件门槛的作用。比较正确率时同时比较覆盖率、可理解程度与单次尝试成本；不能只展示一个有利数字。

当前真实知识库不输出技术建议，因此旧流程的技术建议正确率没有有效分母，不能记作零分再宣称新流程提升。当前可比较观察与重点质量；技术建议的对照须在受控评估中使用相同的已审核主张与素材，分别运行不同流程，评估结果不直接开放给用户。

模型、提示、采样、审核知识、排序或画面压缩变化均应触发对应类别回归。稳定快照模型可减少变化来源，但供应商支持的图像／视频能力并不证明攀岩专项效果。[视觉理解文档](https://help.aliyun.com/zh/model-studio/vision)

## 十一、交付顺序与完成标准

| 阶段 | 工作与负责人 | 完成条件 |
|---|---|---|
| P0：明确现在能做什么 | 产品／前端：零至一项模式、无获准知识的付费前告知、状态和原因；后端：失败用量记录、预算与去重 | 用户在生成前知道可能无技术建议，费用与结果状态不误导 |
| P1：把事实与建议拆开 | 后端：移除观察阶段非必要背景、局部时序复核、媒体冲突检查、主张级条件门槛和拒绝原因 | 构造案例覆盖正常、遮挡、快速、冲突及绕过表达，不靠正则作为唯一门槛 |
| P2：只验证少量类别 | 抱石教练：批准少量具体主张；评估负责人：冻结独立材料、盲审、分组指标；开发：修复并重验 | 每个拟开放类别达到其放行要求；记录未开放类别和原因 |
| P3：小范围使用 | 产品／运营：明确告知试验范围，持续收集误观察与不适用反馈；开发：监控成本、延迟与版本 | 用户知道一项下一步，问题可定位可关闭；需要时退回观察模式 |

风险主张的专业审核另立任务，第一版不以技术类别通过验收为由自动开放伤害判断。生产发布仍需单独明确任务。

必须补齐的测试包括：事实不存在但引用合法、两帧不能证明事件、同义表达绕过过滤、错误来源却检索命中、条件文字非空但证据未知、未审核主张混入获准单元、用户自述被写成画面事实、目标诱导、审核记录不存在或已撤回、失败阶段已收费、超时用量未知、重复点击、旧报告与新数据冲突、账号隔离和删除清理。

最终交付标准：**有建议时，用户能指出一项有条件的尝试与对应依据；无建议时，用户能知道具体缺少什么且费用透明。开放的建议类别通过独立效果验收，范围之外保持拒绝或观察。**
