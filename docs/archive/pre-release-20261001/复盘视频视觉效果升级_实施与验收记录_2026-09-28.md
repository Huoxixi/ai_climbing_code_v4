## 实现要点

- 参考图使用已有墙面参考帧编号，冻结尺寸、媒体摘要、参考图片摘要和坐标版本。轮廓、纹理与同肢体连线使用统一变换。没有为照片线路引入新识别链路。
- 先在独立轻量进程生成并完整解码短尾段，再一次顺序输出正文和尾段。正文不因为新任务的增强而先输出再重编码。历史手动重做可复用有效基础视频，会明确进行一次新的输出。
- 新结果先写临时文件、校验后再更换媒体指针；取消、失败和输入版本变化保留原可播放文件。缓存/成片只允许匹配同一输入与视觉版本。
- 照片推理、视频转换、正文编码和尾段合成共用跨线程、跨进程资源名额，按阶段释放，禁止嵌套获取。任务队列有容量上限；等待资源不阻塞已有视频播放请求。
- 新尾段准入要求可用内存至少 1024 MiB；运行要求至少 768 MiB；进程树 RSS 超过 768 MiB 或超时 120 秒停止。取消会回收子进程树和确切的部分视频文件。阈值是保护策略，不是服务器能力证明。
- `result.visual_replay` 分别记录分析帧数/时长、尾段开始/时长、总时长及原时间到展示时间映射。教练首轮抽帧和局部复核补帧均排除动画；不一致元数据会拒绝分析。
- 参考图服从账号隔离及媒体删除/过期机制，不延长原视频保留期。旧任务素材不足时明确说明，不能恢复已经删除的原视频。

## 测试与证据

v2 工程基准报告见 [10 次运行明细](../../replay-visual-evidence-20260928/benchmark-v2/continuous/resource-report.json)。它早于最终 v2.1 遮挡修订，最终真实视频指标单独记录。测试机器可见内存约 20285 MiB、16 个逻辑处理器，属于本地工作站。短尾段单次生成含编码和完整解码验证：

| 指标 | 本地实测 |
| --- | --- |
| 成功次数 | 连续 10 次 |
| 画幅/帧率 | 720×1280 与 1280×720；24 与 30 FPS |
| 单次最大耗时 | 18.578 秒 |
| 渲染进程树最高 RSS | 126.64 MiB |
| 系统最低可用内存 | 8597.93 MiB |
| 剩余临时视频 | 0 |

这些数字是短尾段独立进程的成绩，不能推断 4 GiB 服务器可承载量。[v2 全成片增量测试](../../replay-visual-evidence-20260928/benchmark-v2/full-output/full-output-report.json) 使用相同 2 秒实墙静止源及演示记录，基础版 2.500 秒、增强版 27.969 秒，真实增量 **25.469 秒**，包含临时尾段编码、验证和最终再次编码；父进程与渲染器合计峰值 **229.19 MiB**。v1 此项为 32.376 秒未达目标，v2 通过局部文字合成和末秒单帧复用优化。该标准样片成绩不代替真实长视频的整链路验收。

已有验证包括：同时事件不拆散、同肢体连线、低可信记录排除、坏素材拒绝、最后一整秒静止、图片摘要校验、横竖屏无露边；真实子进程取消/超时/内存停止与跨进程排队；教练取样和局部扩帧边界；播放器跳转、重试和失效状态。

前端 116 项单元测试、教练 75 项测试、原教练 11 项浏览器测试、新播放器 2 项浏览器测试通过，前端构建通过。最终新增后端组合回归 **44 项通过**（14.868 秒），包含渲染器、资源保护、真实编码集成、确定性并发和教练边界，以及 v2.1 的近时可靠遮挡判断与无可靠观测退让。手机视口模拟不等同真实 iPhone/Safari。

真实视频证据另有 8 项一致性检查通过，包括原素材摘要一致、58 帧姿态记录保持原样、尾段 18 个事件与真实接触记录的肢体/岩点/原时刻/源帧一一相符、428 帧正文加 240 帧尾段等于 668 帧成片。最终遮挡修订前后，原素材、原分析证据、复核证据和基础版视频摘要均未变化，未新增模型请求。

最终 v2.1 成片已在 Chromium 的 1280 与 390 像素宽视口复验：正文播放到 4.000 秒、点击尾段实际呈现 14.267 秒、拖动实际呈现 18.500 秒，均以解码帧回调核对。无页面异常、媒体错误或横向溢出。预览服务支持 HTTP Range，206 响应及指定区间字节准确；下载的 16,358,786 字节与本地成片摘要一致。记录和截图位于同一私有临时目录的 `browser-v21-verification.json`、`ui-v21-1280-tail.png` 与 `ui-v21-390-tail.png`。该检查覆盖真实成片的播放、跳转和下载，不代表普通应用服务已经重启或手机实机门槛通过。
