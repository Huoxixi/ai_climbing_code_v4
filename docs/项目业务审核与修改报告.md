# 攀岩定线辅助系统业务审核与修改报告

报告范围：本地单机版的工作台、定线工作台、岩点库、岩板库、标准线路库、AI
实验室及共享导航。仿真审核业务按约定不在本报告中评判或整改，只检查共享构建与入口未被破坏。

报告结论：系统已经从“功能入口多但业务承诺不一致”的开发原型，整改为能够向老师和非技术客户
真实说明能力边界的本地演示版。核心流程可闭环：查看有来源的标准线路 → 复制为未保存副本 →
在定线工作台编辑并保存为草稿或可检查线路 → 对 11×18 完整线路做 AI 组合或审核 →
归档并恢复本地资产。

## 二、线路生命周期与业务规则

统一后的生命周期如下：

1. `草稿`：允许保存，但名称、坐标、岩点数量、起终点或 Beta 尚不完整。
2. `可检查`：名称、6–14 个有效岩点、手脚起点、最后三排终点和可重建 Beta 均完整。
3. `AI 可用`：已经可检查，且岩板规格为 11×18、40°。
4. `已归档`：日常列表隐藏，可在归档箱恢复，历史图片、映射与向量仍保留。

| 等级 | 审核发现 | 修改结果 | 验证证据 |
| --- | --- | --- | --- |
| P0 | 保存与 AI 入口没有使用同一套完整性规则 | 新增共享完整性判定；保存返回状态、问题清单和 AI 可用性 | `test_release_readiness` |
| P0 | 非 11×18 岩板可能进入仅针对标准板设计的 AI 流程 | 14×20、16×24、18×22 明示“仅手工定线”，AI 服务端再次拦截 | 前后端发布测试 |
| P1 | 起点只看手点，缺少低位脚点；登顶点位置和类型不明确 | 至少一个 Y1–Y5 手起点、一个 Y1–Y5 脚起点；最后三排至少一个非脚点登顶动作 | 完整性单元测试 |
| P1 | 旧评级把 Jug 类型与 V0–V2 强绑定 | 删除等级相关 Jug 规则，统一保留起步、终点、可攀性和岩点适用性检查 | 完整性单元测试 |
| P1 | 标准线路、修复和 AI 候选载入后看起来像已经保存 | 所有外部来源复制统一标记“未保存副本”，原始线路不被覆盖 | 前端发布契约与交互检查 |
| P1 | “删除”会让资产和历史线路显示能力消失 | 岩板、岩点改为软归档并增加恢复；旧 JSON 兼容为未归档 | 归档恢复测试 |

## 三、AI 实验室真实性审核

| 等级 | 整改前问题 | 修改结果 | 客户可用表述 |
| --- | --- | --- | --- |
| P0 | 自由文本需求不会稳定改变算法，却暗示可控制生成 | 移除自由文本框；组合改为“质量优先、目标难度优先、动作风格多样” | “每个选项都对应确定的排序策略” |
| P0 | Beta 不完整时可能输出完整动作审核口吻 | 无法重建双手和至少一脚时，只输出“岩点布局初审” | “系统会明确告诉我们本次检查到哪一层” |
| P0 | 平衡判断没有严格按动作顺序重建四肢接触 | 顺序重建 LH/RH/LF/RF，检查不存在岩点、无效重复、肢体与岩点类型、缺失登顶 | “动作状态可追溯，不靠文字猜测” |
| P1 | 大模型可能被误解为安全结论来源 | 排序、难度、安全结论全部来自确定性规则；大模型仅润色名称和说明 | “模型负责表达，不负责改判定” |
| P1 | 旧接口字段可能让旧客户端立刻失效 | 新增 `generation_goal`、`review_focus`；旧 `user_requirements` 仅兼容且标记废弃 | 不在客户界面宣传旧字段 |

## 四、标准线路库审核

现以 Font 作为产品唯一公开评级体系，统一顺序为 6B、6B+、6C、6C+、7A、7A+、7B、
7B+、7C、7C+、8A、8A+、8B、8B+。标准线路保留 MoonBoard 原始等级；自有线路依据
11×18、40° 真实数据给出 MoonBoard 等效难度、可信度和校准状态。非该规格岩板显示“未校准”。

列表和详情补充原始名称、来源 ID、定线者、MoonBoard 原始等级、模型复核等级、可信度、
重复次数、Benchmark 标记和来源链接；名称、ID、定线者搜索及每页 24 条分页均由
服务端返回可靠 `total`。标准源文件按修改时间缓存，审核队列只在内容变化时原子替换，降低
重复计算和并发损坏风险。

总览页不再设置固定线路推荐区。这避免把少量样例误解为系统唯一推荐结果，也让首页保持资产与工作状态总览的职责。标准线路原始数据没有删除，用户仍可在线路库中按名称、来源 ID 或定线者检索，并将所选线路复制为待编辑、待保存的本地副本。

## 六、数据整改和可恢复性

- 原有四条重复命名、无来源的样例均增加 `archived_at`，没有物理删除。
- 岩点归档只改变元数据状态；图片、映射和向量保留，历史线路仍可解析。
- 本地 JSON 写入使用进程内文件锁、临时文件、刷新落盘和原子替换。
- 数据读取兼容旧记录；缺少新字段时按“未归档”处理，不做破坏性迁移。
- 本次规则与数据调整登记在 `backend/data/modification_log.json`。

## 七、岩板多板对照与 AI 重组可视化

| 项目 | 修改结果 | 验证证据 |
| --- | --- | --- |
| 通用岩板对照 | 岩板资产页增加“资产列表 / 岩板对照”；仅允许选择 2–4 块已启用岩板，第一块为基准，可设为基准、移出或清空 | 实测 3 块启用岩板可选择，归档记录不出现在选择器 |
| 真正只读 | 对照画布的孔位和岩点全部禁用、不可聚焦，不触发放置或选择；读屏名称改为“查看”口径 | 浏览器统计对照画布可操作按钮为 0 |
| 确定性差异 | 坐标及类型、变体、旋转、缩放、起终点角色由前端规则比较；保留、新增、移除、修改同时使用颜色、文字徽标和坐标清单 | 单元测试覆盖四类差异、起终点、Beta 和规格差异 |
| 动作可读性 | 岩点旁显示 Beta 序号，画布下方列出完整左右手脚动作序列 | 浏览器读屏树可读取每个动作和目标坐标 |
| 复用率 | 以“完全保留岩点数 ÷ 基准岩点数”计算；70% 为最优、40% 为通过，其余为变化较大 | 实测 Shrine 3 重组候选移除 G7，复用率 89%，达到最优标准 |
| AI 候选真实性 | 最多返回两块互不相同、且不同于原岩板的有效候选；不足两块时明确说明，不复制原板 | 实测只生成 1 块有效候选，并明确提示无第二块 |
| AI 可视化 | 结果直接并排展示原岩板与候选板，说明坐标、终点、Beta、质量、预测难度、中文风险和复用等级 | 实测候选把 Beta 从 9 步缩短为 8 步，风险显示为“低（20）” |
| 任务响应 | CPU 密集的路线搜索移出接口事件循环，提交后立即返回任务号并正常轮询 | 修复浏览器实测出现的 30 秒请求超时 |
| 响应式 | 桌面按 2/3/4 板布局；窄屏使用横向滚动和吸附，页面本身不横向溢出 | 1440、1024、390 三档页面宽度均与视口一致 |

不同规格岩板可以并排查看，但界面明确提示“坐标只按名称比较，不代表物理位置完全一致”，
不会据此输出不可靠的物理尺度优劣结论。对照选择只存在于当前页面，没有写入本地文件或数据库。

## 八、验证结果

2026-07-18 本轮重新验证：后端非仿真测试 69/69 通过；前端单元与发布契约测试 11/11 通过；生产构建通过。总览旧推荐入口移除、已知旧岩板规格名称兼容归一和离线 HTML 汇报均纳入本轮验收。

- 后端非仿真测试：69/69 通过，其中包含候选上限、候选去重、单候选不伪造、英文模型回复拦截和中文审核重点检查。
- 前端单元与发布契约测试：11/11 通过，其中包含四类岩点差异、复用率、不同规格提示、模板真实性、旧规格名称归一、总览推荐入口移除和 AI 中文结果显示。
- Python 编译检查：通过。
- 前端生产构建：通过。
- 首屏 JS：584.05KB；仿真懒加载 JS：22.94KB。
- JSON 数据文件解析：通过。
- 真实浏览器：请求 1440、1024、390 三档视口；标准线路页页面宽度均等于滚动宽度，无横向溢出。
- 旧设定清理：三档页面均未出现木纹/防滑/竞赛板面材质、旧商业型号名、`Studio`、`AI Lab` 或“虚拟点亮”等过时表述；7 张汇报截图已重新生成。
- 标准线路：服务端每页 24 条；搜索 `Jonty` 返回 2 条，详情显示 Jonty、MoonBoard 原始 7A、模型复核状态和来源链接。
- 修复候选：加载期使用骨架屏；加载后 3540 条候选按 24 条分页，内部英文状态未出现在客户界面。
- 移动端定线工作台：孔位透明命中区实测为 44×44px，读屏名称为“在 A1 放置岩点”。
- 移动端岩点库：页面无横向溢出，上传主按钮在首屏可见，并提供归档箱入口。
- 归档箱：旧样例日常列表为 0 条，归档箱为 4 条且全部显示恢复操作。
- AI 实验室：不存在自由文本需求输入控件；组合与审核分别使用结构化选项，切页后滚动位置为顶部。
- 多板对照：1440px 双栏清晰展示；390px 使用页面内横向滚动，`bodyScrollWidth === bodyClientWidth`。
- AI 重组：原板和 1 块真实不同候选直接展示；实测移除 G7、终点保持 D17、Beta 9→8、复用率 89%。
- 浏览器控制台：0 条 error / warning。
