# AI 攀岩复盘动作命名体系与标签词典

版本：v0.1
日期：2026-09-21
适用阶段：PRD 阶段一 / 发布阶段 A，供动作时间线、复盘建议和知识库共同使用
上游报告：[知识库范围与评价边界报告](AI攀岩复盘_知识库范围与评价边界报告_2026-09-21.md)
证据地图：[知识库文献检索与证据地图](AI攀岩复盘_知识库文献检索与证据地图_2026-09-21.md)

## 1. 目标

系统必须为攀爬者的每个动作建立稳定名称，使用户能够回答：

1. 这是第几个动作？
2. 哪个肢体从哪里移动到哪里？
3. 这是新上点、调整、匹配、换手，还是其他动作关系？
4. 如果存在明确技术特征，它属于哪一种技术动作？
5. AI 对名称有多大把握，用户能否修改？

动作名称不是装饰性文案，而是视频、时间线、问题定位、改进建议和复攀比较之间的共同索引。任何建议都必须引用动作编号和动作名称。完整的产品词汇见：[AI 攀岩复盘攀岩动作中文总表](AI攀岩复盘_攀岩动作中文总表_2026-09-21.md)。

现有动作顺序中的“左手、右手、左脚、右脚”保持不变。基础动作名和技术标签只在旁边作为中文补充，不替换现有主标签。

## 2. 核心原则

### 2.1 每个动作必须有基础名称

只要能确认肢体和接触变化，系统就必须生成基础名称。即使无法识别专业技术，也不能留下“未知动作”或只显示一个序号。

最低可用名称示例：

- `动作 07 · 左手换点 H04→H09`
- `动作 08 · 右脚原点调整 F03`
- `动作 09 · 双手匹配 H12`

### 2.2 技术标签不是基础名称

“交叉手、旗式、drop knee、heel hook、dyno”等属于技术标签。技术标签需要更多姿态、速度、墙面和接触证据；识别不足时可以没有标签，但基础名称仍然存在。

### 2.3 名称描述动作，不评价人物

名称只表达发生了什么，不使用“错误、差、笨拙、不协调、标准、高手动作”等评价词。问题判断和改进建议放在独立字段中。

### 2.4 一个动作只设一个主名称

每个动作只有一个主名称，可以带多个补充标签。主名称用于时间线和语音播报，标签用于筛选、知识检索和详细分析，避免同一个动作在不同页面出现不同称呼。

## 3. 三层命名结构

### 3.1 第一层：基础动作名，所有动作必有

基础动作名由已确认接触事件生成，回答“哪个肢体，从哪里，到哪里”。这是当前产品可以稳定建设的层级。

统一格式：

> 动作编号 · 主体 + 动作关系 + 目标点

有明确起点时：

> 动作编号 · 主体 + 动作关系 + 起点→终点

例如：

- `动作 03 · 右手换点 H02→H06`
- `动作 04 · 左脚上点 F05`
- `动作 05 · 左手原点调整 H06`
- `动作 06 · 右手离点 H03`

### 3.2 第二层：动作关系名，有事件关系时生成

动作关系由两个或多个已确认事件之间的关系生成，例如双手落在同一岩点、同一肢体重新接触原岩点或两肢体在短时间内共同换点。

例如：

- `双手匹配 H08`
- `右手换左手 H10`
- `双脚换点 F04→F07`
- `左手连续换点 H03→H05→H08`
- `手脚同步调整 H06 / F09`

关系名称必须保留对应的原子事件，不能用一个复合名称覆盖底层数据。

### 3.3 第三层：技术标签，证据充分或人工确认后添加

技术标签描述动作解决线路问题的方式，例如身体朝向、平衡策略、接触方式和动态形式。它可以帮助用户学习专业动作，但不是每个动作都必须拥有。

示例：

> `动作 11 · 右手换点 H07→H12 · 交叉手（人工确认）`

> `动作 14 · 左脚离点 · 后旗式（AI 候选）`

## 4. 动作单元如何切分

科学文献把一次攀爬动作分为准备、主要动作和稳定三个阶段。产品采用兼容但更易落地的四段式：

1. **准备**：从上一稳定状态开始，到主要肢体开始离点或移动；
2. **移动**：肢体离开原接触，向目标岩点移动；
3. **接触建立**：触及目标点并形成有效接触；
4. **稳定/衔接**：新接触建立后，到下一动作开始。

一个动作从“上一稳定状态后开始准备”起，到“新接触稳定或下一动作已经开始”止。当前 4 FPS 条件下，阶段边界允许以帧区间和不确定度表示，不能伪造毫秒级精度。

以下情况单独处理：

- **连续动作**：稳定和下一动作准备可能合并，仍保留两个动作编号；
- **同时动作**：分别保存原子事件，并建立一个复合动作关系；
- **动态动作**：存在腾空或多肢体同时离点时，基础名先描述接触变化，技术标签待确认；
- **遮挡**：能确认前后接触但看不清中间过程时，使用“换点”，不推断具体技术；
- **失败尝试**：触碰但未建立稳定使用时，命名为“尝试触点”，不记作成功上点；
- **意外擦碰**：不进入动作序列；无法区分时标记为待确认。

## 5. 基础动作词典

### 5.1 手部动作

| 代码 | 中文名称 | 判定条件 | 展示示例 |
|---|---|---|---|
| `HAND_START` | 手部起步接触 | 开始时该手已在起步点 | 左手起步接触 H01 |
| `HAND_MOVE` | 手部换点 | 同一只手从一个岩点转移到另一个岩点 | 右手换点 H03→H07 |
| `HAND_CONTACT` | 手部上点 | 无明确起点，但建立了目标点接触 | 左手上点 H05 |
| `HAND_RELEASE` | 手部离点 | 结束接触且未在当前动作内建立新接触 | 右手离点 H04 |
| `HAND_READJUST` | 手部原点调整 | 离开后重新接触同一岩点，或同一点内重新抓握且经确认 | 左手原点调整 H06 |
| `HAND_ATTEMPT` | 手部尝试触点 | 触及目标但未形成有效使用 | 右手尝试触点 H10 |
| `HAND_WALL` | 手部撑墙 | 手接触墙面而非指定岩点，并被确认用于支撑 | 左手撑墙 W01 |

### 5.2 脚部动作

| 代码 | 中文名称 | 判定条件 | 展示示例 |
|---|---|---|---|
| `FOOT_START` | 脚部起步接触 | 开始时该脚已在起步点 | 右脚起步接触 F01 |
| `FOOT_MOVE` | 脚部换点 | 同一只脚从一个岩点转移到另一个岩点 | 左脚换点 F02→F05 |
| `FOOT_CONTACT` | 脚部上点 | 无明确起点，但建立了目标点接触 | 右脚上点 F04 |
| `FOOT_RELEASE` | 脚部离点 | 结束接触且未在当前动作内建立新接触 | 左脚离点 F03 |
| `FOOT_READJUST` | 脚部原点调整 | 重新踩同一岩点或同一点内调整且经确认 | 右脚原点调整 F06 |
| `FOOT_ATTEMPT` | 脚部尝试踩点 | 触及目标但没有形成有效使用 | 左脚尝试踩点 F08 |
| `FOOT_SMEAR` | 脚部踩墙 | 脚在墙面建立支撑但没有使用指定岩点 | 右脚踩墙 W02 |

### 5.3 起步、结束与状态动作

| 代码 | 中文名称 | 判定条件 |
|---|---|---|
| `START_ESTABLISHED` | 起步建立 | 起步要求的接触全部建立并经确认 |
| `TOP_CONTACT` | 顶点接触 | 到达终点岩点但尚未确认稳定完成 |
| `TOP_ESTABLISHED` | 完攀建立 | 满足当前线路完攀确认条件 |
| `PAUSE` | 动作间停顿 | 两动作间存在达到项目阈值的无新接触区间 |
| `RESET` | 回撤重置 | 返回先前接触组合并重新组织动作 |

停顿属于动作间状态，不单独代替肢体动作编号。它应显示为“动作 07 前停顿”，而不是混入动作列表成为“第 07 个动作”。

## 6. 动作关系词典

| 代码 | 中文名称 | 关系定义 | 自动化等级 |
|---|---|---|---|
| `HAND_MATCH` | 双手匹配 | 两只手同时使用同一岩点 | 可由确认接触生成 |
| `FOOT_MATCH` | 双脚匹配 | 两只脚先后或同时使用同一脚点 | 可由确认接触生成 |
| `HAND_SWAP` | 手部换手 | 一只手离开后，另一只手接管同一岩点 | 可由事件关系生成，时间窗待验证 |
| `FOOT_SWAP` | 脚部换脚 | 一只脚离开后，另一只脚接管同一脚点 | 可由事件关系生成，时间窗待验证 |
| `BUMP` | 同肢连续换点 | 同一肢体连续移动到多个岩点，中间没有完整稳定 | 候选；稳定阈值需验证 |
| `CROSS` | 交叉移动 | 移动肢体越过身体中线或另一支撑肢体完成上点 | 姿态候选，建议人工确认 |
| `SIMULTANEOUS` | 多肢体同步移动 | 两个以上肢体的移动区间明显重叠 | 可生成候选，重叠阈值需验证 |
| `SEQUENCE` | 连续动作段 | 多个动作间没有明显停顿，形成连续片段 | 可生成候选，停顿阈值需验证 |

## 7. 技术标签候选词典

### 7.1 第一批可建设标签

| 标签组 | 中文标签 | 说明 | 当前准入方式 |
|---|---|---|---|
| 身体朝向 | 正面动作 | 骨盆平面大体与墙面平行 | 需要可比机位与姿态置信度 |
| 身体朝向 | 旋转动作 / 侧身 | 至少一个阶段出现明显骨盆转向墙面 | AI 候选 + 人工确认 |
| 手部关系 | 交叉手 | 一只手越过另一侧完成目标点接触 | AI 候选 + 人工确认 |
| 腿部平衡 | 前旗式 | 非支撑腿从身体前侧伸出参与平衡 | 人工确认优先 |
| 腿部平衡 | 后旗式 | 非支撑腿从支撑腿后侧交叉参与平衡 | AI 候选 + 人工确认 |
| 腿部姿态 | Drop knee / 埃及式 | 同侧膝部明显下沉并伴随骨盆旋转 | 人工确认优先 |
| 接触方式 | Heel hook / 勾脚跟 | 脚跟与岩点建立明确接触 | 人工确认优先 |
| 接触方式 | Toe hook / 勾脚尖 | 脚尖上侧与岩点形成勾挂接触 | 人工确认优先 |
| 动态形式 | 动态够点 | 快速移动到目标点，但未确认全身腾空 | 高帧率不足时只作人工标签 |
| 动态形式 | Dyno / 跳跃 | 主要支撑同时解除并以腾空方式到达目标点 | 当前 4 FPS 仅人工确认 |
| 动态形式 | Double dyno / 双手跳跃 | 动态过程中双手共同离点并到达目标点 | 当前 4 FPS 仅人工确认 |
| 完成方式 | Mantle / 撑上 | 通过手臂支撑和身体越过边缘完成上方平台动作 | 人工确认优先 |

### 7.2 暂不自动识别的标签

以下标签高度依赖岩点受力方向、手指形态、墙面结构或三维信息，首版只允许人工添加：

- 侧拉、反向侧拉、Gaston；
- undercling / 反扣；
- layback / 对拉；
- crimp、open hand、pinch 等抓握类型；
- knee bar、手脚锁定和身体卡位；
- run-and-jump、paddle、coordination move 等现代动态组合；
- “重心转移充分”“髋部贴墙”等带有三维或受力含义的判断。

## 8. 方向和位置修饰词

在墙面坐标可信时，基础名可以增加方向词：

- 上移、下移、左移、右移；
- 左上、右上、左下、右下；
- 近距离、远距离仅在经过个体尺度归一化和阈值验证后使用。

方向必须根据墙面坐标或标定后的线路坐标计算，不能直接依赖存在透视变化的屏幕像素。方向词只是帮助理解，不参与技术好坏判断。

## 9. 命名优先级与降级规则

系统按以下顺序生成名称：

1. 人工确认的肢体、起点和终点；
2. 可确定的基础动作关系；
3. 经阈值验证的方向修饰；
4. 已确认的技术标签；
5. AI 候选技术标签。

证据不足时逐级降级：

- 看不清技术：保留“右手换点 H03→H07”；
- 看不清起点：降级为“右手上点 H07”；
- 看不清目标是否有效使用：降级为“右手尝试触点 H07（待确认）”；
- 连肢体也无法确认：不创建确定动作，生成待审核区间，要求人工补标。

系统不得为了保证“听起来专业”而猜测高级动作。完整命名的含义是每个已确认动作都有稳定名称，不是每个动作都必须被套上专业技术术语。

## 10. 数据结构

每个动作记录至少包含：

| 字段 | 含义 |
|---|---|
| `action_id` | 稳定动作编号，如 `A007` |
| `attempt_id` | 所属尝试 |
| `sequence_index` | 本次尝试中的显示顺序 |
| `start_time` / `end_time` | 动作时间区间 |
| `primary_limb` | 左手、右手、左脚或右脚 |
| `base_action_code` | 基础动作代码 |
| `source_hold_id` | 起点岩点，可空 |
| `target_hold_id` | 目标岩点或墙面区域 |
| `relation_codes` | 匹配、换手、连续换点等关系 |
| `phase_intervals` | 准备、移动、接触建立、稳定/衔接区间 |
| `direction` | 经标定的移动方向，可空 |
| `technique_tags` | 技术标签及各自置信度 |
| `display_name` | 面向用户的唯一主名称 |
| `evidence_frames` | 可跳转的证据帧 |
| `confidence` | 基础事件与标签分别记录置信度 |
| `review_status` | 自动候选、人工确认、已修改或证据不足 |
| `naming_version` | 命名规则版本 |

名称修改只更新展示和标签，不删除原始接触事件。历史复盘保留当时使用的命名版本。

## 11. 界面展示规则

### 11.1 动作时间线

时间线主行保留现有肢体标签：

> `07 右手`

旁边或副行显示中文补充名、目标和标签：

> `换点 H04→H09 · 交叉手候选`

### 11.2 动作详情

点击后展示：

- 起止视频和关键帧；
- 准备、移动、接触、稳定四阶段；
- 起点、目标点及对应轮廓；
- 基础动作名、关系名和技术标签；
- AI 把握程度及命名依据；
- “名称不对”“标签不对”“这不是有效接触”的修改入口。

### 11.3 复盘建议

建议必须以动作名开头：

> `动作 07 · 右手换点 H04→H09` 前出现较长准备和两次试探。下一次先确认目标点再启动；复攀时观察该动作的试探是否减少。

禁止只写“第 7 步做得不好”或“右手动作需要改进”。

## 12. 证据与边界

[The Way Up](https://openaccess.thecvf.com/content/CVPR2025W/CVSPORTS/html/Maschek_The_Way_Up_A_Dataset_for_Hold_Usage_Detection_in_CVPRW_2025_paper.html)提供了四肢、岩点、使用起止时间和遮挡标注的直接依据，并明确区分有效使用与偶然擦碰，适合作为基础动作命名的证据。

[Biomechanical Principles and Techniques—A Systematization for Sport Climbing](https://pmc.ncbi.nlm.nih.gov/articles/PMC13027491/)提出准备、主要动作、稳定三阶段，以及正面/旋转两类技术框架，并列举交叉手、后旗式、drop knee 和动态动作等术语。但作者同时指出攀岩术语长期不统一、许多技术仍依赖经验体系，因此本词典把高级术语放在可修正标签层，而不是不可更改的基础名称层。

[Climbing Technique Evaluation by Means of Skeleton Video Stream Analysis](https://pmc.ncbi.nlm.nih.gov/articles/PMC10574944/)说明动作阶段对技术评价很重要，也展示了姿态、距离和时间规则；但其数据来自 RGB-D、60 FPS、受控路线和少量有经验攀爬者，不能把其中阈值直接移植到当前单目 4 FPS 产品。

## 13. 首版验收标准

- 每个经确认的肢体动作都有动作编号和基础名称；
- 名称可以追溯到起止时间、肢体和岩点事件；
- 匹配、换手、原点调整与尝试触点不会混为普通换点；
- 技术标签与基础名称分开记录，并显示确认状态；
- 遮挡和低置信情况下会降级命名，不猜测高级技术；
- 用户修改名称后，时间线、建议和复攀比较同步更新；
- 同一命名规则在历史记录中可版本化和回放；
- 所有复盘建议引用具体动作编号与名称。

## 14. 当前决策

第一阶段先保证“每个动作都有可靠基础名”，再逐步增加专业技术标签。基础命名依靠人工确认的四肢接触和岩点关系；匹配、换手、连续换点等关系可在此基础上计算；正面、侧身、旗式、drop knee、heel hook、dyno 等标签必须采用更严格证据或人工确认。

这套分层设计既能让用户获得完整、连续的动作语言，也能保护产品不把不可靠的姿态猜测包装成专业教练结论。
