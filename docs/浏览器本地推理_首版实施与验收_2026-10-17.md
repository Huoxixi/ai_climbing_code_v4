# 浏览器本地推理：首版实施与验收

日期：2026-10-17。用户确认采用“打开网站，无需安装；网页自动加载模型，使用本机算力；模型自动缓存”的路径。

## 当前交付与入口

已经实现独立的浏览器骨架验证版：`http://127.0.0.1:4317/browser-replay.html`。

这不是完整最新版 App 的网页迁移。当前接通人物检测、RTMW 133 点骨架、本地选人、保守连续匹配、骨架叠加/纯骨架播放和结构化数据保存。岩点、接触、墙面配准、无人真实背景、视频导出、App 的整段多人轨迹及受限上下文复核尚未迁移。现有 App、原片、历史记录及生产环境未切换到此流程。

开发源继续位于主工作区，未使用旧开发包作为修改基线。数值对照调用的是主工作区的当前 vendor 辅助代码和固定权重；仅借用 D 盘开发包已有 Python 解释器及依赖运行该对照，没有把它当作用户实际安装 App 的验收。

## 运行路径

1. 打开独立网页后，计算 Worker 自动加载当前固定摘要的人物检测器及 RTMW。优先请求本机 WebGPU；初始化或推理失败时仅在本机回退到 WASM CPU。
2. 对模型做字节长度和 SHA256 校验，然后写入浏览器 CacheStorage。刷新后优先复用并重新校验缓存。损坏缓存仅删除对应模型项并重新加载，不清空整个浏览器数据。存储拒绝或配额不足时仍可在内存中运行，并提示下次可能需要重载。
3. 视频通过本机文件选择器读取，预览和处理均使用 blob URL，不上传。当前仅支持浏览器可直接解码的格式，建议 H.264 MP4；不复用原 App 的服务器/本机 FFmpeg 转码接口。
4. 用户暂停在清晰画面，识别人像并手动确认人物，随后从该时刻开始分析最多 90 秒。支持 10/5/2 Hz 采样；这是采样密度，不代表实时处理速度。文件上限 500 MiB，当前画面上限约 4K 像素数。
5. 所有采样依次提交本机 Worker。没有远端分析回退。人物匹配不确定时留空，连续丢失超过 0.6 秒后不擅自换人；可重新选定画面并分析。结束后可播放、隐藏真人显示纯骨架、保存骨架 JSON。停止计算会终止 Worker 并清理本次结果，重新准备时复用完整模型缓存。

## 模型和程序

| 资源 | 字节数 | SHA256 |
| --- | ---: | --- |
| RTMW-L 384×288 / 133 点 | 229320930 | bd033156e5104c4f5d2edfe0453e02661e30a2f3da453ec93c8764d561b83054 |
| YOLOX-S 人物检测 | 35998962 | 332e09ea9696e3401049b6c5314851db020b6430f85da159e65f37034ab3aee8 |

模型合计约 265.32 MB；另需加载运行组件，实际计算内存高于模型文件大小。ONNX Runtime Web 固定为 1.30.0，运行时资源由同站提供，不依赖远端 CDN。为了兼容普通静态托管，WASM 当前使用单线程，不要求 COOP/COEP；计算 Worker 保持页面主线程可响应。

浏览器输入明确转换为与原 cv2 路径一致的 BGR。人物模型实际返回 packed 浮点框和 int64 标签：只读取单类别所需的浮点框，不误转 int64，也不在模型内置 NMS 后叠加新的抑制规则。RTMW 保持 1.25 倍裁剪、288×384 输入、均值/标准差、SimCC 两轴峰值平均分及源图坐标换算。原始 133 点与显示资格分别保存；头部复用现有圆形绘图模块，不生成额外算法关节。

主要文件：

- `frontend/src/browser-replay/`：页面、Worker、模型缓存、输入/输出转换与视频读取。
- `frontend/browser-model-assets.mjs`：本地开发仅暴露精确白名单模型路径；构建时核验并复制模型和许可，不暴露用户文件夹。
- `frontend/vite.browser.config.js`、`frontend/browser-replay.html`：独立静态页面构建。原有默认 App 构建不加入这份模型资源。
- `start-browser-local.ps1`：启动独立静态预览，不运行 Python 后端；端口被占用时不停止现有进程。

## 验收结果

15 项相关自动化检查全部通过：7 项缓存/数值/跟踪逻辑、2 项浏览器检查、6 项现有头部绘图检查。真实浏览器检查内含多项独立断言：

- 全新浏览器上下文自动加载两份真实模型；刷新后模型网络请求为 0。
- 主动损坏该测试上下文中的检测器缓存后，仅重新请求检测器，另一模型继续复用。停止任务后 Worker 释放，可重新准备。
- 真实原视频第 315 帧（720×1280）以相同源像素及同一人物框进行浏览器 WASM 与主工作区 native CPU 对照。检测器输入张量逐值一致；RTMW 裁剪插值存在小差异，归一化输入平均绝对差约 0.00131。133 个原始点平均坐标差 **0.03535 px**，最大 **0.78363 px**。这只是单画面数值一致性，不是独立标注准确率，更不代表原有手腕误差已解决。
- 从原片另存 1.2 秒测试片段，通过实际文件选择器、浏览器解码、点选人物、2 Hz 本机分析、3/3 采样观测、播放、隐藏真人、保存含 133 点及独立资格的 JSON 全流程。
- 上述浏览器流程网络检查：非 GET 请求 0，分析/账号 API 请求 0，外部站点请求 0。测试原片、帧与结果仅置于被忽略的 `.tmp`，没有打入静态包。
- 桌面及 390 px 宽页面检查通过，无横向溢出；关闭真人后仍有独立播放和进度操作。
- 独立静态构建与原有默认前端构建均成功。编译后的独立静态包另行完成同一短片流程，无页面脚本错误，不依赖 Python/API。

本机回环网络的最后一次冷启动约 2.96 秒，缓存启动约 1.93 秒。该画面 CPU 检测加骨架约 2.94 秒；这些数字不能用于估计公网首次下载、其他设备、手机或整段任务速度。此次实际通过的是 WASM CPU，WebGPU 初始化和运行失败的本机回退已实现，真实硬件 GPU 的兼容性和速度尚未验收。

依赖审计未将问题归于新增 ONNX 依赖；报告中的 3 项高等级条目来自既有 Vue/server-renderer 和 source-map-js，未在本次顺带升级既有 App 依赖。当前浏览器页面仅做客户端渲染，不使用 SSR。此项不构成完整安全审计。

证据：`.tmp/browser-local-replay-20261017/` 内的 `reference.json`、`browser-report.json`、`static-build-report.json`、桌面/手机截图及对照输入；不上传私人测试素材。

## 重开与构建

在主工作区运行：

```powershell
./start-browser-local.ps1
# 源码改变后重建：
./start-browser-local.ps1 -Build
```

在 `frontend` 中独立构建：

```text
npm run build:browser
npm run preview:browser -- --port 4317
```

静态产物为 `frontend/dist-browser/`，入口是 `browser-replay.html`。只包含页面、计算组件、固定模型、清单和许可。开发模式 `npm run dev:browser` 也可直接打开此页。

普通逻辑与浏览器失败状态检查：`npm run test:browser-local`。真实模型及私人片段对照另外需要设置 `CLIMB_BROWSER_NATIVE_FIXTURES`，其生成入口为 `backend/scripts/prepare_browser_pose_validation.py --source ... --output ... --frame 315`。对照测试不会把私人片段写入 public 或发布目录。
