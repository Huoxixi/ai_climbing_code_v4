| 命令 | 固定范围 |
| --- | --- |
| `maintenance-tools` | 工具源码 SHA 与命令清单 |
| `maintenance-status` | 活动路径、健康、Nginx、磁盘和当前发布安装包下载大小 |
| `maintenance-network` | 固定公开 GitHub 安装包及正式站点连接；不打印重定向签名或请求头 |
| `maintenance-cleanup-plan` | 只列清理候选，保留当前版本及其他两个最新完整网页版本 |
| `maintenance-cleanup` | 核对健康、已验证远端备份及共享发布锁后，只删除上述计划内的旧程序；遇未知内容、数据目录、非网页或未完成版本就停止 |
| `maintenance-cancel-download` | 只停止活动发布中 root 拥有、命令及工作目录完全匹配的安装包下载，使用稳定进程句柄防 PID 复用；不接受 PID 参数 |

原 `status`、`logs 100`、`releases`、`deploy <标签>` 等命令沿用。命令入口只接受上述完整固定命令，sudoers 不含任意参数通配符；新增 helper 清空传入环境并以 Python 隔离模式运行。工具不可访问任意路径、URL、shell 或 PID，不能删除业务数据、配置及备份。清理保留三份完整网页回退程序；先计划、核对、再执行，执行回执保存在 `/var/backups/ai-climbing/maintenance`。

安装先保存实际旧入口和 sudo 配置、验证 Bash/sudoers，再原子更新并以 `codex-ops` 实际测试无密码固定 sudo；失败恢复原入口。安装回执与旧工具保存在 `/var/backups/ai-climbing/maintenance-tools`。安装后需通过原 SSH 密钥验证旧命令、新只读命令、无事可清理的清理执行、非法参数拒绝及生产健康，不能只凭安装脚本返回成功宣称完成。

此授权允许在用户任务范围内直接使用固定维护操作；发布仍须本地检查、PR 门禁、主分支不可变标签与标签门禁后执行标准脚本。数据恢复、任意 root shell、密钥读取和防火墙修改不在此扩展范围。

## 发布步骤

1. 唯一基线的当前功能、已提交与未提交差异均需审核；真实数据、照片、数据库、`.local/`、`.private/`、密钥、依赖目录和临时产物不得上传。
2. 运行本地生产测试、无界面浏览器测试和构建。测试使用隔离临时目录，不写入个人历史。完整后端命令为 backend 下 `python scripts/run_release_tests.py`；前端为 `npm ci && npm test && npm run test:release-browser && npm run build`，生产构建设置 `VITE_ENABLE_SIMULATION=false`。
3. 推送开发分支，通过 PR 的 release-gate 纳入 main，再给最终提交创建未使用的不可变 pilot-v 标签，验证标签 release-gate 全部通过。不能用旧分支名或旧 tag 作为这次发布结果。
4. 登记上一版本、完整 SHA、门禁链接、维护时间和回退人。核对无编辑／AI 任务、无备份任务重叠，磁盘足以安装依赖、生成构建和发布前备份。旧固定凌晨窗口不适用于已明确授权的当前发布；无证据的运行条件仍须保留为未完成。
5. 在 root 终端执行唯一发布脚本：

```bash
/usr/local/lib/ai-climbing/deploy_release.sh <完整标签>
```

使用已登记受限密钥时，对应的是主目录 `project-ops` 的 deploy 命令，服务器仍调用同一脚本。不得 git pull、手工覆盖 current、更新生产配置或迁移数据。失败回退与备份由脚本负责，不另造流程。

6. 检查运行路径、release.env、健康接口和服务，再访问正式域名验证照片线路／AI 复盘。检查 0.75 倍速、简短动作说明、总结逐条出现后收盘、手动重开保持、重播不重复自动演示；桌面和手机宽度均检查。真实业务记录需要现有授权会话，不能从密钥文件取网页登录密码。

```bash
readlink -f /opt/ai-climbing/current
cat /etc/ai-climbing/release.env
curl -fsS http://127.0.0.1:8000/api/health
systemctl is-active ai-climbing nginx
```

7. 观察 30 分钟并记录结论、异常、限制及待办。没有实际执行／验证的步骤不得打勾。

## 空间清理

先把仓库 `deploy/scripts/cleanup_server_caches.sh` 上传 `/tmp/cleanup_server_caches.sh`，root 执行 `bash /tmp/cleanup_server_caches.sh audit`。它仅统计发布目录、缓存、备份、数据和日志总大小，不打印数据或凭据。

审核后 `bash /tmp/cleanup_server_caches.sh clean` 仅清理 `/root/.cache/pip`、`/root/.npm/_cacache` 与 `/var/cache/apt/archives/*.deb`，保留锁文件。发现活动部署／包安装或重定向目录时停止。全部发布目录、模型、运行依赖、业务数据、备份和配置保留。清理记录在 `/run/ai-climbing-cleanup/`（重启后不保留，应另存脱敏结果）。用户明确授权历史发布保留最近三个。先执行 `bash /tmp/prune_old_releases.sh audit`，确认当前版本位于保留集合、三个版本完整、旧版本的 backend/data 仅为持久数据目录符号链接，再执行 `prune`。脚本拒绝未知受保护内容；停止后只能核对来源和用途，不能直接取消保护。新发布完成并验证后再清理第四个版本，保持三个完整回退资产。若仍不足 8 GiB，停止发布；8 GiB 是保守操作预留，不是脚本对所有工作量的保证。

## 日常检查、回退与数据恢复

root 可运行 `/usr/local/lib/ai-climbing/daily_check.sh`；检查服务健康、最近备份、磁盘和日志。域名可访问是当前预期，不再以公网不可访问／隧道 active 判断成功。应用端口仍不得公开。

程序故障按已记录上一完整版本执行 `/usr/local/lib/ai-climbing/rollback_release.sh <上一标签>`，随后重复版本和健康检查。程序回退不回退数据。数据恢复是独立高风险操作，必须列明备份、影响、数据损失与回滚并获得准确的“确认执行”，本次发布授权不包含它。不得用数据恢复处理页面或普通程序故障。
