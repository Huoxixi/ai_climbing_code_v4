# AI 攀岩复盘细化动作词典与证据合同

日期：2026-09-30。命名版本：`replay-action-names-v2`。本文记录本地实现的词语、证据与展示规则，供开发和人工标注使用。专业技术识别尚未通过独立真实视频验收；现有知识库的审核与自动使用状态保持原样。

实现沿用基础动作、动作关系、技术标签三个层次。基础动作可以确认而技术标签仍为候选；知识条目解释词义，连续原片决定词语能否用于本次动作。没有证据的接触、受力、完攀和失败原因不随词语细化补全。

## 基础动作与易混规则

以下例子均为构造例。基础事件必须有至少三张不同原片帧，覆盖前、中、后阶段，并经独立局部检查确认肢体侧别、骨骼链连续、无遮挡与冲突。接触事实另需至少两张不同帧及独立核对，不能继承基础事件的通过状态。

| 输入动作 | 中文过程名称 | 必要条件和排除项 | 合格构造例与不合格构造例 |
|---|---|---|---|
| `reach` | 伸手够点或移脚靠近目标 | 连续肢体路径可见；不宣称已接触。目标未知时不添加岩点身份 | 三帧看见右手伸出；仅看到结束姿态不能补出路径 |
| `lift` | 抬手或抬脚 | 肢体抬起过程可见；不据此确认高抬脚技术 | 看见脚离开原位并抬高；人物整体上升不能冒充脚部动作 |
| `move` | 伸手或移脚 | 核对运动侧别；不同岩点身份另行验证 | 左脚路径清楚但终点被挡，只写移脚；不写成功换点 |
| `move_up` | 向上伸手或抬脚 | 兼容旧记录中的向上过程，不升级接触状态 | 旧记录有局部动作核对，可改细过程词；旧词“上点”不自动证明接触 |
| `adjust` | 调整手部或脚部位置 | 可见局部调整；不直接认定离点或重新抓握 | 手腕调整可见但手指不清，写位置调整；不写原点重新抓握 |
| `contact` | 接触岩点或落到脚点 | 目标身份可定位，首次接触及其后保留接触可见 | 在1.5秒接触目标，1.5秒前只写靠近目标；手在岩点附近不算接触 |
| `release` | 离开岩点 | 接触结束前后可见，且岩点身份已核对 | 看见左脚从点上离开；遮挡后轨迹消失不算离点 |
| `readjust` | 原点重新抓握或重新踩放 | 同一岩点内实际调整或离开后重新接回可见 | 同点重新踩放；接到不同点应归为换点 |
| `attempt` | 触及后未保留接触 | 看见触及和随后离开，观察窗口足够；不诊断失败原因 | 触点后马上移开；只有触点最后一帧不能证明未保留 |
| `wall_contact` | 接触墙面 | 连续画面确认接触墙面区域；不由缺少岩点匹配推断撑墙或受力 | 手掌贴墙可见；未匹配岩点的悬空手不算接触墙面 |

单独事实包括 `source_contact / target_contact / release / readjust / attempt / wall_contact`。岩点事实只能使用当前分析版本的合法岩点ID，原片对应帧必须提供经过墙面配准的候选轮廓；轮廓只是定位参考，不是接触证明。检查者需覆盖提出者使用的全部证据帧，并将事实条件判为 `satisfied`。不满足或未知均不放行。

`HAND_MOVE / FOOT_MOVE` 表示运动类别，伸手与抬脚保存为 `motion_phase`。当 `base_action_status=motion_only` 时，不得把代码解释成已完成岩点转换。确认前后不同岩点才成立换点；没有起点但确认新接触则展示目标接触。原点调整沿用 `HAND_READJUST / FOOT_READJUST`，但同样须查看事实状态，不能仅凭兼容代码判定重新抓握。

方向字段需要模型与独立检查一致，还须由墙面配准后的连续肢体位置支持。缺少配准或方向模糊时只保留无方向的过程词。兼容读取既有 `move_up` 记录不会补写新的墙面方向证据。

基础词义参考[原动作词典](AI攀岩复盘_动作命名体系与标签词典_2026-09-21.md)、[中文动作总表](AI攀岩复盘_攀岩动作中文总表_2026-09-21.md)和[知识库](bouldering-knowledge/README.md)。涉及重新抓握、原点调整与连续换点可追溯到 `KB-HAND-003`；落脚与换脚可追溯到 `KB-FOOT-001 / 004`。这些映射不授予自动建议权限。

## 接触关系与冻结阈值

阈值是本项目第一轮开发规则，尚未经独立留出材料验证。变更须增加算法版本并重做比较，不能在看到留出结果后放宽门槛。

| 关系 | 条件 | 易混与构造反例 |
|---|---|---|
| `HAND_MATCH / FOOT_MATCH` 双手或双脚并点 | 两条已核对接触链在同一岩点重叠至少0.10秒 | 先后踩同点但没有重叠，不算双脚并点 |
| `HAND_SWAP / FOOT_SWAP` 换手或换脚 | 原肢体已确认离点，另一侧接同点，间隔0至0.50秒 | 缺少离点证据不算换脚；先并点再离开仍记录并点及离点，不改写为换点接管 |
| `BUMP` 同肢连续换点 | 同肢相邻事件接不同目标点，间隔0至0.30秒 | 当前仅候选；时间短不单独证明没有稳定段 |
| `SIMULTANEOUS` 同步动作 | 不同肢体的已核对运动区间重叠至少0.15秒 | 按各自原子事件展示，不能机械写成“随后” |

这版收紧旧词典中“双脚先后或同时同点均为匹配”的定义，要求真实重叠。`CROSS` 在技术层保存，不由横坐标交换自动生成交叉手。两个独立事件及其接触必须保持可追溯；同点编号相近或来源不同不能合并为同一身份。

## 专业技术候选

全部机器技术标签仅为 `candidate`，不进入确认字幕。人工确认只作用于本人的这次修正，不成为算法成绩，也不修改知识库许可。英文名是术语对应；表中判断条件是本项目的工程合同，例子为构造例。

| 代码与首选名 | 英文与别名 | 必要画面 | 排除项与易混例 | 来源映射 |
|---|---|---|---|---|
| `CROSS` 交叉手 | Cross | 完整出手路径、留手和身体中线跨越 | 只有画面横坐标交换或身体转向不足 | KB-HAND-004 |
| `HIGH_STEP` 高抬脚 | High step | 可靠身体比例、高脚位置及接触 | 普通抬脚或近大远小不能成立 | KB-FOOT-006 |
| `HIP_TURN` 侧身转髋 | Hip rotation | 肩髋可见及连续旋转 | 单帧斜侧姿态或镜头运动不足 | KB-BODY-001 |
| `OUTSIDE_FLAG` 外侧旗式 | Outside flag | 支撑脚、自由腿及侧向伸展 | 普通跨步或支撑关系未知不足 | KB-BODY-002 |
| `BACK_FLAG` 后旗式 | Back flag | 支撑脚、自由腿及后侧关系 | 平面投影交叉而深度不清不足 | KB-BODY-003 |
| `INSIDE_FLAG` 内侧旗式 | Inside flag | 支撑脚、自由腿及前侧关系 | 前后遮挡不明时不细分旗式 | KB-BODY-003 |
| `DROP_KNEE` 沉膝 | Drop knee，埃及式 | 脚点接触、膝旋转及髋旋转 | 普通屈膝不能成立 | KB-BODY-004 |
| `ROCK_OVER` 移髋过脚 | Rock over | 脚点与髋经过支撑脚的过程 | 整体上升或姿态单帧不足 | KB-FOOT-005 |
| `HEEL_HOOK` 勾脚跟 | Heel hook | 鞋跟接触细节与接触过程 | 17点踝位置不能证明脚跟接触 | 原动作词典，未映射专门单元 |
| `TOE_HOOK` 勾脚尖 | Toe hook | 鞋尖上侧接触细节与过程 | 普通脚尖踩点不能成立 | 原动作词典，未映射专门单元 |
| `MANTLE` 撑上 | Mantle | 手部撑压动作、边缘及身体越过过程 | 手放在点上不能证明撑上 | 原动作词典，未映射专门单元 |
| `DYNAMIC_REACH` 动态够点 | Dynamic reach | 密集原帧、起动及目标接触 | 快速伸手本身不证明腾空 | 原动作词典；KB-DYN-001只提供动态组织背景 |
| `DYNO` 跳跃 | Dyno | 密集原帧、所有支撑解除、腾空及接点 | 局部跳帧或脚被挡不能证明腾空 | 原动作词典；KB-DYN-001为相关背景 |
| `DOUBLE_DYNO` 双手跳跃 | Double dyno | 密集原帧、双手离点、腾空及双手接点 | 先后出手不能改成共同跳跃 | 原动作词典；KB-DYN-001为相关背景 |

技术证据至少三帧，每项必要条件在提出与独立复核中均为 `satisfied`，同时 `conflict=false / occluded=false`。快速动作采用更密原帧，最大间隙不超过0.05秒才提供密采样条件；插帧或漏帧不能满足。密采样仍不是技术准确率验收。

半扣、全扣、捏握、侧拉、反扣和卡膝未加入本轮机器候选。全身素材缺少必要细节时，不能为了细化名称猜测接触方式。

## 字段合同与显示规则

| 层次 | 已冻结字段与状态 |
|---|---|
| 结果 | 保留 `schema_version=replay-actions-v1`；`algorithm_version=source-motion-blind-local-naming-v4`；新增 `naming_version=replay-action-names-v2` |
| 事件 | 稳定 `id`、`limb`、`action`、`motion_phase`、`base_action_code`、`base_action_status`、原片 `start_seconds/end_seconds`、`evidence_status/event_status` |
| 接触 | `facts[]` 的 `kind/hold_id/start_seconds/end_seconds/status/evidence`；事件 `contact_status`；派生起点终点每次重建 |
| 关系 | `id/code/name/event_ids/start_seconds/end_seconds/hold_id/status` |
| 技术 | `code/name/status/conditions/evidence/unit_id`；机器始终候选，个人修正明确人工确认 |
| 字幕 | `caption_parts[]` 的 `start_seconds/end_seconds/text`；`display_name` 为片段短名称 |
| 修正 | 账号、时间、前后版本、修改字段和前版快照；撤销追加审计记录，不擦除修改历史 |

岩点ID归一成字符串，但必须来自同一分析版本。状态 `locally_verified` 表示局部模型检查通过，不代表独立人审或真实识别效果验收。自动候选接触和人工修正混合统计时明确标注其来源。

字幕按原片时间取阶段，首次接触前不显示接触，离点和尝试结论在对应事实结束后显示。重叠运动同时呈现，旧字幕结束尾部不会遮住下一动作或延长真实重叠。候选关系和技术不混入主字幕。人工标签保留“人工确认”文字。

人工修正接口为 `POST /api/climb-replay/jobs/{job_id}/actions/review`，撤销为同路径 `/review/undo`。必须传当前 `result_version`；跨账号、失效版本、越界时间、非法岩点及任务进行中的写入被拒绝。改变接触会重算相关关系、四肢岩点数和线路合并去重使用率，并使旧导出失效。原片、自动分析和基础画面保留。原基础动作图可能仍显示旧分析，页面会提示版本差异。
