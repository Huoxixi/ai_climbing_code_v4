# AI 攀岩复盘：抱石知识库完善计划

日期：2026-09-25
版本：v0.1
状态：建设计划。已查看项目现状、七张参考图并做首轮来源检索；尚未执行批量入库、视频样本标注或分析功能改造。

## 1. 建设目标与范围

完善一套能支持 AI 分析室内抱石视频的知识库，使复盘能够回答：**哪一段发生了什么、涉及什么动作原理、有哪些值得核对的解释、下一步如何调整或补充信息，以及如何比较下一次尝试。**

知识内容既要帮助人理解技术，也要让 AI 知道使用一条知识需要哪些视频证据。以室内人工抱石为第一阶段范围，覆盖常见静态动作、动态动作和连续协调动作；顶绳、先锋、户外保护操作暂不展开。体能、心理、训练与恢复保留为背景知识及自述记录，是否能用于某次视频解释另行判断。

第一轮交付“可阅读、可检索、可追溯的内容版本”，随后再验证自动调用。知识收录、动作识别成功、建议有效，是三个分别验收的结果。

因此，建设重点是把已有目录、术语和文献转成**有技术解释、有使用条件、有视频观察入口的知识单元**，补充抱石专项内容、反例与案例，并定义未来调用接口。

需要优先统一四处口径：

1. 旧文档的六个分析阶段、四个展示阶段，与图片的动态事件链建立映射。保留层次差异，不强行让所有动作具有相同切段。
2. “首次接触”“持续接触”“后续任务完成”分别记录；程序里的持续阈值不能直接证明承重或身体控制。
3. “接点后先稳定”改为有适用条件的候选提示。连续动态动作可能直接衔接，不能普遍要求停顿。[动作阶段研究](https://pmc.ncbi.nlm.nih.gov/articles/PMC13027491/)也讨论了连续动作中相邻阶段合并的情况。
4. 现有 `HAND_MOVE` 等语义代码与中文总表的 `B06` 等目录代码建立对照，以语义代码为候选规范入口，保留旧编号；实施时再与实际事件字段核对，不新增第三套独立词典。

## 4. 知识内容框架与优先级

保留十模块作为人的阅读入口；AI 同时按“问题、动作阶段、接触关系、墙面情境”检索，同一知识单元可被多个入口引用。

| 模块 | 要补充的抱石内容 | 建设顺序与视频使用方式 |
|---|---|---|
| 01 表现与分析框架 | 动作结果、过程、任务约束、竞争解释；进步与单次表现的区别 | 第一批；所有分析共用 |
| 02 身体与动作基础 | 四肢接触组合、胸廓/骨盆朝向、可见位置变化、动作阶段与衔接 | 第一批；二维观察与教学解释分别存储 |
| 03 手脚与身体技术 | 点型、手点方向、抓握方式；内外侧踩点、踩墙、换脚、勾脚；换手、匹配、旗式、转体、Drop knee、撑上 | 第一批核心；看不清细节时保留知识，降低标签确定性 |
| 04 动态与协调 | 动态够点、Dyno、Pogo、动态旗式、连续接手、跑跳、放脚与回脚、接后控制及衔接 | 第一批建立事件骨架和高频条目，第二批扩展变式；复杂标签先人工确认 |
| 05 岩壁与线路风格 | Slab、垂直、仰角；局部面朝向、体积点、可用接触面、不同下一步要求 | 第一批；区分整体墙角与局部点面，无法测定时不填精确角度 |
| 06 读线与策略 | 手脚顺序、候选 beta、身材与可达性、熟悉度、尝试间修订、休息与探索 | 第一批；预想方案来自用户记录，实际顺序来自视频 |
| 07 体能与活动范围 | 力量、功率、持续输出、活动范围与任务要求的区别 | 第二批背景；测验需有独立记录，不从一次视频诊断短板 |
| 08 心理与注意 | 用户自述的害怕、犹豫、注意目标；主观感受与可见行为的差别 | 第二批背景；不从表情或停顿猜测心理状态 |
| 09 评估、训练与恢复 | 同线路复盘、一次改一个条件、练习记录、尝试次数与恢复背景 | 第一批先建记录与比较框架，后续补训练知识 |
| 10 安全与长期参与 | 抱石场景条件、退出与停止推进的条件、现场核查责任 | 与第一批同步；作为适用条件，不生成现场安全认证 |

技术内容必须讲清楚“这一动作解决什么任务、常见实现方式、前后接触如何连接、在哪些情境下可能不合适”。不能只写术语释义或一串禁止事项。

首批建议围绕 30 个高频问题形成约 30 个核心单元，复用已有术语表，不按词条数量扩张：

| 问题组 | 拟建单元数 | 代表性问题 |
|---|---:|---|
| 脚步与接触转移 | 6 | 踩到后反复调整；换脚后如何接下一步；踩墙与踩点如何区分；回脚失败在哪个阶段 |
| 手部接触与动作关系 | 5 | 触到即离开；匹配与换手；原点调整；连续换点；交叉后的下一步 |
| 身体位置与朝向 | 5 | 转体发生在何时；旗式与支撑关系；高抬脚后转移；Drop knee；撑上与边缘手位转换 |
| 动态与协调 | 6 | 未触达与触达后失败；Pogo；动态旗式；计划放脚与意外失去接触；连续踩点；接后回脚与衔接 |
| 读线与探索 | 4 | 预想和实际脚序不同；停顿用途；重复探索；两种 beta 如何比较 |
| 同线路复盘 | 4 | 更快是否更好；接触次数变化；疲劳/熟悉度如何记录；条件变化后还能比较什么 |

这些数量是排期估算，不是科学标准。若某个问题依据不足，交付待核条目和缺口说明，不用同义词或虚构结论补足数量。

## 5. 知识如何存储并供 AI 使用

建议先采用可版本管理的文档与结构化字段，后续从同一份内容生成检索索引。建设五类互相引用的材料：阅读章节、知识单元、来源与证据卡、问题索引、案例与评测集。

每个知识单元至少包含以下内容：

| 内容组 | 必填内容 |
|---|---|
| 身份与检索 | 稳定 ID、中文名、英文名/别名、相关问题、已有动作代码、版本 |
| 技术内容 | 定义、任务目的、关键配合、常见变式、与相近动作的区别 |
| 适用情境 | 活动类型、整体墙角/局部点面、手脚接触、前后动作、个体条件与未知项 |
| 视频观察 | 哪些手脚或身体部位必须可见；要看哪个时间段；接触顺序和可见结果；镜头及采样要求 |
| 解释依据 | 可支持的解释、其他可能解释、各自需要的区分证据、不能推出的结论 |
| 下一步 | 补充什么信息；条件满足时可比较的一个调整；下次观察什么；不适用或停止条件 |
| 证据与管理 | 来源 ID、具体页码/段落/时间戳、主张支持关系、审核记录、允许调用范围 |
| 案例 | 典型例、相似但不适用的反例、遮挡或证据不足例；案例真实/构造状态 |

必须分别管理三条证据线：**视频中观察到的事实、攀爬者主动提供的描述、外部资料中的知识**。外部资料可帮助解释事实，不能补造视频没拍到的接触；用户说“脚滑了”也不等同于画面已确认脚滑。

在旧版 E1—E5 标记之外，增加三个独立维度：

- **来源性质**：专项研究、一般方法研究、协会/原作者教学、项目样本、产品规则；另记研究质量和任务匹配度。项目样本验证了识别准确度，不自动证明建议有效。
- **每条主张的适用关系**：原研究直接支持、有条件迁移、教学假设、个体待验证。借鉴图中四类标记，但不用它们给整篇材料排统一高低。
- **审核和调用状态**：检索线索、定位原文、内容核对、专业复核、项目验证分别留记录；调用范围分为解释知识、辅助复核、候选建议、可自动触发。

一篇来源可以支持多张证据卡，同一单元可以包含不同强度的主张。下载成功、网页可检索、有教练署名或标记 reviewed，都不能单独完成所有审核。

### 6.2 按问题检索并回到原文

围绕六组问题进行中英文检索：

1. 脚部接触：foot placement、edging、smearing、foot swap、heel/toe hook、foot transfer。
2. 手部接触：hold orientation、grip type、hand match、readjustment、touch versus hold usage。
3. 身体技术：flagging、backstep、drop knee、rock over、mantle、body orientation。
4. 动态与协调：dyno、deadpoint、pogo、dynamic flagging、cut feet、foot recovery、coordination、paddle。
5. 策略与学习：route preview、exploration、affordances、sequencing、familiarity、video feedback。
6. 视频依据：contact annotation、occlusion、temporal sampling、movement phases、2D pose validity。

每次记录检索词、检索日期、来源入口、纳入/排除理由与对应缺口。检索结果和二手文章主要帮助定位原作者；进入证据卡时核查作者、版本、活动类型、研究/教学对象、实际任务、测量方法与具体支持段落。

书籍核对具体版本、页码与引用范围；原作者视频核对连续示范、前后动作和时间戳。无法获得原文的来源保留线索状态。不同转载或同一作者的重复版本按来源谱系去重；相互冲突的说法同时保留条件，不通过引用数量表决。

图中提及的 Hermans、Limonta、Seifert 等具体结论也按上述流程回查，不只依赖图片中的作者名和页码。采用自己的摘要并保留链接；书图、课程视频和示例素材另记使用范围，来源可公开阅读不等于可复制分发或用于训练。

## 7. 为视频分析设计观察与回答协议

### 7.1 先定义事件，再附技术名称

动作观察骨架为：**起动前的接触 → 旧接触的变化 → 目标首次接触 → 接触保留与后续动作 → 该段实际结束状态**。

每项分别允许“画面可见、遮挡、出画、抽样未覆盖、尚未复核”。同时动作允许时间区间重叠；无法区分先后的两个事件不得强排顺序。“未触达”必须有覆盖关键过程的画面，不能因为抽样没检测到就判定。

接点结果拟区分：未触达目标、触达后很快离开、接触保留但后续任务未完成、接触保留并继续，以及无法判断。目标和结束要求来自线路/用户确认；短暂触碰也可能是有意中转，不能仅凭接触时长判失败。

单元需要同时记录“这类动作应观察什么”与“本次输入实际提供了什么”。原视频帧率、分析抽样率、时间来源和人工修正版本进入调用条件；当前默认 4 FPS 下未覆盖的快速事件转为待复核，不借助知识常识补齐。

### 7.2 AI 调用流程

1. 读取该尝试有效的人工修正、视频证据和用户背景。
2. 按活动类型、可见性、动作阶段、接触关系与情境筛选知识；缺少必要输入的条目只用于提示补信息。
3. 通过动作代码、中文别名和问题描述检索；初版先用结构化筛选与关键词，检索评测表明确有需要时再增加语义索引。
4. 先写可复查事实，再给与证据相称的解释；确有不同合理解释时，说明如何区分。
5. 输出一项下一步：补充观察，或在条件满足时比较一个调整，并说明下次如何核对。
6. 保存动作/片段 ID、视频位置、知识单元与证据卡版本、来源定位、生成时间及审核状态。

知识回答可展开技术原理；单次视频复盘以一个主要问题为先，至多三条，避免让用户一次改变多个条件。数据不足时仍应给出有用的具体缺口，例如“需要确认左脚离点是在右手触点之前还是之后”。

### 7.3 一个用于校验结构的构造例

问题：“右手碰到下一点后脚离开了，是不是核心不够？”

- **可见事实**：在右手已接触目标点的画面中，随后可见双脚离开原接触；关键离点瞬间若未覆盖，则只记录前后状态，不推断离点原因。
- **解释方向**：可能涉及计划放脚、原接触意外丢失、接后回脚任务或目标点使用方式。是否适用须看动作目标、连续画面和本人描述，不由术语名称选定原因。
- **需要补充**：脚是否按计划释放、原脚点是否可见、下一回脚目标、右手接触是否保留。
- **下一步**：先对比出手前、首次接点、脚离开与回脚这几个事件；条件充分时再形成一个针对该段的调整候选。
- **复盘观察**：比较接触顺序、目标接触是否保留、是否完成回脚和下一步，不把一次成功解释为力量提高。

此例是知识单元结构示意，不代表本项目已分析真实用户视频，也不代表已经验证了具体技术建议。

## 9. 验收标准

### 内容与追溯

- 首批每个问题均有有效知识单元或明确的待核结论；能从自然语言问题找到对应内容。
- 每个可调用单元均有技术说明、适用条件、观察要求、反例和来源定位；证据不足时不强行填写调整建议。
- 每条运动知识主张可追溯到来源及具体位置；产品自定义规则、教学假设和构造示例另作标记。
- 草稿、审核和调用范围分别记录；内容修改保留版本，旧分析可追溯到当时使用的版本。

### 检索与回答

初版约 40 个离线用例覆盖普通问题、术语别名、多种解释、遮挡、低采样、情境不适用及资料相互矛盾等情况。预先固定期望条目与允许输出，保留至少四分之一用例不参与调试。

可先把“前五条检索结果包含期望条目，覆盖率至少 90%”作为待确认的工程目标；它不是科学结论。引用必须对应实际支持的主张；无证据时间点的事实、把未知写成确定接触、把更快写成必然进步、直接诊断力量/心理/伤病等严重问题在固定测试集上应为零。零例只能说明通过该测试集，不能宣称全面可靠。

### 视频与实际效果

选用明确授权、用途相符的视频。开发阶段可先从约 20—30 个真实动作片段验证字段和标注规范，覆盖典型与困难情况；这只是试点规模，不足以证明所有动作可自动分析。

后续自动化验收需按攀爬者与线路分组保留独立样本，避免同一视频相邻片段同时用于调试和验收；记录接触事件一致性、时间误差、脚部遮挡、固定/移动镜头及动态动作分层结果。标注采用两人独立判断与分歧仲裁，专业动作与建议内容再由相应人员复核。若人员或样本未就绪，继续完成内容和离线测试，相关自动建议保持未启用。

“识别对不对”“引用是否支持”“建议适不适用”“实际是否帮助下一次尝试”分别评价。用户觉得有道理或一次完攀，都不能单独作为建议效果已验证的结论。
