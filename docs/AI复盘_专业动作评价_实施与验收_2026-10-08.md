# AI 复盘专业动作评价：实施与验收记录

日期：2026-10-08。基线为用户指定的本地工作树 `ai_climbing_code_v4-photo-yellow-release`，目标见 [用户确认计划](AI复盘_专业动作评价分析模型计划.md)。

后续更新：用户另行授权同步到本地 App，现已生成 `0.1.2-professional-preview.20261008` 并更新桌面快捷方式；详见 [桌面同步验收记录](Windows桌面版_专业动作评价同步_2026-10-08.md)。下文“未重打桌面安装包”描述保留为首次工程接入时的状态；专业准确率和真实费用限制仍然有效。

本轮完成原片保留、清晰副本、真实帧采样、动作证据结构、通用视觉评语接口及页面连接，并用隔离数据完成工程测试。专业动作正式命名、专业评价和首要技术调整尚未通过真实素材独立验收。不能把本记录理解成整个计划的质量验收通过。

## 1. 用户现在可以使用的流程

1. 上传视频并从画面取色；原片固定保留。
2. 识别、逐点复核或补点，确认全部岩点。
3. 单独点击开始本地分析，默认 10 FPS。可选择 4 FPS 对照档；15／20 FPS 标记为实验档，也可填写一个重点时间窗口补充采样。
4. 观看原有左右复盘布局、骨架和动作顺序。动作说明仍在原有位置，长评语不烧录进视频。
5. 在“设置 → 服务”填写视觉服务地址、模型、密钥和计费参数。保存设置不调用外部服务。
6. 单独勾选同意发送动作证据并确认费用，再点击生成逐动作评语。页面结束总结增加回看重点。

上述代码已写入本地工作树；本轮没有重启正在运行的本地后端、重打桌面安装包或部署生产。已启动的旧进程需要在正常重启后使用新代码。

## 2. 已实现的工程行为

| 项目 | 实现情况 |
|---|---|
| 原片生命周期 | 新上传固定保留原片与分析副本；移除“处理后删除”、倒计时和自动删除执行路径。历史待清理任务不会再执行自动源片删除。保留主动删除原视频／整条记录。 |
| 清晰度 | 常见竖屏副本 720×1280，横屏对应 1280×720；其他比例等比适配，不拉伸或冒充新增细节。不再在失败时静默降到低清副本。 |
| 原片访问 | 增加归属校验的原片下载接口；历史记录如果没有保留高清原片，不伪造为可下载。原始文件摘要和片段时间映射随记录保存。 |
| 骨架采样 | 默认整段 10 FPS；支持 4／10／15／20 FPS 原生帧计划和人工重点窗口。记录实际帧号、时间、样本数和最大间隔；不使用插帧充当证据。 |
| 缓存和恢复 | 同源、同模型、同人物选择规则及岩点绑定的真实帧可复用磁盘缓存；取消及重试沿用原任务机制。失败保存原片和上一版可用结果。 |
| 时间规则 | 接触停留和轨迹平滑改用真实时间，不以固定样本数解释秒数，避免提帧改变动作意义。 |
| 动作结构 | 增加关联事件、协同片段分组、二维角度／角速度、相对位移／速度、阶段、有效覆盖、缺失原因和版本证据。身体移动与四肢主动移动分别处理。未知目标与支撑不填造假数值。 |
| 首批技术 | HIGH_STEP 与 CROSS 保存必要条件、易混项和内部候选状态；自动确认关闭。133 点保留，手脚细节点参与技术判断仍待可用性验证。 |
| 视觉服务 | 新入口使用账号独立的 OpenAI 兼容图文接口；退出百炼环境密钥自动调用和失败回退。历史评语及计量继续保留。 |
| 证据发送 | 按动作分批发送结构化事实、真实前中后三帧和必要的手脚局部图，不默认上传整段视频。高清局部优先从保留原片读取，保留原片与分析片时间对应。 |
| 密钥 | 服务端保存；Windows 使用当前用户 DPAPI 加密，其他服务端使用受限文件。接口不返回密钥，普通结果不包含密钥。 |
| 费用 | 默认预算 ¥1，可调整；预留本次调用费用，重试计入同一底层分析已发生或尚不确定的费用。价格未知时阻止真实调用；失败不自动重试或切回旧服务。 |
| 评语检查 | 检查动作身份、肢体、引用帧、真实时间及部分不允许的无依据表述；不能据此宣称语义正确。未通过审核的专业命名、受力判断和训练处方不放行。 |
| 页面 | 独立外部发送授权；动作评语沿用原说明位置；结束总结增加“本次最值得回看”。不新增常驻字幕侧栏，原有轨迹结束展示和播放行为保留。 |
| 新旧结果 | 新结果绑定版本，成功替换时归档前一版动作结果；失败保留上一版评语和可用视频，人工修正后移除过期评语总结。 |

费用控制依赖正确的供应商价格及图片计费上界。当前预留图片输入 token 并加入余量；用户填写的计费上界未经供应商实测验证前，不能保证真实账单必定不超过 ¥1。服务返回 usage 时记录实际模型和计量；未返回时保留预留费用，不显示为已知零费用。

## 3. 第三、四章的完成边界

### 动作及专业识别

基础结构已经允许未知岩点、没有换点的身体移动、多事件分组和人工审核记录，不再只依赖岩点转换生成动作。连续轨迹可提供观察级动作描述；回收、同点调整、可见接触变化的完整自动分类和协同技术判断仍需用户试标、规则完善与独立验证。不能把“接近岩点”解释为已经抓稳或承重。

首批两类动作的试标约定如下，真实正反例尚未标注：

| 类别 | 试标定义与边界 | 必要证据 | 易混反例及不可判定 |
|---|---|---|---|
| 高抬脚 | 观察抬脚准备至高位目标附近稳定的过程；可见接触另行标记。高位几何只是候选线索，不直接构成正式技术确认。 | 躯干尺度可靠、脚的连续轨迹可见、高位目标及接触细节可核对。 | 身体下沉使脚相对升高、普通抬脚、脚部遮挡或跳点；接触不清时只写抬脚过程。 |
| 交叉手 | 观察移动手离开初始位置、经过躯干中线至目标附近稳定的过程。 | 移动手路径、保留手及肩髋连续可见；中线关系有连续证据。 | 左右身份交换、整体横移、双手同时移动、单帧重叠；保留手或跨越过程缺失时不确认技术。 |

这些是开发试标起点，尚未由两名独立审核者冻结定义。旗式、转髋、沉膝、ROCK_OVER 及后续动态类别未在本轮新增自动准入。

### 评语与首要调整

新接口已能生成逐动作的短观察评语，检查不通过的条目继续显示本地观察，不将 API 返回文本直接当作专业事实。当前没有对新模型通过独立验收的技术调整规则，因此结尾从证据完整的动作中选出回看重点，说明过程并提供原片核对入口。它不会为凑出一项缺点而编造训练要求。

要输出“最应该调整什么、为什么、下一次如何验证”，还需要实际供应商模型验收和已审核的评价规则。这是计划中尚未完成的专业能力，不是页面免责声明能够替代的工作。

## 5. 真实本地素材实验

已盘点 `素材/视频复盘首批10段_20261005/浏览器兼容版` 的 10 条素材，保存元数据、文件摘要、各采样档计划及空白试标表。没有虚构动作标签、审核人或独立测试成绩，实验前后核对的原片摘要一致。

### 同片 3 秒骨架实验

第一条素材的同一段 720×1280、30 FPS 画面，固定 RTMW 和人物选择逻辑；仅运行骨架，不包含配准、动作特征和视频生成：

| 采样档 | 真实样本量 | 骨架阶段耗时 |
|---|---:|---:|
| 4 FPS | 12 | 2.260 秒 |
| 10 FPS | 30 | 2.823 秒 |
| 15 FPS | 45 | 4.350 秒 |
| 20 FPS | 60 | 5.050 秒 |

模型首次加载另约 4.202 秒。没有参考标注，以上只证明采样和运行链路可用，不能证明短动作漏检降低，也不能外推完整视频总耗时。30 FPS 到 20 FPS 的最大样本间隔仍为约 0.066667 秒。

### 30 秒工程链路实验

第四条素材 V010，截取前 30 秒，720×1280、30 FPS、10 FPS 骨架，运行真实 RTMW、配准、特征和视频合成。为隔离测量使用五个**构造岩点区域**，不是用户确认的真实线路。

- 整体约 **116.153 秒**，输出 900 帧均可解码；原片摘要不变。
- 进程峰值内存约 **459.45 MiB**。
- 骨架及其相关处理约 31.269 秒，视频生成约 80.253 秒，特征约 0.499 秒。找人、骨架推理和配准是内部细分时间，与阶段时间存在包含关系，不可全部相加。
- 计划采样 300 个，其中只有 **87 个有效骨架样本（29%）**。另一次同输入的骨架诊断复现 87／300：从源帧 261（8.7 秒）起，213 个缺失均为 `track_missing_or_ambiguous`。这定位到现有保守人物跟踪，尚不能证明丢失后重选哪一个人正确；没有用插值或降低准入条件补成“有效证据”。本轮增加逐帧缺失原因与运行计数，后续需验证跟踪找回及旁观者误选。

该案例在 180 秒内完成，**不代表产品的 3 分钟目标通过验收**：岩点未人工确认，骨架有效覆盖偏低，且不是从真实页面点击起包含队列等待的多案例测量。应在修复覆盖问题后，使用用户确认岩点的代表素材重新测量。

## 7. 人物选择问题后续修复

用户随后授权修复。逐帧检测与画面核对确认，V010 的旧版先锁定了左侧旁观者，旧 87 个有骨架样本不能计为正确攀爬者样本。已增加线路范围及当前画面配准约束、短时外观与位置恢复，并把缓存改为原始检测与分框骨架，重试及加密时重新选人。

同段完整复测有骨架 277／300，开头 23 个旁观者样本留空；2.3 秒后连续观察至 29.9 秒。完整工程流程约 115.799 秒，900 帧均可解码。另两段覆盖 245／257、300／300，选人截图抽查未见旁观者误选。206 项回归及随后计时修正的 61 项复核通过。构造线路范围、截图抽查和工程耗时仍不能替代真实标注与独立验收；恢复分支的真实案例验证也待补充。详情见 [人物选择与跟踪修复](AI复盘_人物选择与跟踪修复_2026-10-08.md)。

## 8. 剩余验收顺序

1. 用户试标 10 条开发素材，固定首批动作边界与正反例；用新增缺失原因检查人物选择与骨架覆盖，先保证能够观察到动作。
2. 同片、同岩点、同标注比较 4／10 FPS，并在标注窗口比较 15／20 FPS。核对小脚点、压缩损失、左右交换、时间边界与短动作漏检，不能仅比较样本数。
3. 指定视觉供应商、模型和实际计费规则后，独立验证逐动作评语、图片计费上界、重试总费用和事实准确性。
4. 另选未见素材，两名审核者独立标注并处理分歧。每类至少 60 正例、60 易混或负例、20 独立分组；正式命名正确率 ≥95%、基础可判定召回率 ≥85%、专业标签 95% 区间下界 ≥90%、无依据放行零，且必须报告覆盖率和误报／分钟。
5. 专业评价规则通过审核及新模型独立验收后，才启用首要技术调整建议，再逐类扩展专业动作。

当前可交付的是实现上述门禁的工程基础。零输出不能计为高准确率，工程测试、单个耗时案例和用户准确性提示均不能替代剩余质量验收。
