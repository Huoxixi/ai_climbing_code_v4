# 四项优化：进一步排查与修改方向

日期：2026-10-11。本轮是进一步只读排查和修改建议，未改变识别程序、默认参数或 App。承接 [首轮逐项验收](四项优化_首轮执行验收汇总_2026-10-11.md)。优先解决自动选人、人物输入框和原始关节错误，再改变接触规则；脚形继续只表示脚，不显示独立脚趾。

## 新增排查证据

1. 重新统计首轮真实原始观测：01/02/09 的腕踝响应分别为 988/904/540 个，合计 2432 个，全部大于 1。当前 `replay_pose_rtmw.py` 截断到 `[0,1]`，这些位置均得到分数 1。这是响应饱和统计，不是 2432 个关节都正确；在这三个样本中，把接触门槛从 0.15 提至 0.5 无法区分它们。
2. 固定输入复现：配准诊断误差为 3.2 像素、关节分数 0.9 时，`align_pose_record` 加 `_contacts` 仍保存接触事件，而 `registered_points` 不支持显示腕点。另一对照将误差设为 0、分数设为 0.2，仍是接触保存、显示腕点无效。有效对照误差 0/分数 0.9 两者一致支持。构造四肢均在同一诊断岩点，得到的四个事件只是复现口径，不能当真实误报数量。
3. 为判断上述机制是否解释 09 的已知漏亮，重新读取其全部 135 个已观察源帧，固定岩点参考帧 145 做真实配准。135 个均被接受，没有一个因误差超过显示的 3 像素门槛而冲突。因此该视频 264 帧的已知右手漏亮仍应归原始关节错位，不能归给这项机制风险。
4. 固定选人候选复现：已有追踪框位于线路范围外时，`_select_box` 的 `iou_follow` 分支可在重新核对线路之前返回旧对象。纯骨架初选没有线路范围时主要按框面积选择。结合 02 的真实选旁人案例，说明初次锁定及续跟缺少足够的重新比较；这不意味着所有范围外的人体动作都错误，真实摆荡也可能暂时离开线路区域。
5. 历史显示兼容性：当前页面优先使用已保存 `replay_visualization`，脚形新增后布局版本仍是 `split_analysis_right_v11`。有旧可视数据的记录不会自动走新的原始骨架派生路径；即便原始 wholebody 尚在，也可能没有新脚形。没有读取用户历史记录证明发生数量，也不能据此声称所有旧记录都有可恢复的脚部点。

私有证据：`.tmp/quality-next-audit-20261011.json`；09 逐帧配准诊断为 `.tmp/quality-next-registration-09-20261011.json`。没有读取 `.local/`、重跑付费模型或使用留出素材调参。

## 1. 优先修自动选人和姿态输入框

**实际问题。** 02 号源帧 180 选中左侧旁人；516/519/522 同帧框对照表明，过大的当前人物框可能让姿态模型把手脚颠倒。人工/既有关键点上下文收紧框能恢复部分帧，但旧检测框不可靠；现有自动重试只修好 516、519，522 仍失败。

**修改方向。** 初次选人从单帧最大框改为短时间内比较多个真实人物候选：结合身体可见性、连续身份、与墙面/已确认路线的关系及动作过程，延后不可靠的首次锁定。纯骨架模式从画面与人物时序提取依据，不增加用户选人开关。续跟保留身份稳定性，但对新出现的攀爬候选、框突变和人体结构冲突重新比较，不能永久继承一次错选，也不能因摆荡越界立即换人。

针对姿态输入建立同源帧的全人物框/身体上下文候选，核验肩髋覆盖和可见肢体支持。上下文只定位重推理的图像区域，不把手脚拉到旧位置、不交换标签，也不靠滤波去掉真正的快动作。现有 `supports_retry` 要求候选靠近原始错误端点，可能拒绝实际正确位置；应通过同帧图像与独立候选的一致支持来核验，而不是直接放宽历史距离。

**验收条件。** 单列首次锁错、身份切换、错手脚、拒绝/缺测和恢复时延；复测多人背景、局部入画、真实高抬脚和快速伸手。522 必须保留为失败回归，修好两个帧不能代表整段通过。原始错误位置、候选与采纳理由同时保存。

## 2. 建立关节可靠性及统一配准口径

**实际问题。** 分数 1 在目前三个实测片段没有区分腕踝正确性。接触和显示又分别使用 0.15/0.5，配准接受与显示误差门槛不统一，存在能保存事件但不显示该关节的机制风险。09 的实测配准无该冲突，须与实际错位区分。

**修改方向。** 保留原始响应，把“有限、在画面内、分数满足规则”与“位置有可靠支持”拆开。结合同帧不同上下文的结果一致性、人体链结构、图像局部证据和跨帧身份冲突判断，时序异常只触发核查。不能未经验证将任意响应归一化成正确概率，也不能单用速度判错。若开展响应校准，需冻结真实可见关节标注及单独验证集。

抽出一个共有的配准质量判断，统一接触、骨架、脚形、轨迹和导出对误差单位、有效区域、矩阵稳定性、内点及缺测的解释。配准误差先统一到原图像素，再决定门槛，避免缩放后判定与源像素诊断混用。仅把接触门槛调成 0.5 不能解决饱和问题。

**验收条件。** 增加 3.2 像素/0.2 分数等固定边界回归，并逐帧列出“能支持接触但不能显示端点”的数量及原因。确实不可显示的观察，不应悄悄支持确定事件；对真实正接触转为未知仍计召回缺口，不能靠隐藏骨架与亮点获得改善。

## 3. 修岩点可见性、小点筛选与错误融合

**实际问题。** 黑边面积修复后，08 号仍有 5 个青色候选被筛除，尚未逐一证明它们都是真岩点。当前仍有外接框面积 0.0015 的统一门槛、至少两帧支持及外接框关联。09 加密推理多出的人物腿部假点说明重复出现不足以证明是岩点。

**修改方向。** 先逐一核验被拒绝的小候选真假，再比较实际轮廓面积、尺寸、原始清晰度和多帧支持，形成受证据约束的小点例外；不整体降低面积或分数门槛。选帧按目标岩点是否可见、是否被人体挡住及局部边界清晰度，在有限推理预算内选互补帧。全图清晰度最高的帧不必是目标岩点最佳帧。

将相邻岩点误合并与同一岩点重复分开诊断；在匹配困难处比较轮廓、颜色与源帧身份。与人物动态区域重叠的候选改找无遮挡观测并核验，不整体删除人体附近岩点，因为真正使用中的点也常被遮挡。完整分块推理须保留整图上下文，原轮廓对照和密集采样仍不默认启用。

**验收条件。** 完整目标地图的真实岩点漏检、假点、合并/重复及轮廓偏差分别统计；用增加同等耗时或固定推理预算的对照评价收益。候选多了、筛除少了均不算精度改善。

## 4. 重建接触部位和短触/持续使用的共同规则

**实际问题。** 09 号 264 帧右腕和指尖同时错在左侧点；部位替换没有恢复。零停留会让错误左侧点被当作右手接触。固定脚踝下移、归一化 0.02 邻域和最近中心选点，也会跨画幅、方向及相邻点产生不同效果。简单脚形是显示，不会自动修好踝点或接触。

**修改方向。** 在原始位置与地图更可靠后，按手/脚的真实可见区域生成空间候选，距离统一为源像素或有依据的身体尺度，比较取消固定脚部下移。多个岩点竞争时保存歧义，不直接按最近中心确定身份。保留用户要求的简单脚形，加入脚前端/脚跟缺测及明显不合理延伸的检查，不显示独立脚趾、不用脚形回推“必然踩点”。

在同一状态引擎中区分“有图像支持的短碰触”和“持续使用”，分别记录实际支持开始、确认与离开；短碰不能只是把 0.4 秒改成 0。短碰需要真实观察支持，二维经过、悬空和弱点不能因为足够近就点亮；未知/缺测不能无限沿用上一点。离线回核也不把整段接近无条件倒填为确定接触。

**验收条件。** 短触、持续使用、经过、离点、相邻点和遮挡的同一冻结正负集共同评分，报告错点身份、漏亮/误亮时长、起止偏差、未知和输出覆盖。亮错相邻点同时计错点误报和真点漏报。

## 5. 补齐显示版本、当前流程回归和资源验收

**实际问题。** 新脚形只有两帧真实显示核验；旧可视化优先路径可能阻止重新派生。旧浏览器夹具等待已删除的“重要动作解说”区域而失败，当前流程尚缺完整暂停/回拖/导出回归。骨架候选的 09 耗时波动混有原始推理变慢，不能都归给新候选。

**修改方向。** 给派生可视数据增加版本判断：原始 wholebody 足够且派生版本旧时，以只读方式重新派生当前显示；缺原始点时保持缺测，旧导出和用户记录不被覆盖。页面、当前 App 和新导出对同一时间点比对骨架、脚形、亮点和末帧汇总。

更新隔离测试夹具以匹配目前简化后的产品流程，不恢复已删除的用户功能。资源对照分开记录冷启动、缓存命中、人物检测、每个姿态上下文、墙面配准与编码；固定线程/设备和同机条件重复对照，重试次数必须有预算。完整素材的解码策略及自适应局部采样再单独评估。

**验收条件。** 优先建立小规模但冻结的真实失败/正常参考集，再补全十条素材和开发/留出验收；困难正样本输出未知仍计缺口。避免通过对同一批失败反复调参冒充留出成绩。旧记录只读派生、暂停、离点、回拖、末帧和导出检查须通过；原片哈希与用户数据不变。

## 建议实施顺序

1. 自动初选/续跟和人物上下文，保留错位与快动作回归。
2. 统一可靠性和配准口径，解决“有事件但端点不可显示”的机制冲突。
3. 可见性驱动的有限选帧及小点/融合核验。
4. 在同一正负集修改部位与短触/持续使用规则。
5. 补齐当前页面、App、导出、历史派生及留出/资源验收。

每一步先冻结对应失败及正常输入，实施后单独验收；不一次同时换全部模型、地图和时间规则。
