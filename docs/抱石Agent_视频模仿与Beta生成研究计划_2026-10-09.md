## 1. 研究目标与边界

研究目标是使用已有室内抱石视频、骨架与岩点接触关系，构建具备固定身体比例和明确能力限制的模拟 Agent，使其先模仿真人攀爬，再独立选择动作与岩点，最终生成可以复核的候选 Beta。每次完整候选攀爬之后，允许 GPT 根据实际尝试记录提出修改，再由同一模拟环境检验修改是否有效。

本阶段只开展研究。交付为数据规范、实验程序、模型、骨架回放、评估表与研究报告；不制作网页、App、账号系统、线上接口或生产部署，不改变现有照片线路和视频复盘产品流程。普通离线回放、实验图表与视频是研究证据，不是产品界面开发。

研究对象为抱石：固定线路的允许岩点、指定起终点、手脚协同、身体调整、局部疲劳和短时动态动作。不研究绳索保护、挂快挂、长距离耐力攀登、登山或梯子攀爬。通用人体控制项目只作为技术参考，不能用其走路、跳跃或梯子表现替代抱石验证。

最终预期输出是“在给定环境信息和身体能力假设下的候选 Beta”，而非保证真人完成的唯一最优解。复现视频、模拟成功、未见线路泛化、真人认可与真人完成分别报告。

## 3. 待检验的研究问题

| 编号 | 问题 | 支持该结论所需证据 | 不能据此宣称的结论 |
|---|---|---|---|
| Q1 | 现有视频能否构成可信动作示范？ | 人工抽查接触、骨架与时间，给出可用覆盖与错误类型 | 自动识别全部准确 |
| Q2 | 固定身体的 Agent 能否复现真人 Beta？ | 参考接触和连续姿态在规定环境中执行，完整记录失败 | 学会选择新 Beta |
| Q3 | 模仿是否改善动作执行与恢复？ | 同预算下相对无模仿基线的执行与扰动恢复差异 | 一定更省力或更适合真人 |
| Q4 | 能否独立生成新 Beta？ | 不提供测试线路的真人目标顺序，产生规则合法候选 | 普遍适用于任意墙面和动作 |
| Q5 | 身体比例与能力是否改变合理 Beta？ | 固定环境下改变指定身体档案，比较可达性和动作变化 | 从视频精确识别真实力量 |
| Q6 | GPT 反思是否有增量价值？ | 相同模拟调用预算下与无反思、规则修正对照 | GPT 文字解释本身构成学习 |
| Q7 | 模拟结果是否具有现实参考意义？ | 独立抱石复核者核对，必要时另外组织真人验证 | 模拟成功等于真人必成 |

各问题允许得到负结果。没有改进、只能复现、只适用于部分动作，均应成为研究报告的明确结论。

## 4. 技术路线与最低可行研究

总体路线：原视频与既有分析 → 研究样本及质量审核 → 身体和墙面表达 → 真人动作重定向 → 模仿执行 → 独立 Beta 规划 → 本地模拟 → GPT 修改建议 → 同环境复测 → 对照评估。

采用两层结构。上层决策“下一步哪个肢体去哪个接触目标、是否先调整身体”；下层控制“关节怎样连续运动、怎样保持允许接触”。上层可以先用搜索或小型序列模型，下层先建立确定性姿态与轨迹求解，再评估物理控制策略。不存在必须一次性训练大型端到端模型的前提。

保留两条研究路线，并严格区分结论：

- 路线 A：二维或有限深度条件下的接触顺序、姿态可达性与 Beta 候选研究。适合首先利用现有数据；只能支持几何和简化接触条件下的结果。
- 路线 B：已知墙面几何和身体模型下的三维连续物理控制研究。用于检查动态、受力及接触过程；需要更完整环境信息，不能把路线 A 的成功率称为物理完攀率。

第一里程碑选一条高质量抱石线路、一个身体档案和少量可靠动作：复现原 Beta；修改一个脚位或手序；重新求解；并解释修改失败在数据、几何、接触、控制还是体力层。选中的演示线路属于开发材料，不用于宣称未见线路泛化。

## 5. 数据清点、筛选与人工复核

### 5.1 清点单位

以“线路、攀爬者、完整尝试、动作事件”为基本单位。相邻视频帧是相关观测，不当作独立技能样本。记录同一视频重复导入、同线路重拍和同一尝试的不同裁剪。

清单至少包含：原片内容摘要、研究内编号、攀爬者匿名编号、线路编号、墙面编号、原片时长与帧率、拍摄方向、镜头移动、人体可见程度、骨架来源和版本、接触标注来源、起终点证据、尝试结果、环境信息完整程度。

仅凭衣服颜色不能确认跨视频为同一人；只有位置照片不能确认线路未变。身份和线路关系缺少证据时标为未知，并在评估中说明分组限制。

### 5.2 初始样本选择

先选固定或可可靠配准机位、全身大部分可见、起终点及岩点清楚的素材。优先选同线路多次尝试、不同 Beta 和失败后修正的记录。

首轮工作量建议为 10–20 条完整尝试、尽量覆盖 3–5 条线路，用于检查数据流程和决定是否值得扩展；这不是训练充分性的结论。若实际数据不足或动作质量较差，缩小范围并报告。后续用不同数据规模的学习曲线决定新增素材，避免凭固定视频数量承诺效果。

### 5.3 复核方法

逐条核对首批开发尝试的关键接触变化与成功判定；扩大后按线路、拍摄角度、成功失败及动作类型分层抽查。测试集的核心接触和结果应人工复核，不沿用模型自己的预测作为正确答案。

对关键测试样本由两名独立标注者复核，记录一致率与分歧，再仲裁；若只有一名复核者，明确报告这一限制。

质量记录包括左右肢体交换、缺测时长、异常关节跳变、配准失效、接触误判、动作起止不清、出画、视频剪辑和结果不明。

### 5.4 样本分层

| 层级 | 条件 | 可以用于什么 |
|---|---|---|
| A | 接触明确、骨架连续、配准可靠、关键动作已复核 | 核心模仿与主要测试 |
| B | 部分缺测，但关键目标和时间可复核 | 掩码监督、局部动作研究 |
| C | 遮挡重、环境未知或接触不确定 | 感知误差研究与补充观察 |
| D | 主体错选、严重错位、无法恢复时间关系 | 不进入动作训练；保留剔除原因 |

姿态置信度不是接触概率，也不是标签正确率。低置信度帧不以插值补齐后冒充观测；插值必须携带派生标记。

## 6. 研究样本规范

使用独立、可版本化的数据格式，原始观测与修正值分开保存。

| 对象 | 最小字段 | 约束 |
|---|---|---|
| 视频 | source_hash、原始帧率、尺寸、时间映射 | 裁剪、重采样后仍可定位原片 |
| 人体 | person_id、关节布局、身体比例、尺度来源、质量 | 无真实尺寸时不标米制测量 |
| 姿态帧 | source_frame、time、坐标、关节置信度、有效掩码、来源 | 明确像素／归一化／墙面／三维坐标 |
| 岩点 | hold_id、轮廓或接触区域、允许用途、坐标、属性证据 | ID 稳定；抓握方向未知允许留空 |
| 接触 | limb、target_id、起止、置信状态、接触类型、来源 | free 与 unknown 区分；未知不等于离点 |
| 动作 | 前后接触、移动肢体、时间、连续骨架、结果 | 固定原片时间；含多肢体动作，不强行单肢体切分 |
| 线路 | 起点、终点、允许岩点、墙面和造型使用规则 | 人工明确；不能从颜色自动猜规则 |
| 尝试 | 结果、结束时间、结果证据、失败原因状态 | 结果可确认而原因未知；二者分开 |
| 审核 | 标注者、版本、修正理由、原始值引用 | 不改写原始分析文件 |

肢体统一为左手、右手、左脚、右脚。手部先以腕部位置作为代理；脚部先以可用脚踝或足部关键点为代理，不能据此推断指尖、鞋边或脚跟确切接触。足部细节不可见时，不标注已确认脚跟勾挂。

每项量带有 evidence_type：observed（直接观测）、derived（从观测计算）、assumed（模拟设定）、unknown（无法确定）。例如真实手腕位置、二维角度、设定指力和未知岩点深度分别属于不同层级。

一个训练样本由一段当前状态、可用环境信息、身体档案和后续动作组成。执行策略可以使用短时历史；除明确研究预瞄控制外，不输入当前时刻之后的真实视频。GPT 评语不作为默认技巧标签，先保留行为事实。

## 7. 骨架尺度、身体比例与坐标处理

### 7.1 视频内固定身体

参照每段视频攀爬者的骨架构建 Agent，但只估计一套稳定比例。优先用多帧可见、低遮挡、较少透视缩短的身体段；二维长度只是投影长度，不能把中位数或最大值直接宣称为真实骨长。

先估计躯干、上臂、前臂、大腿、小腿的相对比例及不确定范围。拟合时同时考虑连续性、固定骨长和可见关节投影误差；左右比例相近作为可放宽的先验，不强制人体绝对对称。缺少证据的身体段保留默认先验并记录来源。

Agent 一次尝试内身体尺寸固定。转身、屈膝或镜头远近变化不能改变骨长。若无法从原片可靠恢复比例，使用一组可能身体档案进行敏感性分析，不声称已还原真人。

### 7.2 跨视频统一表达

归一化坐标先按原片宽高恢复像素几何，再处理身体尺度；不能直接在 [0,1] 的横纵坐标上计算欧氏距离而忽略画面宽高比。

身体与岩点必须一起缩放。跨视频以身体尺度单位表达距离，并保留各段比例。形态归一化用于学习动作关系，不能把不同人的可达范围完全抹平；身体档案仍作为模型输入。

### 7.3 墙面与三维

镜头移动时先追踪固定墙面参考。平面墙面可研究单应变换，造型、多平面墙和身体离墙不能由同一个墙面变换完整解释。配准失效片段隔离，不能用变换后的二维身体当作三维真值。

采用从易到难的环境：已知平面墙及固定镜头 → 已知倾角与有限深度 → 明确造型几何 → 动态动作。静态或准静态动作也需要有深度假设；没有几何证据时只报告简化模型结果。

已知身高、墙面尺寸或可靠标尺可用于尺度约束，但单个标尺不自动解决身体深度与相机问题。三维恢复结果须与二维投影、接触和骨长一致性联合核对。

## 8. Agent 状态、动作与身体能力

### 8.1 状态

Agent 状态包含根部位置与朝向、关节角度和速度、四肢接触状态、目标岩点相对位置、墙面信息、身体比例、固定能力及动态疲劳。独立 Beta 生成时不提供测试真人的后续接触顺序。

几何路线可以使用关键点状态；物理路线须使用完整关节状态与动力学。感知输入有缺测时携带掩码，不把不可见肢体默认放到最近岩点。

### 8.2 动作

上层动作包括移手、移脚、换手／并手、身体调整、允许休息，以及后续扩展的多肢体动态转换。目标可以是岩点接触区域或线路允许的墙面／造型表面。动作包含持续时间与完成条件，不能只在起终状态之间直线连线即判为完成。

下层采用关节目标加受限控制器作为首选实验方式，再决定是否训练直接力矩控制。控制器必须有力矩、速度和动作幅度限制；重定向得到的参考姿态不等于已经实现的控制。

### 8.3 能力与疲劳

固定身体能力包括体重／质量假设、关节活动范围、关节力矩上限、左右握持能力、腿部发力能力和恢复参数。能力来源区分测量、个人提供、默认假设及敏感性范围。不能由身高或骨架大小推断力量。

疲劳首版优先左右手分别建模，再逐步加入腿部、核心或全身短时能力。避免在缺少证据时引入许多不能识别的生理参数。

采用归一化疲劳 F_i∈[0,1]。一种待验证的工程模型为：

F_i(t+dt) = clip(F_i(t) + [k_load,i × u_i(t)^p_i − k_recovery,i × r_i(t)] × dt, 0, 1)。

u_i 是模型估计的相对负荷，r_i 是满足休息条件时的恢复项，k 的单位与秒制时间一致。最大可用能力可设为 C_i,max(F_i)=C_i,base×(1−α_iF_i)，α_i∈[0,1]。这些表达是研究假设，不是已校准的人体生理规律。

几何路线没有可靠受力时，只能用明确命名的动作代价代理；物理路线可用模拟负荷计算。不能把停留时间直接等同于疲劳，也不能把模拟力矩当作真人测量。

每次独立 episode 初始疲劳一致；连续多次尝试若研究累积疲劳，则单独定义协议。学习过程中不增加能力上限、不延长可达范围、不降低成功标准。

## 9. 抱石环境与接触约束

最先实现明确起终点、允许岩点、墙面使用规则与碰撞几何的简化线路。岩点使用接触区域而非唯一中心点；岩点类型和抓握方向来自证据或显式假设，未知时做多情景复测。

抓握约束需要明确附着与释放条件、最大承载、摩擦／方向、接触持续性和超过限制后的滑脱。人工附着模型可以作为工程近似，但不能无限承重、凭距离瞬间吸附、释放后继续施力或用不可解释外力稳定身体。

脚部普通踩点、摩擦踩墙、脚跟勾挂、脚尖勾挂分别定义。第一版未实现某种接触时应标为范围外，不用普通脚踝附着替代并宣称支持。

逐步覆盖：

| 层级 | 动作 | 进入条件 |
|---|---|---|
| M1 | 普通移手移脚、换手、身体调整 | 基础连续控制与接触验证 |
| M2 | 高抬脚、交叉手、旗式、侧身配置 | 关节、身体深度及非接触肢体表达可信 |
| M3 | 脚跟／脚尖勾挂、脱脚与摆荡 | 足部接触与相应力学实现 |
| M4 | 动态跳跃、多肢体转换 | 高时间分辨率与完整动力学验证 |

上述顺序是研发课程，不是对抱石技巧难度的专业排序。研究记录同时保留未覆盖动作，不能将其一律判成错误。侧身、旗式等名称先作观察类别，不由单个二维角度阈值认定完整技巧。

成功定义由线路规则决定：合法起点、只用允许接触、达到规定终点并满足稳定完成条件。开发简化线路可暂设双手终点稳定 2 秒，但这是工程设定，必须按真实线路修正并在验证前冻结；单手终点等不同规则不强套双手要求。

超时、合法终点未完成、接触滑脱、落地、禁止接触、数值失稳、穿透及能力超限分别计数。达到求解预算只说明搜索未完成，不证明线路无解。

## 10. 模仿学习方案

第一步建立无学习参考重放：把示范接触和姿态作为目标，经重定向及受限执行生成轨迹。它用于诊断数据和环境，不计为 learned policy。

第二步训练上层行为克隆：输入当前接触、周围岩点、身体条件和姿态，预测下一动作或候选分布。多种可行 Beta 允许多个标签，不把与示范不同但合法的动作全部判错。

第三步训练下层动作模仿：将真人参考动作转为固定骨长的 Agent 动作，损失考虑关节姿态、末端位置、根部运动和接触时间。缺测部位不计算强监督；重要接触优先于画面风格。

第四步在环境中练习恢复：从示范中间、轻微姿态偏移、时间偏移等可恢复状态开始，检验 agent 是否能继续合法动作。扰动幅度由开发集确定，不将身体放入穿透或不可能状态后要求恢复。

本阶段优先比较确定性轨迹执行、行为克隆、示范引导控制。只有这些实验有可靠基础，才增加 AMP 等动作先验方法。通用动作先验若偏好走路或地面接触，必须用抱石素材重新检验。

## 11. 独立 Beta 规划与强化学习

先放开局部选择：固定起终状态，允许改变一个脚位或手序。随后选择中间岩点，最后不给参考顺序，规划整条线路。

规划使用固定线路允许岩点，并保证候选动作与实际身体相连。几何不可达动作可以筛除，但深度和能力存在不确定时保留筛除依据，防止过严规则漏掉真人动作。规划器的可达结论须经连续执行确认。

奖励由合法任务进展、终点完成、动作质量与消耗构成；碰撞、非法接触和能力超限是单独失败条件，不能让高奖励抵消违法动作。只奖励向上或减少动作数容易产生漏洞，应分别报告时间、动作数、峰值负荷、疲劳和稳定性，而不是用一个分数包办结果。

“省力”在本阶段指指定模型内的负荷或疲劳代理。候选 Beta 用多指标或帕累托比较，不把最少动作默认称为最省力。

强化学习先考虑 PPO 等可复现基准，再决定其他算法。训练采用相同环境接口、身体模型和预算，保留学习曲线、随机种子及成功失败轨迹。遇到失败不能仅靠反复调奖励，应检查接触、数据与控制是否成立。

模拟产生的数据带 synthetic 标记；通过质量检查后进入单独训练池，不能混入真人示范或测试真值。

## 12. GPT 自动反思协议

GPT 是上层研究组件：总结一次完整尝试并提出可执行 Beta 修改，不直接每帧控制关节。完整候选 episode 可以是完攀，也可以是失败或超时，均形成一个反思对象。

底层强化学习的海量短 rollout 默认使用本地反馈；按批次汇总给 GPT 的模式另列实验。工具式候选改进实验按每次完整尝试反思，明确每次调用是否真的执行，不把模板本地总结冒充 GPT 输出。

### 12.1 输入

输入包含冻结的任务规则、身体档案、岩点表、完整动作计划、实际执行接触、失败类型、能力及疲劳代理、关键帧／轨迹摘要、历史已试修改。真实受力未知时写 unknown；仅提供抽样画面时明确非完整视频观察。

研究默认优先结构化数据与模拟画面。发送真实视频画面须沿用用户对外发送及费用授权要求，不因研究计划自动上传数据或调用付费模型。

### 12.2 输出

结构化输出至少包含：failure_hypotheses、evidence_refs、proposed_edits、expected_effect、uncertainty、stop_reason。每项 edits 明确动作编号、肢体、目标 ID 或时间调整；它描述假说，不能自行改写模拟结果。

允许修改动作顺序、目标、准备动作与限定范围内的节奏。禁止修改身体能力、岩点布局、合法规则、验证阈值，禁止凭空新增岩点或已确认接触。

接收器检查 ID、规则、幅度与输出格式，非法或空建议记录为失败建议。每次修改必须完整复测，保存原建议、原始响应、实际采纳项、执行结果与采纳理由。解析失败时从已保存响应本地修复，不自动重复付费调用。

### 12.3 反思停止条件

同计划重复建议、连续无有效改进、达到尝试次数／模拟步数／调用费用上限或数据不足时停止。初始工程设定可为每个起始候选最多 5 轮修改，开发集调整后冻结。此次数不是已验证最优值。

### 12.4 反思与学习的区别

单线路上修改 Beta 并记录经验属于在线规划改进；把经验转为训练样本、更新策略参数并通过独立评估，才属于策略学习。测试期在线修改与离线模型训练分开报告，测试轨迹不回灌训练后继续用同一测试集声称泛化。

## 13. 对照实验与消融

| 实验 | 方法 | 主要回答 |
|---|---|---|
| E0 | 原示范重定向与受限参考执行 | 数据与模型能否表达真人动作 |
| E1 | 规则／搜索＋相同下层执行 | 不使用示范学习时已有能力 |
| E2 | 上层行为克隆＋相同执行 | 示范是否改善下一步选择 |
| E3 | 无示范强化学习 | 仅环境练习的效果及代价 |
| E4 | 模仿初始化＋强化学习 | 先模仿是否提高效率与稳定性 |
| E5 | E4／固定规划器＋规则式失败修正 | 普通自动纠错的基准 |
| E6 | 相同起点和控制器＋GPT 反思 | GPT 相对规则修正的增量 |

小规模阶段只执行 E0、E1、E2，验证通过后增加 E3、E4，最后增加 E5、E6。不因为计划列出实验就立即全部训练。

关键消融：去除身体比例输入、去除接触信息、去除局部疲劳、不给扰动恢复、去除 GPT、GPT 只给文字不执行、GPT 给建议但不检验。最后两项只用于说明机制和发现错误，不作为可用生成方法。

比较时固定允许岩点、身体能力、下层执行器和成功标准；能共用组件则共用。统计训练算力、模拟调用、候选次数、推理耗时及 GPT 成本。反思方法多用模拟次数时，必须另给同次数的搜索／随机局部修正对照。

至少采用 3 个训练随机种子作为初始研究要求；方差大或结论不稳定时增加种子。小样本先报告各线路原始结果，不能只给总体均值或显著性措辞。

## 14. 数据划分与泛化评估

首先按原视频和重复尝试分组，禁止相邻裁剪跨集合。同一线路的多个视频不能散落到“未见线路”训练和测试两侧；同一人分组也须符合评估任务。

设置不同评估场景，不合并成一个泛化率：

1. 已知线路、未见尝试：检查同环境鲁棒性，允许训练中见过线路，但不提供测试动作轨迹。
2. 未见线路：线路所有示范留出，测试只给环境和身体条件。
3. 未见攀爬者／身体比例：攀爬者及其示范留出，检查身体条件适配。
4. 新墙面或新场馆：有足够数据时，墙面及其线路整体留出，检查场景变化。
5. 新动作类型：后期单独检验，不能由同类型动作完成率替代。

初始可考虑按分组约 60%／20%／20% 划分训练、验证、测试；数据少时用按线路的留一或分组交叉验证。比例只是规划值，首先保证分组有效。数据不足以同时留出人和线路时，分别研究，不伪造独立性。

归一化统计、阈值、标签修正规则、模型选择及奖励调参只用训练／验证数据。冻结测试名单和配置后再运行主要测试；任何测试后修订需标记探索性结果，并另设最终留出验证。

已有真人测试视频仅供独立评价者评分，不能进入 Beta 生成输入。若评估允许用测试视频重建环境或身体，须只使用明确限定的几何信息，避免泄漏后续手脚顺序；“有视频辅助”和“只有线路”的设定分别报告。

## 15. 指标、初始门槛与证据等级

### 15.1 指标

| 维度 | 指标 | 口径 |
|---|---|---|
| 数据 | 关键关节可用比例、接触一致率、有效事件覆盖 | 带时间窗与分母；缺测不算正确 |
| 几何 | 骨长偏差、末端误差、二维重投影误差 | 用像素或身体尺度单位；有标尺才报米制 |
| 接触 | 目标 ID 一致、接触时间误差、非法接触 | unknown 分开，不当 free |
| 执行 | 单动作完成率、整条连续完成率、恢复率 | 参考目标和独立规划分开 |
| 物理 | 穿透、负荷超限、滑脱、辅助外力、数值失稳 | 硬失败单独计数，不以平滑掩盖 |
| Beta | 合法候选数、去重后结构差异、动作数、耗时 | 同序列不同动画不算新 Beta |
| 能力 | 峰值相对负荷、疲劳代理、能力扰动敏感性 | 明确模型内含义 |
| 泛化 | 分线路／身体／墙面的完成情况 | 按分组统计，不把帧当独立样本 |
| 反思 | 有效建议率、采纳率、改善幅度、重复与非法建议率 | 同预算比较，计模型调用成本 |
| 人工 | 可达性、规则、接触合理性、关键动作认可度 | 评分者尽量不知方法来源 |

主要研究终点建议为：未见线路中满足冻结规则的连续模拟完成情况。体力节约、候选多样性、动画自然性作为分项，不替代主要终点。路线 A 的终点仅称几何／简化接触完成，不能沿用路线 B 物理完成名称。

置信区间按线路等独立组自助采样；少量组时同时报告每组结果和范围。没有足够组数时不作强统计结论。首轮不输出未经校准的“真人成功概率”。

### 15.2 初始工程门槛

首轮可用以下门槛启动数据筛选：关键动作窗必要关节有效率至少 90%、关键接触全部可复核、固定模型骨长相对设定偏差不超过 1%。其中关节识别置信度先参考现有实现的 0.5，但不是准确率或专业标准。质量不足时允许局部样本，不将其作为整条可靠示范。

骨长偏差门槛约束 Agent 模型，不代表视频真实骨长估计误差。末端误差门槛根据岩点接触区域和标注不确定性制定，不能统一用固定厘米数覆盖所有视频。

以上都是待开发集验证的工程起始值，不是科研结论。主测试前冻结并记录调整依据；禁止测试后放宽门槛提升成绩。

### 15.3 结论分级

- L1：原视频观测与接触标注已复核。
- L2：固定骨架在简化环境中可复现。
- L3：受限控制在指定物理环境中完成。
- L4：在留出线路或身体条件中有稳定表现。
- L5：独立抱石复核者认可部分候选。
- L6：另行组织的真人尝试验证。

结论逐级报告，不默认从 L2 跳到 L6。真人尝试不是当前首轮必须交付项，也不因编写计划自动组织或联系人员。

## 16. 模拟漏洞与失败诊断

在学习前建立小型反例集：超远伸手、无限承重、手未接触就施力、穿墙、身体借地面反弹、非法点、持续辅助力、关节速度异常、终点瞬间触碰及超时。几何与物理路线各自检查适用反例。

直接相关的 [HumanoidClimb-RL 仓库](https://github.com/s1ddh-rth/HumanoidClimb-RL#results)报告其论文实验中的完整 dyno 转换成功率约为 0%，并出现借地面反弹的失败模式。因此该项目用于接触环境和奖励设计参考，不能当作已验证成功基线。

故障分类统一为：data_error、scale_uncertain、scene_uncertain、kinematic_unreachable、contact_invalid、control_failure、capacity_exceeded、rule_violation、numerical_failure、budget_exhausted、unknown。推测原因与实际违反的条件分开。

失败处置：

| 现象 | 首先检查 | 后续动作 |
|---|---|---|
| 真人参考动作也失败 | 骨架、尺度、环境、接触模型 | 修复或收窄研究范围；不先加训练量 |
| 参考动作能重放，策略执行失败 | 控制器、参考可执行性、训练状态覆盖 | 加强恢复课程或改变控制表达 |
| 模拟成功但动作异常 | 接触和奖励漏洞、外力、能力上限 | 修模型并重新跑受影响实验 |
| 同线路好，未见线路差 | 数据覆盖、环境表示、过拟合 | 加学习曲线及检索基准，收窄泛化结论 |
| GPT 没有改进 | 输入证据、合法建议率、同预算基线 | 停止扩大调用，记录负结果 |
| 三维无法可靠恢复 | 深度和墙面信息不足 | 保留路线 A，不宣称动力学验证 |

## 17. 开源项目评估与选择

选型先运行官方最小示例、核对依赖与输入格式，再接入自己的动作。下载、安装和大规模训练属于后续执行，不是本计划编写时已完成的事项。

| 项目 | 计划角色 | 最先核实的问题 |
|---|---|---|
| [MimicKit](https://github.com/xbpeng/MimicKit) | 首选动作模仿训练候选 | 动作格式、身体替换、选定模拟后端、自定义接触与 PPO 训练 |
| [HumanoidClimb-RL](https://github.com/s1ddh-rth/HumanoidClimb-RL) | 抱石相关环境参考 | 抓握是否人工约束、力量限制、目标姿态与奖励、失败复现 |
| [HumanoidClimbEnv](https://github.com/dylancaet/HumanoidClimbEnv) | 接触环境补充参考 | README 开发中状态、代码完整度和训练入口 |
| [ProtoMotions](https://github.com/NVlabs/ProtoMotions) | 后续批量训练候选 | 对项目规模的必要性、环境扩展成本、选定后端资源 |
| [PHC](https://github.com/ZhengyiLuo/PHC) | 噪声输入与恢复参考 | 对悬挂和墙面接触的适用性，不能沿用地面动作成绩 |
| [GVHMR](https://github.com/zju3dv/GVHMR) | 可选三维动作恢复对照 | 攀岩姿态误差、接触漂移、尺度及许可证 |
| [DeepMimic](https://github.com/xbpeng/DeepMimic) | 原理与数据表达参考 | 仓库已推荐 MimicKit，不优先采用旧依赖栈 |

[MimicKit 官方说明](https://github.com/xbpeng/MimicKit)提供 DeepMimic、AMP 等方法及不同仿真后端入口；[ProtoMotions 官方说明](https://github.com/NVlabs/ProtoMotions)提供更丰富的物理人体训练与迁移能力。这里的选型优先级是本项目判断，不是对各框架效果的实测排名。

研究使用代码、模型资产、预训练权重和数据集分别记录许可证。[GVHMR 许可证](https://github.com/zju3dv/GVHMR/blob/main/LICENSE)允许教育、研究与非营利用途，并限制商业使用；本轮研究仍需遵守其修改分发等条件。框架代码开放不意味着 SMPL 等身体资产和外部视频自动具有相同授权。

| S4 独立规划 | 局部变化到整条 Beta，E3／E4 | 候选、独立运行记录、分组测试 | 能在不给目标顺序时产生可检验候选 |
| S5 反思实验 | E5／E6，同预算比较 | 提示词、响应、修改轨迹与增量报告 | 有效／无效均形成明确结论 |
| S6 汇总 | 敏感性、人工复核、复现整理 | 研究报告、实验索引、下一步决策 | 证据可追溯，边界与负结果完整 |

S2 若只能复现局部动作，交付局部结论并决定继续修环境；不能把它写成整条 Beta 已成立。S4 若只能产生几何候选，保留其研究价值但不升格为物理生成系统。

每阶段保存检查点，结果按只读方式引用。问题重复出现时依据失败表收窄范围或切换路线，不通过改成功定义假装推进。

## 19. 工作量、硬件与费用规划

以下为初始排期估计，按有效研究工作日，不是已经确定的交付日期或训练耗时承诺。

| 工作 | 初始估计 | 主要不确定因素 |
|---|---|---|
| S0–S1 数据与环境准备 | 3–7 日 | 视频数量、标注质量、环境兼容 |
| S2 单线路复现 | 5–10 日 | 三维／接触信息、身体转换、控制器 |
| S3 模仿与恢复 | 5–10 日 | 样本质量、模型和训练资源 |
| S4 独立 Beta | 7–15 日 | 搜索空间、接触验证与泛化 |
| S5 GPT 对照 | 3–7 日 | 稳定失败信号、外部调用与预算 |
| S6 汇总复核 | 3–5 日 | 重跑、人工评价与不确定性 |

首个开发线路里程碑建议按 1–3 周量级评估；完整探索为约 26–54 个有效工作日，部分任务可重叠，但依赖阶段不能跳过。若缺少几何或需重建控制环境，时间可能明显增加。

数据整理与小型序列模型优先本地资源。GPU 物理训练先测定 1／少量／逐步增加环境数的吞吐、峰值显存和数值稳定，再选择批量规模。没有核实硬件前不承诺本机可跑指定并行数量；不套用开源 README 的训练速度预测本项目。

Windows 上先核实选定后端兼容性。确有需要时评估 WSL／Linux 或研究服务器，但不修改现有 App 环境，不自动安装庞大依赖或申请云资源。

每个实验设置最大环境步数、墙钟时间、显存、存储、GPT 轮数和费用上限。先短跑验证再长跑；所有资源消耗记录在 run_manifest。云 GPU 与付费 GPT 的具体预算在真实执行前根据实测和授权确定。

## 20. 研究目录与可复现交付

后续实验建议放在当前项目基线的独立研究目录，例如 `research/boulder_agent/`。本轮只新增计划文档，不创建训练程序或修改业务模块。

建议目录职责如下：

```text
research/boulder_agent/
  README.md                 复现步骤与研究边界
  schemas/                  数据及反思协议
  configs/                  身体、环境、训练与评估配置
  data_manifests/           匿名清单与冻结划分
  adapters/                 既有数据到研究格式的只读转换
  environments/             几何／物理抱石环境
  baselines/                搜索、模仿、强化学习与反思对照
  evaluation/               指标、反例与复核程序
  prompts/                  版本化反思提示词
  reports/                  质量、实验和结论报告
  outputs/                  本地忽略的轨迹、模型与回放
```

真实视频和个人研究数据留在指定本地数据位置，不提交到源码。输出另存，使用研究编号与摘要关联，避免公开私人绝对路径。拟提交的清单也须检查身份及内容泄漏。

每次实验记录：run_id、代码提交及在途改动摘要、配置摘要、输入数据版本与划分摘要、依赖、硬件、随机种子、环境步数、停止原因、指标、失败事件、模型位置。GPT 实验另存供应商／模型、调用时间、提示词摘要、请求编号、用量及原始响应；密钥不进入日志。

由于当前基线有较多已有在途修改，不能仅用 Git HEAD 描述研究输入；需要保存相关源码差异摘要或研究快照。开源依赖固定提交或版本，避免更新后不可复现。

每个报告至少提供一种成功、典型失败及边界案例。回放标明实测／重定向／模拟／插值，时间统一对齐原片；不能将模拟骨架画到原视频上后误导为真人观测。

## 21. 首轮具体执行清单

1. 建立输入清单，只核实可用视频、既有分析和环境信息，不重新处理全部视频。
2. 选一条开发线路及完整尝试，人工确认起终点、允许岩点、核心接触和结果。
3. 检查关节布局、源帧时间、横纵尺度和镜头配准，隔离缺测与错位段。
4. 拟合一套固定身体比例，保存不确定区间及尺度来源。
5. 建立接触序列与连续动作样本，至少包含若干完整转换和稳定保持。
6. 使用最简环境验证参考动作；明确采用几何模型还是物理模型。
7. 生成原片、参考骨架和实际执行的对照回放，定位最大误差。
8. 逐个测试超远接触、非法点、无限承重、穿透与虚假完攀反例。
9. 修改一个脚位或手序，检查可达性、连续执行和失败类型。
10. 写首轮报告：哪些动作可复现、哪些不能、缺少什么、下一阶段是否值得投入。

首轮不调用 GPT 来掩盖环境问题，不同时追求全部抱石动作，不宣称模型已学会独立攀爬。报告形成后，根据证据选择扩大数据、修环境、训练模仿或暂时停留在几何 Beta 研究。

## 22. 完成标准与下一步决策

本研究完成不以“生成一个动画”判定。完成需要交付可追溯数据、至少一组同预算基线比较、清楚的成功和失败边界，以及能够重跑的配置和代码。

若视频改善了接触选择但无法支持连续物理执行，结论应是“示范辅助 Beta 候选规划有效，执行层仍未验证”。若物理执行成立但新线路表现较弱，结论应收窄到已有环境。若 GPT 没有超过规则修正，应保留这一负结果，不继续将 GPT 作为必要组件。

只有留出评估及独立抱石复核提供支持后，才讨论扩大研究或后续产品化；网页、App、商业集成与部署均不属于本计划任务。

## 23. 研究依据与引用范围

本计划的身体、接触、疲劳和验收设定是拟检验方案，不是引用文献已经验证的参数。外部依据用于支持方法选择与识别限制，不能替代本项目实测。

- [DeepMimic 原论文](https://arxiv.org/abs/1804.02717)：示范引导物理角色控制与任务目标结合的基础；不是抱石效果证明。
- [2019 年模拟攀岩强化学习论文](https://ieee-cog.org/2019/papers/paper_34.pdf)：给定手脚目标下的攀岩动作控制与 episode 初始化；与独立线路 Beta 选择应区分。
- [2025 年攀岩控制论文](https://diglib.eg.org/items/f2e12ac3-95b5-4afd-91c0-4e855fec04db)：先学习悬挂再学习攀爬的分阶段路线；不代表本项目已有同样数据和环境。
- [MimicKit](https://github.com/xbpeng/MimicKit)、[ProtoMotions](https://github.com/NVlabs/ProtoMotions)：候选训练框架；本轮只核对公开说明，未完成安装复现。
- [HumanoidClimb-RL](https://github.com/s1ddh-rth/HumanoidClimb-RL)：攀岩环境及失败模式参考；不能引用为成熟完攀工具。
- [GVHMR](https://github.com/zju3dv/GVHMR)及[许可证](https://github.com/zju3dv/GVHMR/blob/main/LICENSE)：三维动作恢复候选及使用条件；攀岩适用性待实验。

公开仓库的动态内容查询日期为 2026-10-09。实际开始实验时固定所用版本，再记录与此计划的差异。
