# 攀岩项目 Windows 桌面版迁移计划书

日期：2026-10-06（北京时间）  
用途：交给另一个 Codex 聊天框执行桌面迁移；本聊天框继续研究新的骨架模型。

## 1. 用户目标与本次范围

将当前已有攀岩项目做成可以发给别人使用的 Windows 桌面软件。用户双击程序打开独立窗口，选择本机照片或视频，使用本机分析能力，结果保存在本机。不要求手机端，不以商业服务为目标。

第一版以迁移已有功能为主，复用现有 Vue 界面、Python 后端、照片专项模型和复盘逻辑。桌面化与姿态模型替换是两项独立工作：本计划不接入 InstantHMR，不承诺因桌面化提高识别质量，不将已有云端功能写成已离线。

完成目标是“可安装或解压即用、可独立运行、可在其他 Windows 电脑验证”的交付包，不能只交付一个仍依赖开发目录的启动脚本或远程网站快捷方式。

## 3. 推荐架构

推荐先验证 `pywebview + 本机 Python 后端 + 已构建 Vue 静态文件`。后端和分析工作进程随程序启动，桌面窗口显示本机界面。现有 HTTP 接口可以保留，服务仅监听回环地址，不部署到公网。

```text
双击攀岩软件
  → 启动器检查运行环境、可写数据目录与已有实例
  → 启动本机后端与任务处理
  → 独立桌面窗口打开现有界面
  → 选择本机素材 → 岩点识别／复盘／导出
  → 结果写入当前用户的数据目录
```

前端在构建时使用 Node，最终使用者无需安装 Node 或运行 Vite。程序携带必要的 Python 环境和依赖，最终使用者无需安装 Python、Codex 或修改环境变量。

采用受支持的 Windows WebView2 渲染环境；安装或检测策略必须具体落实。先验证当前播放器和视频编码在该窗口中能运行，再确定外壳。若 pywebview 经实测不能满足视频或打包要求，记录失败证据后选择替代外壳；保持现有界面和分析逻辑可复用。

桌面包使用独立数据目录与运行实例，不借用当前开发服务、不结束用户其他 Python 进程。原 `4176/8004` 开发入口和启动脚本保持可用；桌面实例可分配独立回环端口，并将真实服务地址交给窗口，不能靠更改开发入口掩盖启动冲突。

## 4. 必须保留的行为

### 照片线路

- 上传原图后不自动识别。
- 原图取色／调色盘选色，用户点击后才识别所选颜色线路。
- 使用现有专项模型原生掩膜和轮廓内分色。
- 支持用户复核、补点、保存个人照片线路和恢复任务。

### 视频复盘

- 保留上传与本地准备、逐个补点／删点、确认全部岩点，再单独开始付费分析的顺序。
- 保留左侧真人骨架／岩点、右侧当前四肢用点图、底部动作顺序。
- 保留默认 0.75 倍速、原片时间、动作说明与结束总结行为。
- 分析后逐点编辑只保存草稿；确认全部岩点后复用 `pose_samples` 统一重算。
- 本地重算、重生成岩点图和导出不得新增姿态或百炼请求。
- 保留旧视频、旧分析与修订恢复；失败不能覆盖上一版可用结果。

第一版复用现有本地模式。核实本地账号和数据访问行为，避免把生产邀请码、生产账户、线上数据库或生产配置带入软件。确需改变本地账号体验时，先说明具体影响，不顺便重做账户系统。

## 5. 本地能力与云端能力

| 功能 | 第一版处理方式 |
| --- | --- |
| 照片／视频岩点识别 | 搬到本机，复用现有已核验模型 |
| 保存、恢复、岩点编辑、既有姿态重算、视频生成与导出 | 本机完成 |
| 阿里云人体姿态识别 | 保留现有可选能力，需要用户自己的配置和独立授权 |
| 百炼动作名称核对 | 保留独立调用与计量；未配置时给出明确提示 |
| InstantHMR 或其他本地姿态模型 | 另一个评测任务负责，不属于迁移交付要求 |

“本机分析”指具体已经本地运行的功能。断网时应能使用已有本地能力、读取历史结果；需要云服务的功能应清楚显示配置或联网要求，不自动回退到收费调用。

## 6. 实施阶段

### 阶段一：依赖盘点与运行路径整理

1. 记录当前基线、已有改动和迁移涉及文件，确认受保护目录。
2. 梳理后端实际运行依赖、动态导入、原生库、专项模型、配置、字体和 FFmpeg。
3. 输出清单：名称、来源、版本、大小、用途、CPU／GPU要求、随包分发条件。不照搬包含开发工具的整个 `requirements.txt` 环境。
4. 将安装资源、可写用户数据、临时文件、日志与用户自己的服务配置分开；避免模型安装在不可写目录时创建缓存失败。
5. 新建桌面专用启动配置，不能复用会自动读取开发 `.local/photo-vision.env` 的入口。明确禁止读取开发私密配置、真实测试视频清单及诊断素材。

交付：依赖／资源清单、目录合同、具体打包方案与阻塞项。

### 阶段二：桌面窗口与生命周期

1. 构建 Vue 静态文件，明确资源路由和 API 路由优先级，不能使用 Vite 开发代理作为最终运行方案。
2. 启动本机后端，健康检查通过后打开独立窗口；支持加载进度与可理解的启动失败提示。
3. 验证照片选择、视频选择、图片与复盘媒体读取、Range 请求、下载和导出路径。
4. 实现重复启动处理、资源任务互斥、正常关闭、取消／恢复任务、异常退出后恢复。
5. 回环服务增加实例级访问保护，约束外部网页调用；不监听 `0.0.0.0`。退出时只处理本实例启动的进程。

交付：开发环境可运行的桌面入口、启动与退出验证、照片／视频页面预览。

### 阶段三：可分发包

1. 在独立、受控的构建环境打包，优先采用目录式程序包，再制作安装包。无需强求把大型模型塞入单个 EXE。
2. 打包必要 Python 运行环境、后端依赖、Vue 静态文件、FFmpeg、字体和已确认可分发的模型资源；固定版本与校验值。
3. 核实专项模型和原生依赖的实际 Windows 可移植性；不能用当前电脑已安装的 Detectron2、Torch 或外部目录掩盖缺包。
4. 没有兼容显卡时验证 CPU 路径。有显卡的加速只在实际兼容性验证后开放，不在迁移时盲目升级已有 Torch／CUDA 环境。
5. 缺失或损坏资源应在启动／分析前明确提示；资源获取方式需可复核，不能静默下载未知权重。
6. 用户数据默认写入当前用户应用数据目录，例如 `%LOCALAPPDATA%/AiClimbing/data`；具体目录在阶段一固定。配置与密钥单独存储，不输出到日志或打包清单。
7. 更新程序保留用户数据。测试卸载行为，默认不删除用户素材、结果或配置。

交付：带版本号的 Windows 程序包／安装包、校验值、构建脚本、简明使用说明。

### 阶段四：独立环境验收

在没有项目源码路径、Codex、Python、Node 和开发缓存的干净 Windows 环境验证。仅在本开发机运行成功不算可分发验收。

| 验收项 | 合格条件 |
| --- | --- |
| 安装与启动 | 普通用户权限启动，首次运行提示明确，不要求配置开发环境 |
| 路径适配 | 中文、空格路径可用；未安装在原开发盘符仍可用 |
| 照片流程 | 不自动识别；选色、识别、复核、补点、保存、重启恢复成立 |
| 视频与导出 | 解码、转换、复盘播放、原片时钟、0.75 倍速和导出保持一致；覆盖已有 HEVC 兼容路径 |
| 草稿与成本 | 上传／补点／确认不触发付费；已保存姿态本地重算不新增请求 |
| 断网与缺配置 | 本地能力和历史结果可用；云端功能准确提示，无隐式请求 |
| 进程与资源 | 重复启动、任务中退出、异常重启可处理；不误结束其他程序 |
| 数据保护 | 更新／失败不覆盖旧结果；开发真实数据和密钥未进入分发包 |
| 配置与性能 | 报告测试电脑 CPU、内存、显卡、耗时和峰值内存；最低配置据实测确定 |

真实云端调用不是迁移验收前提。优先复用现有构造素材、模拟响应与隔离数据验证复盘链路；模拟通过不能写成真实姿态准确率通过。若当前没有干净电脑、虚拟机或完整模型资源，完成所有可做工作并明确标注未验证部分，不能宣称最终验收完成。
