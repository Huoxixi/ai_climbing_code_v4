# AI 复盘：动作样本驱动识别与知识库实施计划

日期：2026-10-03。版本：v1.0。配套需求：[建设方案 v1.1](AI复盘_动作样本驱动识别与知识库_建设方案_2026-10-03.md)。状态：需求和计划已补全，阶段 0–5 均未启动；本次未处理新视频、训练模型、修改业务程序或部署。

## 1. 执行范围与基础

单人串行推进，先获得少类别、可追溯的新视频识别结果，再细化个人动作分析。不以数据量、聚类图或成功案例替代识别评价。用户已说明素材由本人授权；不重复索取已有授权，但素材使用范围未知时需补登记，不能把本地分析权限扩展为云端上传、训练或公开比赛播放的权限。

待用户指定素材目录后启动。保存原片并另存派生产物，真实媒体、身份和私有路径不提交代码仓库；不扫描或覆盖 `.local/`。源码基于指定最新版目录，执行前检查正在进行的其他修改，所有模型/工具依赖和数据路径在本地记录。

2026-10-03 只读核对发现可以复用的基础：

| 现有模块 | 可复用内容 | 需要补足的地方 |
| --- | --- | --- |
| `backend/core/replay_action_segmentation.py` | 连续轨迹检查、躯干相对运动、明显位移候选 | 当前把重叠/接近运动合并，可能漏小幅动作，不能直接代表全部动作事件 |
| `backend/core/replay_actions.py` | 候选组、原片时间、移动/未知区间组织 | 回看组与细粒度事件分开，补漏检事件和多标签关联 |
| `backend/core/replay_action_naming.py` | 受控名称、技术必要条件、知识单元引用 | 现有词典不是已训练识别器，技术自动确认仍关闭 |
| `backend/core/replay_action_jobs.py` | 账号隔离、任务、版本、修正、撤销和导出 | 新结果适配、缓存依赖和陈旧任务保护须按实施时接口核对 |
| `docs/bouldering-knowledge/` | 术语、来源、知识合同 | 真实样本索引另建，不改构造例性质或既有审核状态 |

现有文件处于其他任务在途修改中，以上是当前快照，不保证接口冻结。实施阶段再核对；不把阈值、条件枚举或现有局部自查当新素材准确率。

## 2. 阶段总览与工作量

| 阶段 | 主要结果 | 集中开发/整理工作量估算 |
| --- | --- | --- |
| 0：审计素材 | 知道什么可用、有什么缺口 | 1–2 人日 |
| 1：发现类别与试标 | 少量可执行的类别卡和边界规则 | 3–5 人日 |
| 2：样本索引与评测冻结 | 可追溯样本、可检索对照、隔离数据集 | 4–8 人日 |
| 3：新视频识别基线 | 整段视频的候选事件与类别报告 | 5–10 人日 |
| 4：页面与纠正闭环 | 用户能够逐项回看、修正和撤销 | 3–5 人日 |
| 5：难例与迭代 | 根据实测扩大可用覆盖 | 持续迭代，按失败原因估算 |

前五阶段合计约 16–30 个集中人日，是尚未审计素材的粗估，不是完成日期承诺；不含专业审核等待、正式验收补充采集、素材规模扩大或新姿态后端建设。阶段 0 后依据实际数量、标注速度和设备重新估算，单人业余推进不能直接换算为连续日历天数。

## 3. 阶段 0：素材审计

任务：

- P0-01：只登记指定目录，生成匿名素材 ID、内容摘要、媒体规格、可解码状态和用途记录，不输出身份授权凭据。
- P0-02：核对重复、同原片剪辑、人员/线路/机位关系；未知关系单列，不假定独立。
- P0-03：从可用素材选约 10–20 段原视频先导，覆盖实际存在的不同人、墙面及质量情况；该数量用于流程探索。
- P0-04：记录出画、遮挡、剪切、速度、帧时间与局部可见性。自动剪切检测仅提议，人审核对，不能把快速动作误作剪切。
- P0-05：小批测解码和已有轨迹生成成本；优先复用获准的已有分析，不默认触发云端姿态请求。

交付：素材清单、质量问题表、重复来源组、时间映射记录、先导选择清单、资源初测。研发集/测试预留组在广泛动作发现前规划，避免全部素材都先用于选类。

退出条件：每个先导视频能追溯到原文件；明确哪些片段能用于外形、连续时序、原速统计；测试预留组未参与探索。原速未知及授权用途未知必须可见，不能默认补齐。

失败处理：素材缺乏连续画面或关键部位时减少目标类别；无法解码的文件保留失败原因；人员/来源关系未知的材料可探索但暂不算独立验收组。

## 4. 阶段 1：动作发现、命名和标注试跑

任务：

- P1-01：先看连续原片建立人工事件草稿，再运行候选分段，记录窗口外漏检；先不用模型结果引导参考标签。
- P1-02：提取已有可靠轨迹，按身体尺度和躯干相对运动整理；相似检索/聚类只在研发材料提出候选。
- P1-03：逐组对照正例、跨组例和易混反例，排查墙面、衣服、机位或人员分组偏差。
- P1-04：形成建议 4–6 个类别，先实现证据最充分的少数类。写通俗名、专业名/来源、成立条件、起止规则、变式和不能推断内容。
- P1-05：试标左右侧、重叠事件及边界不确定区间；复标部分材料，整理名称/边界分歧。专业术语争议保留待核，不凭投票解决定义。

交付：候选类别卡、已核样例、首版标注协议、分歧表、现有窗口漏检清单。每类尝试获得 15–30 个正例与同量易混反例，来源覆盖按实际记录；该目标不足以正式自动确认。

退出条件：至少有少数类别能够按规则与反例区分，必要证据可见，已有试标支持其边界。没有稳定区分规则的类不能进入自动识别开发，只保留样本候选。

失败处理：减少类别、合并不可区分子类或降为基础描述；不能为凑目标数把左右侧/体型差异全部新增为类。

## 5. 阶段 2：样本索引和评测合同

任务：

- P2-01：使用离线 JSON/JSONL 索引或其他轻量本地格式落实配套方案的数据合同；先做可打开原片的清单，不先搭独立平台。
- P2-02：样本以完整事件计数，存起止、不确定区间和上下文窗口；类别多标签、必要条件缺失和未标注三种情况分开。
- P2-03：补真实正例与易混反例，关联知识单元；专业审核和样本核对状态分别保存。
- P2-04：冻结开发/验证/测试清单及摘要。正式评价按既有人员/线路连通组隔离；如果关系把素材连成一大组，则缺乏独立留出，不能随机切片解决。
- P2-05：制定事件一对一匹配、重复预测处罚、重叠标签、边界区间、拒识和可判定分母规则；保留现有正式验收条件。
- P2-06：建立按类查看正例/反例及人工补标入口；第一版可用本地报告和已有播放器。

交付：样本索引 v1、类别卡 v1、标注协议 v1、冻结清单、评测合同、漏检/误报记录模板。真实数据本地存放；代码仓库只保存空模板、工具和非个人示例。

退出条件：所有样本和标签有来源与版本；不把未知当负例；数据隔离检查通过；容差及探索验收目标在看测试结果前登记。留出不足可进入开发实验，但阶段 3 必须写“尚无独立泛化验证”。

失败处理：样本不足的类降为待核；补充不同来源的既有素材。只在验证集调整阈值；禁止用试标或开发集冒充冻结测试。

## 6. 阶段 3：整段新视频的识别基线

任务：

- P3-01：保留现有回看片段规则，在内部建立肢体事件及技术候选定位；合并回看组不删除内部事件。处理小幅运动、相邻重复事件和跨肢体重叠。
- P3-02：先做可解释轨迹规则与已核样本检索；特征不足再试预训练特征和小分类器。每次只比较有明确假设的改动。
- P3-03：识别状态区分候选、已知类拒识、缺证据和运行失败；质量不足不宣布新动作，相似度不当概率。
- P3-04：在未裁剪验证视频检查定位、分类、误报/分钟、覆盖、拒识和边界误差；单独看普通运动与易混反例。
- P3-05：固定模型、特征、阈值及配置后运行冻结测试，保存机器原始输出；人工改正另列。
- P3-06：记录本机规格、端到端耗时、资源峰值与每分钟视频处理时间；第一次提取和缓存命中分别记录。

交付：识别器开发版本、完整视频原输出、按类/条件报告、典型误判与漏检、基线对比、运行成本报告。没有当前素材实测前，不写准确率或实时保证。

探索退出条件：整段新视频能生成时间与类别候选；满足阶段 2 冻结的探索目标且误差可解释；没有独立留出时仅允许受限开发演示。自动确认仍关闭，正式开启须满足既有独立验收。

失败处理顺序：先检查参考标签和素材时间 → 定位漏检/合并 → 类别混淆 → 特征与缺失证据 → 阈值与拒识。分类器看不到目标动作时，增加训练量通常不能解决分段漏检。

## 7. 阶段 4：个人复盘与纠正

任务：

- P4-01：接入现有动作时间轴和详情；主行保持肢体、简短名、文件/原片时间，候选与本人确认有明确状态，不增加字幕侧栏。
- P4-02：回看组内保留多个事件及重叠关系；展开后能分别定位和修正，不强迫整个组只有一个技术名。
- P4-03：回放当前证据和获准样本参照。没有样本访问权限时仅展示定义；参考样本不证明当前接触。
- P4-04：修正类别、侧别、边界，保存修改前后和版本；撤销不跨不兼容版本覆盖，保留机器原输出。
- P4-05：建立待审样本队列，修正需核对来源、用途、定义和数据分组后才能进入下一版研发集。
- P4-06：任务异步、取消、失败重试、缓存失效和账号隔离复用既有机制；保护历史记录、原始分析与导出。

交付：可逐项回看/修正的个人动作时间轴、版本审计、待审队列和回退路径。

退出条件：同一片段多个动作不丢失；用户能发现并改正误判；0.75 倍播放与原时间统计正确，原素材变速未知时不伪装成原速；切换记录、撤销、取消和结果版本冲突不污染历史数据。

失败处理：识别质量不足时仍可提供明确标记的候选整理与人工复盘，不能把修正后的结果计入模型成绩；不扩大页面复杂度掩盖识别问题。

## 8. 阶段 5：补难例、升级与正式验收

按错误来源补最有效的材料：边界错误补连续过程；类别混淆补易混反例；换人失效补独立人员；看不见必要细节则保留缺证据，而不是制造标签。

类别拆分必须同时有稳定定义、可见区别和独立评价收益。类别合并/改名保留迁移记录；模型版本与标签定义共同固定，旧视频结果不无声改名。每次升级提供旧版对照、新增适用条件和回退版本。

正式自动命名执行[既有独立验收](AI攀岩复盘_细化动作独立验收说明_2026-09-30.md)，先补足两位审核者、独立分组和按类材料。可用于开发的单人标注不等于正式参考标准。比赛公开播放样本只使用确认有展示用途的材料。

退出条件：欲开启的类别逐类满足冻结验收，保留失败类与受限条件；工具分数不自动授予确认资格。若无法完成正式验收，交付范围是候选识别原型和真实开发报告，不宣称全自动已验证。

## 9. 针对性验证清单

| 检查 | 必须覆盖的情况 | 执行阶段 |
| --- | --- | --- |
| 时间与素材 | 可变帧率、已知/未知变速、剪切、重复/近重复、解码失败；禁止跨剪切连续推断 | 0、2 |
| 标注合同 | 多标签、未知条件、不确定边界、侧别镜像、遗漏标签不算负例 | 1、2 |
| 数据隔离 | 同源剪辑/增广、同人或同线路相连、未知来源组；测试不得参与选类/调参 | 2、3 |
| 分段 | 缓慢/小幅动作、连续重复、多人歧义、躯干携带运动、遮挡与重叠动作 | 1、3 |
| 评价 | 一对一匹配、重复输出、零输出、错误侧别/目标、缺证据放行、拒识与覆盖并报 | 2、3、5 |
| 产品 | 当前片段回看、原时间与 0.75 倍速、多个事件修正和撤销、折叠详情 | 4 |
| 生命周期 | 陈旧结果、原素材/词典变化、取消后写回、跨账号访问、失败重试、版本回退 | 3、4 |

代码实施时对分段、数据合同、版本和权限等实质逻辑做针对性自动测试；视觉类别是否正确必须通过真实视频核对，不能写镜像实现的测试替代。本文是未来检查清单，本次未运行这些检查。
