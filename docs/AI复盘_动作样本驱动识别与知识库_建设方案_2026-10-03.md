# AI 复盘：动作样本驱动识别与知识库建设方案

日期：2026-10-03。版本：v1.1，补全需求、实施边界和验收。状态：建设设计，尚未读取本次新视频、形成真实样本类别或实施新识别器。用户已说明素材经过本人授权，素材文件夹尚未指定。

执行入口：[分阶段实施计划](AI复盘_动作样本驱动识别与知识库_实施计划_2026-10-03.md)。本文定义需求与边界，配套计划定义任务、交付物、失败处理和验收；两者均不代表已实现。

## 1. 最新目标与建设顺序

用户希望从大量攀岩动作样本中发现相似而可区分的动作，结合通俗描述与专业名称建立类别和知识库；输入新视频后，自动定位动作、识别类别，再逐步细化每名攀岩者的动作分析。

本方案作为当前建设主线。2026-10-01 的[同线路比较 PRD](AI复盘_同线路细粒度动作对比_PRD_2026-10-01.md)和[实施计划](AI复盘_同线路细粒度动作对比_实施计划_2026-10-01.md)保留为后续应用设计，先后顺序调整为：**真实样本整理 → 动作发现与命名 → 样本和知识关联 → 新视频分段识别 → 个人动作分析 → 跨次比较**。

首版定位为单人可以持续建设的少类别闭环。暂定从素材中选择 4–6 个证据充分、容易区分且频繁出现的类别；这是开发规模建议，具体类别与数量由素材决定。不会预先要求所有视频都符合已有词典，也不会把每个姿态差异都命名为新技术。

## 2. 需要建立的三类资产

| 资产 | 保存什么 | 如何使用 |
| --- | --- | --- |
| 动作样本库 | 原视频引用、片段时间范围、人员/机位分组、正例、易混反例、可见性及人工标签 | 发现类别、训练或匹配、误判复查 |
| 动作知识库 | 类别定义、通俗名、专业名及来源、成立条件、易混区别、适用画面和未知边界 | 解释识别结果、维护统一命名 |
| 动作识别器及版本记录 | 分段方法、特征、分类或检索方法、输出阈值、支持类别和实测结果 | 在未见过的新视频中定位并识别动作 |

文字知识库不能替代视频识别器。给片段取名也不等于模型已经学会该动作。已有知识库的 `automatic_use=false` 涉及知识自动使用边界，不能通过改成 true 来宣布识别完成；识别器另记录其验证状态，识别结果也不自动升级为训练建议。

## 3. 从片段发现类别，而不是从单帧猜动作

动作包含进入、持续变化和退出过程。先在连续视频中提出候选窗口，保留前后上下文，再核对移动肢体、躯干变化、另一肢体关系和可见接触；不能只保存动作最显眼的一张图片。

初始特征结合身体尺度归一化后的手脚轨迹、躯干相对运动、肢体相对位置、时序和局部画面。原始像素位移容易受机位、体型影响；二维骨架又不足以单独证明接触、鞋边、握法或实际用力，因此需要保留视频核对入口。

机器聚类或相似检索只用于提出候选分组。人工核对每组的共同动作特征、组间差别及反例：衣服、墙面、同一个人或同一条线路相似，不足以成为动作类别。若换人或换墙后分组失效，先调整表示与样本，不能用漂亮的聚类图当验证结果。

命名规则：

1. 已与专业定义吻合的类别，采用“通俗描述／专业中文名（英文名）”，记录术语来源和别名。
2. 只发现稳定运动模式、尚无可靠专业对应的，采用描述性名称，状态为“待核对模式”；不编造专业术语。
3. 上穿/下穿、左/右侧等差异先作为类别属性；只有定义、样本和识别评价支持时，才拆成独立子类。
4. 同一技术因身高、柔韧性、机位不同而呈现的差异，先保留为变式，不默认新增动作类别。

可用于设计命名的例子如下，均不是对本次未读取素材的判断：

| 通俗展示描述 | 专业名称候选 | 需要核对的区别 |
| --- | --- | --- |
| 手从另一只手上方或下方穿过去 | 交叉手／Cross-through | 连续路径、移动手与留手关系；单帧双手重叠不足 |
| 把脚送到较高脚点 | 高抬脚／High step | 明确高度参照与脚点，区分抬脚、触达和后续身体转移 |
| 膝内转向下并配合转髋 | 沉膝／埃及式／Drop knee | 脚部接触、膝和骨盆组合；侧身或单个膝角不足 |

命名依据沿用现有知识单元 [KB-HAND-004](bouldering-knowledge/units/KB-HAND-004.json)、[KB-FOOT-006](bouldering-knowledge/units/KB-FOOT-006.json)、[KB-BODY-004](bouldering-knowledge/units/KB-BODY-004.json)，这些条目仍待专业和真实视频验证。Back step 与 Drop knee 的定义区别可核对 [REI 原教学页](https://www.rei.com/learn/expert-advice/climbing-techniques.html)；交叉手与高抬脚来源见知识库的 [sources.json](bouldering-knowledge/sources.json)。

## 4. 类别不是互相排斥的一张清单

| 层次 | 例子 | 标注方式 |
| --- | --- | --- |
| 基础运动事件 | 左手移动、右脚抬起、躯干转动 | 标记肢体和时间范围，不自动推断技术或接触 |
| 肢体关系 | 双手同点、换手、手脚动作重叠 | 有关系证据才标记；同点需要点位和接触资料 |
| 技术动作 | 交叉手、高抬脚、沉膝等 | 满足该类完整判定条件后标记 |
| 动作组合 | 某技术伴随出手，随后移脚 | 关联已有事件，先不新增组合类别 |

例如，一个片段可以同时包含右脚移动、身体转向和左手交叉。时间轴允许标签重叠，保留事件之间的先后与包含关系。技术无法确定时仍能输出证据充分的基础事件；无法定位边界时保留边界不确定范围。

## 5. 本批视频怎样预处理

| 素材问题 | 处理方法 | 可用范围 |
| --- | --- | --- |
| 墙面不完整 | 按动作需要核对局部肢体、目标点及连续过程；记录出画范围 | 局部证据充分的动作仍可使用；缺失部分记未知 |
| 难度较高 | 根据动作是否清楚、样本是否足够决定，不按难度直接丢弃 | 可留作进阶类候选或复杂场景测试 |
| 已剪辑 | 检查突变并在剪切点断开片段；保留原始时间引用 | 连续片段可用，不能跨剪切推断动作或接触顺序 |
| 已加速、倍率已知 | 保存文件时间到原时间的映射；变速分段记录 | 验证映射后才用于原速时序分析 |
| 已加速、倍率未知 | 保留“速度未知”；不猜倍率或补造原帧 | 可辅助部分外形/轨迹样本；动态速度与原速统计不采用 |
| 遮挡、模糊、多人干扰 | 记录受影响部位与时段、人员跟踪歧义 | 作缺证据/拒识测试，或仅采用未受影响事件 |

同一原片的多个剪辑、重复上传及增广版本必须有共同来源组；不能分别混入训练和测试。原文件保留不覆盖，所有候选片段、缩略图和标注作为派生产物保存。未经指定不扫描私人目录，不上传素材。

## 6. 每张动作类别卡需要什么

- 稳定类别 ID、定义版本、通俗名、专业名/别名与来源；描述性模式要明确状态。
- 起始条件、过程特征、结束条件；必要可见部位、不能推断的内容。
- 多个代表正例，以及最容易混淆的反例；按人员、墙面、机位记录覆盖。
- 左右侧、路径、幅度等属性；成立技术标签与仅成立基础事件的区别。
- 标注分歧、未知理由、复核记录；错误样本必须可追溯到原片。
- 样本及标注版本、关联知识单元、对应识别器版本和未见素材评价结果。

真实媒体引用保存在本地样本索引，不把私人路径、人员身份或视频塞进公共知识条目。已有构造例不能改称真实视频证据。类别合并、拆分时保留旧 ID 的迁移记录，避免历史视频随词典变化无声改名。

## 7. 新视频的预期输出

输入连续新视频后，系统完成质量检查、候选动作定位、多标签识别与结果整理。每项输出包括原片起止时间、参与肢体、通俗名/专业名、识别状态、证据片段，以及可查看的相似已核样本。

识别状态区分“已达到该版本自动标记条件”“候选待确认”“不匹配已收录类别”“证据不足”。其中“不匹配”只是当前识别器拒绝已知类的结果，可能是新动作，也可能是已知动作的变式或识别失败，不能直接宣布发现新技术。素材质量不足与类别不匹配不是同一个状态。不能强迫所有片段匹配现有类别，也不把相似度分数直接展示成准确概率。

目标是输入后自动完成识别。是否达到实时处理，需要在用户电脑上实测视频时长、分辨率、处理时间与资源占用后再定，现阶段不承诺零等待。骨架、样本特征与识别结果按内容和版本缓存，避免重复处理。

保留现有视频复盘布局、原时间统计及 0.75 倍播放/导出约定。新增识别结果接入动作时间轴和详情，沿用可折叠确认入口；不将分析说明烧录进视频，不改照片流程。

## 8. 单人实施阶段

| 阶段 | 工作 | 交付物与退出条件 |
| --- | --- | --- |
| 0：素材审计与小批探索 | 从不同人员/墙面抽取约 10–20 段原视频作先导；检查剪辑、速度、可见性和重复来源 | 素材清单、问题分类、代表片段；明确可用证据和素材分布 |
| 1：动作发现和命名协议 | 提出候选窗口、对比相似组与反例，选首批类别；固定边界、必要证据和别名 | 4–6 张候选类别卡及已核样例；人工能解释组间区别，分歧保留 |
| 2：标注与可检索样本库 | 建立正例/易混反例索引，修正片段边界，按来源/人员/墙面分组，冻结测试集 | 样本浏览与人工核对流程；真实样本可追溯，训练测试无来源泄漏 |
| 3：首版新视频识别 | 复用现有候选分段，比较轨迹规则与样本检索基线；需要时再加入预训练视频特征和小分类器 | 未裁剪新视频自动输出类别与时间；按类报告误判、漏检、边界误差和拒识 |
| 4：细粒度个人复盘 | 接入时间轴、回放、重叠标签、用户纠正与新样本待审队列 | 可以逐项核对一个人的动作；纠正不会未经审核自动成为训练真值 |
| 5：补难例并扩大覆盖 | 按实测混淆补样本；针对明确失败原因新增特征、子类或训练 | 新版本在冻结测试和新增独立测试上评价；达到可用条件后再增加类别 |

配套实施计划提供集中工作量粗估，素材审计后再修订，不能视为完成日期承诺。前两阶段可由当前开发者做探索标注并明确“单人核对”；专业命名有分歧时寻求针对性复核，不把开发者自查写成独立专业验收。

技术选择由基线失败决定：几何规则适合解释清楚的模式，样本检索便于小规模核对，视频特征可补充外观信息；不会先默认从零训练大型模型。可参考 [MMAction2 官方项目](https://github.com/open-mmlab/mmaction2)提供的动作识别、时间定位、骨架识别和视频检索能力，但现成工具不意味着已具备攀岩类别或本项目准确率。

## 9. 如何判断系统确实学会了

评价对象必须包含整段未裁剪视频，不能只评价已人工切好的正确片段。测试保留普通移动、易混动作、未收录动作和缺证据片段，防止只在典型正例上得出好成绩。

按类别记录精确率、召回率和混淆；同时记录时间边界误差、重叠事件漏检、误报/分钟、未知与缺证据拒识表现。明确哪些画面条件被支持，并同时披露可识别覆盖率，避免用全部拒识获得虚高精确率。

精确率以正确匹配预测数除以该状态的预测数，召回率以正确匹配参考数除以可判定参考数；候选与正式确认分别统计。零输出时精确率为空，有正例时召回率为零。还须报告“全部参考机会中有多少能判定”和全范围正确覆盖，避免通过排除难例提高成绩。边界不确定项不强行造单点真值，按冻结协议单列；每个事件最多匹配一次，重复预测计额外误报。未标注片段先核对，不能自动充当负例。

同一来源组严格隔离。依数据量分别安排未见人员、未见墙面/线路与未见机位的测试；某种条件样本不足就报告该条件未知，不用同片切片代替。测试集不用于选择阈值；调参使用训练/验证部分，修改后版本单独记录。

阶段 1 后按类别定义容许边界误差及上线门槛，不先套用统一置信阈值。探索性小样本成绩只能用于开发；面向比赛披露样本数、分组方式、失败例和标注来源。

## 10. 可积累的技术价值

可积累的是攀岩动作的可见证据协议、带易混反例的授权样本、连续视频定位和多标签识别方法，以及纠正到再评价的闭环。通用姿态模型和专业名称本身不足以构成壁垒；也不能保证他人无法复刻。

下一步在用户指定素材目录后先做阶段 0，输出素材审计和首批动作候选，再决定真实类别。当前没有分析过这批素材，因此没有已发现的新动作、训练结果或识别准确率可报告。

## 11. 首版范围与暂缓事项

| 项目 | 首版约定 | 超出条件时 |
| --- | --- | --- |
| 输入 | 用户指定的本地素材；固定机位，单个目标攀岩者；保留连续原片 | 多人身份不明、镜头移动等进入问题清单，暂不承诺自动完成 |
| 动作覆盖 | 建议 4–6 类，先验证其中证据最充分的少数类 | 类别不足就减少数量，不用样本稀缺类凑数 |
| 推理方式 | 上传后异步自动处理，先建立本地离线基线 | 实时、生产服务器资源和云端处理另行实测；不默认新增付费调用 |
| 分析内容 | 动作时间、肢体、类别、属性、可见关系和重复发生 | 不从动作名称推断省力、错误原因、真实受力或能力短板 |
| 用户体验 | 复用现有复盘页和折叠修正；研究样本核对以本地工具先行 | 不先建独立数据平台或复杂标注系统 |

首版暂缓：任意机位、任意动作全覆盖、从零训练大型模型、自动评动作优劣、训练处方、跨次比较和实时反馈。少类别识别完成后才能评价扩大范围的成本。

## 12. 补全后的功能需求

| 编号 | 需求 | 验收要点 |
| --- | --- | --- |
| FR-01 | 素材登记、问题审计与重复来源分组 | 原片可追溯；问题按时间段记录；重复和剪辑不能跨数据分组 |
| FR-02 | 统一时间与可见性记录 | 文件播放时间、原速时间分开；未知倍率及变帧率不伪造时间 |
| FR-03 | 候选窗口与动作事件分离 | 允许一个回看片段含多个重叠事件；漏掉的事件可人工补标 |
| FR-04 | 相似样本检索及候选分组 | 可查看同组和跨组样本、最易混反例；不能自动把聚类当真值 |
| FR-05 | 类别定义与双层命名 | 通俗名称和专业名称分栏；专业名有来源；待核模式不冒充技术 |
| FR-06 | 人工标注、边界区间及分歧 | 可记录多标签、左右侧、未知条件；不强迫单一标签和精确边界 |
| FR-07 | 本地样本索引与知识关联 | 样本、类别、知识、定义版本分开引用；可按类别与质量检索 |
| FR-08 | 数据分组与冻结评测清单 | 来源隔离，正式验收按既有人员/线路连通分组；清单与版本可核对 |
| FR-09 | 新视频完整分段与识别 | 在未裁剪视频输出事件；拒识、缺证据和失败有明确原因 |
| FR-10 | 基础描述与技术候选分离 | 骨架移动不自动升级为接触或专业技术；确认状态明确 |
| FR-11 | 结果证据与相似样本回看 | 定位到当前原片；参考样本仅辅助说明，不替代当前证据 |
| FR-12 | 时间轴与多事件详情 | 主展示保持肢体、简短名、原片时间；重叠标签放入折叠详情 |
| FR-13 | 修正、撤销与待审样本 | 可修类别、侧别和时间；保留模型原输出，修正不自动成为训练真值 |
| FR-14 | 分阶段评价与自动命名准入 | 按类和画面条件报告；探索验证不降低已有正式放行门槛 |
| FR-15 | 任务、缓存和版本失效 | 可重试/取消；仅同素材与同配置复用；陈旧任务不能覆盖新结果 |
| FR-16 | 样本、模型和类别升级回退 | 类别合并拆分可迁移；保留旧结果；支持回退模型版本 |

## 13. 类别准入与标注协议

类别先经历“发现候选 → 定义可执行 → 样本已核 → 识别器开发中 → 探索验证 → 正式验收”。类别存在、名称有依据和机器可自动确认是三个独立条件。

进入首批开发的类别必须同时满足：定义能说明与最易混类别的区别；必要画面信息在现有素材中实际可见；有多个独立来源的正例和易混反例；边界规则能执行；名称与来源不存在未解决的关键冲突。无法满足时保留待核类别，或仅使用基础运动描述。

先导标注工作量建议每类收集 15–30 个完整正例、15–30 个易混反例，争取至少 5 个不同来源组。这是探索目标，不是独立样本量推导，也不是正式自动命名的准入数量；若都来自同一人同一路线，其泛化证据仍不足。

标注者先看连续原片并记录事件，再看模型候选，避免候选窗口限制参考答案。对整段试标素材也要检查窗口之外的动作。只有一名标注者时，隔一段时间隐藏旧标签复标一部分，记录自身分歧；这不等于两人独立审核。

边界至少保存三个范围：带上下文的回看窗口、动作本身的起止范围、边界不确定区间。基础移动以可观测的肢体相对运动为依据；技术以各类别规定的进入/退出条件为依据。短暂停顿是否拆开、同点调整是否单列由类别规则决定，不能套用一个阈值处理所有动作。

左右侧按人的解剖侧标注；镜像显示不翻转语义侧别。遮挡、出画、身份交换与剪切处断开证据连续性；不能把轨迹插值当实际观测。原片已有加速时，统计默认标明“文件时间”，未知原速时不显示“原速动作耗时”。

## 14. 最小数据合同与纠错闭环

以下是离线研发合同草案，不是本轮新建业务数据库或修改现有知识 schema。

| 对象 | 必备字段组 |
| --- | --- |
| 素材 | 匿名素材 ID、内容摘要、共同来源组、人员/线路/机位分组、授权记录引用及允许用途、时长、真实帧时间、速度/剪辑状态 |
| 标注事件 | 事件 ID、素材引用、类别与定义版本、基础/关系/技术层级、肢体、侧别、起止与不确定范围、必要条件逐项状态、证据帧引用、标注者及复核记录 |
| 类别卡 | 类别 ID、定义版本、名称与来源、必要证据、易混区别、变式、正反例引用、知识单元引用、开发及审核状态 |
| 数据划分 | 清单版本、素材摘要、来源与连通组、训练/验证/冻结测试用途；排除项及理由 |
| 识别结果 | 原始预测、事件时间、候选类别/分数、缺证据或拒识原因、特征/分段/分类/词典版本、运行配置、原片证据 |
| 用户纠正 | 原结果版本、修改前后值、原因、操作者、时间、撤销关系、进入待审队列的状态 |
| 运行报告 | 软硬件和输入规格、耗时、资源峰值、任务状态、模型原输出指标、修正后结果另列、支持条件与失败例 |

识别状态、证据状态和人工确认状态分栏。用户确认一个片段，不表示该类别全局准入；匹配到一个典型样本，也不表示当前必要接触已经成立。纠正流程为“修改个人结果 → 可撤销记录 → 待审样本 → 核对定义/分组/授权 → 纳入下一版研发集 → 重新评价”。已进入冻结测试的片段，不能因用户纠正而混入同轮训练；用于开发后必须退役为开发材料，另补新测试。

标签缺失不自动当负例。只有实际核对不存在该类或明确属于易混情况，才能做该类负例；一个类的正例可能同时也是另一个类的正例。增广不得改掉动作语义，镜像时同步处理侧别；邻近帧和增广不重复计独立事件。

## 15. 自动确认、展示和正式验收边界

首版默认机器输出基础描述及技术候选，沿用现有命名模块 `automatic_confirmation=false`。新识别器不能绕过这项条件，也不能用“已识别”替代尚未完成的确认。

正式自动命名沿用[细化动作独立验收说明](AI攀岩复盘_细化动作独立验收说明_2026-09-30.md)：两位独立审核者，人员/线路连通组不跨开发与留出，每类至少 60 个真实正例、60 个易混/负例和 20 个独立组，以及其中冻结的正确率、召回率、专业标签区间和零缺依据放行门槛。当前没有这些材料和审核结果；探索阶段先推进，不伪造完成。

既有标准匹配还涉及动作代码、肢体、起终点身份、时间交并比及边界容差。新增类别无法直接映射时，先注册离线类别并制定匹配协议；不能硬塞到近似代码里取得通过。重叠事件和拒识需要补充评价，不能把旧评估工具的数值当全部需求已验收。未来修改正式标准必须有明确理由和新的冻结版本，不能看完成绩后降低门槛。

类别样本不足时可以交付标明限制的候选识别演示，但不能交付宣称准确率已达标的自动确认功能。页面默认不展示相似度百分比；详情明确“候选/本人确认/证据不足”，研究版保留分数及其定义。

## 16. 必须验证的假设与失败处理

| 假设 | 怎样验证 | 未成立时的处理 |
| --- | --- | --- |
| 素材够支撑首批类别 | 统计独立来源、正反例、关键可见部位和速度状态 | 减少类别或保留待核，不能用重复帧补数量 |
| 类别规则可重复执行 | 原片试标、隐藏旧标签复标或独立复核 | 合并难区分类，补充规则或降为描述标签 |
| 现有窗口能覆盖目标动作 | 在整段人工参考上检查漏检、合并和截断 | 保留用户既定回看分组，另补内部事件定位 |
| 骨架/轨迹能分清目标类别 | 与易混反例对照，并在未见组上检查 | 增加局部图像证据、换表示或暂缓该技术 |
| 拒识不会使系统几乎不输出 | 同时报告精确率、召回率、覆盖和拒识原因 | 调整方法与适用范围，不只提高阈值美化成绩 |
| 本机处理成本可接受 | 小批实测端到端耗时、内存/显存、失败重试 | 缓存、减少重复提取、缩小首版处理量 |

训练、测试和类别发现使用的数据范围必须登记。冻结测试不参与选类别、聚类展示、阈值选择或失败调参；留出结果一旦用于改进，该轮仅作为历史测试，新版本需要补新的独立材料。竞赛结论限于实际支持的类别、机位与人群条件。
