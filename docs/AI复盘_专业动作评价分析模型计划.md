# AI 复盘专业动作评价分析模型计划（用户确认修订版）

更新：2026-10-08。本文记录用户授权的建设目标；工程实现、真实素材实验及未完成验收见 [本轮实施与验收记录](AI复盘_专业动作评价_实施与验收_2026-10-08.md)。工程测试通过不代表专业识别或评语准确性通过。

## 一、目标与已确定的产品方向

对每个有证据的动作给出清楚、准确的评语，最后指出本次攀爬最应该调整的一项。

完整流程：上传并保留原片 → 识别与人工确认岩点 → 本地骨架分析 → 整理动作与运动特征 → 视觉大模型生成逐动作评语 → 汇总首要调整重点。

| 项目 | 用户确认方案 |
|---|---|
| 原片保存 | 取消“处理后删除”，本地保留原片，支持用户主动删除 |
| 常见竖屏规格 | 720×1280，保持比例；横屏对应 1280×720 |
| 基础骨架采样 | 10 FPS，4 FPS 作为对照 |
| 重点片段采样 | 比较 15／20 FPS，最高不超过原片有效帧率 |
| 本地处理目标 | 当前电脑，30 秒视频尽量在 3 分钟内生成复盘 |
| 首批专业动作 | 高抬脚 HIGH_STEP、交叉手 CROSS，分别验证后扩展 |
| 评语服务 | 替换百炼，接入可配置的视觉大模型 API |
| 单次评语预算 | 默认上限 1 元，可调整，计入本次重试 |
| 人工验证 | 用户先试标；正式专业结论再进行独立复核 |

3 分钟从确认岩点后点击“开始本地分析”计时，包含骨架、配准、特征和视频生成；人工补点与外部 API 等待分别统计。原片、旧分析与旧媒体保留，新结果另存并绑定版本。生产部署另行安排。

## 二、视频清晰度与骨架采样

### 2.1 分辨率与原片保留

- 原片保持上传字节、方向、帧率和时间信息；常见竖屏分析／观看副本以 720×1280 为基准。
- 其他比例等比适配，不拉伸、不裁掉四肢；低清素材不通过放大冒充新增细节。更高清原片用于按需局部取帧。
- 保持左真人与骨架、右线路动作图、底部动作顺序；720×1280 指真人素材基准，最终合成画布按既有布局确定。
- 去除自动删除选项、倒计时及后台删除路径；旧待清理任务恢复后也不得删除原片。用户主动删除仍可用。
- 清晰度同时检查尺寸和压缩损失。岩点比较同帧漏点、误点、小脚点及轮廓，不能只由分辨率推定效果提升。

### 2.2 骨架采样方案

| 档位 | 用途 | 30 秒计划样本量 |
|---|---|---:|
| 4 FPS | 对照基线 | 约 120 |
| 10 FPS | 整段基础分析 | 约 300 |
| 15 FPS | 重点片段第一组实验 | 全段等效约 450 |
| 20 FPS | 重点片段第二组实验 | 全段等效约 600 |

首版采用整段 10 FPS，重点窗口补充真实样本。15／20 FPS 使用同一人工标注窗口配对比较，选择达到准确性要求且处理量较小的档位；都没有改善时保留 10 FPS 并检查其他原因。

重点片段来自已观测动作速度线索与用户指定窗口。画面运动发现方法另行验证；仅靠低频骨架不能发现已经漏过的短动作。

加密复用同源、同模型及相同人物选择条件的已有样本，仅补充缺少的真实帧。记录原始帧号、实际时间和最大间隔。显示平滑、插帧、慢放不计作新增证据；遮挡、模糊、左右交换不能靠加密自动变可信。

30 FPS 原片采到平均 20 FPS，最大间隔仍可能约 0.067 秒，不能宣称每个间隔小于 0.05 秒。必要窗口可查看原生逐帧画面。

### 2.3 清晰度与采样的分工

岩点利用空间细节，提高骨架采样不自动增加岩点识别取帧次数，两者分别配置、验收。RTMW-L 人物输入仍是 384×288；视频清晰度帮助人物裁剪与局部复核，采样密度帮助短动作覆盖、轨迹和边界，单帧定位仍需独立检查。

保持现有骨架模型，优先验证清晰度、人物选择和真实采样密度，暂不以前置换模型解决问题。

### 2.4 本地资源控制

逐帧读取、限量缓存，沿用重任务串行与模型缓存释放。分别计量找人、骨架、配准、特征、渲染及总耗时；支持进度、取消与失败恢复。失败保留原片及上一版复盘，不能静默降低清晰度或减少采样。

例如 30 秒基础 10 FPS，其中 6 秒补到 20 FPS，约 360 个样本，低于全段 20 FPS 的 600 个。样本量不等于耗时预测；不同采样网格的并集以实际去重帧数为准。

## 三、动作定义、特征与专业识别范围

### 3.1 动作单元

| 层级 | 内容 |
|---|---|
| 基础事件 | 伸手、抬脚、回收、同点调整、身体移动、可见接触变化 |
| 协同片段 | 多个肢体与躯干共同完成的一段过程 |
| 专业动作 | 连续证据满足定义的技术类别 |

允许多事件、多技术标签、未知目标岩点、未成功够点、没有换点的身体调整；不能为了凑齐序列虚构接触与离开。

### 3.2 特征与数据结构

复用 17 点身体骨架与 RTMW 保存的 133 点证据；手脚细节先检查可用性。动作数据包含：

- 参与肢体、阶段、关联事件及岩点身份；
- 原片摘要、播放副本时间映射、模型／岩点修订／规则版本；
- 二维角度、位移、速度、停顿、回收的时间序列；
- 坐标系、单位、归一化尺度和有效观测比例；
- 证据帧、缺失、遮挡、配准失败、左右身份冲突；
- 技术必要条件、内部判断状态及人工审核记录。

未知值为空；模型分数、证据质量和人工确认分开保存。接近岩点不能记作承重支撑。关节角度明确是二维投影；墙面配准轨迹与原图角度分开，不解释为真实三维几何。

### 3.3 专业动作阶段

第一批仅验证高抬脚、交叉手，每类固定动作定义、起止边界、必要证据、典型正例、易混反例及不可判定条件。

随后扩展旗式、转髋、沉膝、ROCK_OVER；动态够点、BUMP、勾脚跟、勾脚尖、MANTLE、DYNO 为后续阶段。

候选及审核状态内部保存；类别通过独立验证且当前证据满足条件，用户端才使用确定专业名称。二维肩髋图形转向不能直接确认专业转髋；普通视频不能可靠测量真实重心、受力、承重比例或诊断伤病。

## 四、视觉 API 与用户评语

### 4.1 通用接口及费用

当前入口退出百炼，历史结果保留，不迁移为新模型结论。首版采用可配置 OpenAI 兼容图文接口：服务地址、模型、密钥、人民币计费参数、单次预算。

密钥保存在服务端／本机受保护存储，不进入前端结果和普通日志。输入为动作结构及必要的前中后、局部证据，不逐视频帧调用、不默认上传整段原片。

输出包含动作 ID、评语、引用证据和整次首要重点。本地检查身份、引用、时间及数据一致性；结构检查不替代真实语义验收。

默认总预算 1 元，含重试。供应商、价格和图片计费规则明确后才验证预算；价格未知时不启动真实付费分析。更换模型或版本重新验收。用户单独授权发送证据，不与本地骨架混在一起；失败或预算不足保留已有本地复盘和评语，不回退百炼。

### 4.2 逐动作评语

主展示为肢体、动作、原片时间与简短评语；候选、分数及技术字段内部控制。

有证据时直接描述能够成立的动作和评价；证据不足只描述确定部分。停顿、路径长、调整多不自动是缺点；不凭外形推断力量不足、踩实、抓稳或真实受力。逐动作与最终总结保持一致。

例如只支持运动过程时：“右脚抬高后，身体向右上移动，随后左手继续够点。”只有证据及已审核规则都满足，才进一步评价哪里做得好、哪里影响衔接。

### 4.3 结尾首要重点

选择证据充分、重复出现、有明确改善依据的一项，说明“哪个动作 → 调整什么 → 判断依据 → 下次如何验证”。依据不足时不强行造缺点或训练处方，改为最值得回看的动作及已确认现象。

建议沿用知识来源与审核机制；模型更换不继承旧验收，不放行未审核建议。页面只显示一次：“AI 评语基于视频中的可见信息，可能存在识别偏差，请结合原片核对。”

保持动作说明位置与结束总结行为；长评语不烧录进视频，不增加常驻字幕侧栏。

## 五、数据验证、交付顺序与验收

### 5.1 参考数据

现有 10 条用于开发、用户试标、失败回归，保留漏检、重复候选与遮挡案例。用户先标基础事件、时间边界、岩点身份、首批两类动作，记录未知与分歧；个人修正不计机器成绩或独立专业验收。

正式验证另选未见素材，两名审核者独立标注并解决分歧。同原片剪辑、相关攀爬者和线路分组不得跨开发／留出集。

### 5.2 验收指标

| 层级 | 内容 |
|---|---|
| 视频与岩点 | 清晰度、比例、原片完整、小脚点、漏点／误点、轮廓 |
| 骨架与动作 | 定位误差、左右交换、短动作漏检、边界、有效覆盖 |
| 专业技术 | 分类别精确率、召回、易混错误、误报／分钟、覆盖率 |
| 评语与总结 | 事实、证据对应、评价适用、首要重点合理、用户易懂 |
| 性能与成本 | 耗时、峰值内存、磁盘、API 用量、实际费用 |
| 生命周期 | 取消、重启、旧清理任务、原片保留、失败恢复 |

提帧使用同片、同岩点、同参考标注，检查时间平滑、连续帧及速度规则，避免加密把短暂抖动识别为动作。

正式门槛：每类至少 60 个真实正例、60 个易混／负例、20 个独立分组；确定命名正确率至少 95%，基础可判定召回至少 85%，专业标签 95% 区间下界至少 90%，无依据放行为零。最低分组数不保证区间门槛同时通过。样本不足只输出有证据描述，不宣称专业识别达标。

评语单独验收；骨架或技术成绩不能替代评语验收，零输出不算高准确率，免责声明不能替代事实检查。

### 5.3 实施顺序

1. 素材盘点、用户试标、固定首批定义与比较协议。
2. 原片保留、720×1280 副本、原片局部取帧。
3. 比较 4／10 FPS，再验证重点片段 15／20 FPS。
4. 动作事件、协同片段、特征、首批两类研究规则。
5. 通用视觉 API、逐动作评语、预算和失败恢复。
6. 结尾首要重点、独立留出验收，再扩展专业类别。

采用用户指定最新本地工作树。工程建设可先行，用户试标、供应商配置与独立专业验收未完成时不自动宣告上述阶段验收通过。
