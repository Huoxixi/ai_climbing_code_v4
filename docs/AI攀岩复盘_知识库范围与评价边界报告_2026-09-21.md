# AI 攀岩复盘知识库范围与评价边界报告

版本：v1.0
日期：2026-09-21
适用阶段：PRD 阶段一 / 发布阶段 A，兼顾阶段 B 的知识准备
对应产品：本地 AI 攀岩复盘

## 1. 报告目的

本报告先定义 AI 复盘知识库需要覆盖的知识、允许形成的评价、必须保留的证据以及不得越过的边界，再据此检索文献。知识库的首要目标是帮助使用者改进动作，而不是展示一组分析指标。AI 应根据人工确认后的动作事件和可复核指标，定位一个具体动作环节，生成少量、直接、能够在下一次尝试中执行并回到视频时间点复查的建议。

知识库服务于“动作定位—问题解释—调整建议—再次验证”的改进闭环，不替代岩点识别、姿态估计和接触检测，也不把未经确认的模型结果包装成技术结论。现有 PRD 中的单次复盘指标、可解释摘要、历史比较和风险观察边界继续有效，但指标只承担证据作用，不能成为复盘页面的主角。

动作定位采用统一命名体系；详细定义见：[AI 攀岩复盘动作命名体系与标签词典](./AI攀岩复盘_动作命名体系与标签词典_2026-09-21.md)和[攀岩动作中文总表](./AI攀岩复盘_攀岩动作中文总表_2026-09-21.md)。现有“左手、右手、左脚、右脚”主标签保留，每个经确认动作在旁边增加中文基础名称，专业技术名称作为可修正标签附加。

## 2. 产品问题与评价对象

### 2.1 产品需要回答的问题

第一版只回答四个问题：

1. 最值得改进的是哪一个具体动作或动作衔接？
2. 视频中出现了什么可以复查的动作现象？
3. 用户下一次应尝试哪一个明确、低风险的调整？
4. 再次尝试后，怎样判断这项调整是否带来了改善？

第一版不回答“用户是什么水平”“动作是否符合唯一标准”“为什么失败”“是否会受伤”等超出当前证据的问题。产品评价的是特定线路、特定动作和特定尝试，不给使用者贴能力标签。

### 2.2 评价对象

AI 的直接输入必须是本次尝试中已经人工确认或明确标注为候选的数据：

- 原视频及可跳转的证据时间点；
- 线路岩点及其轮廓；
- 左手、右手、左脚、右脚的接触开始、结束与顺序；
- 尝试开始、结束和完攀状态；
- 从上述事件计算出的动作数、接触时长、动作间隔和停顿；
- 带置信度的二维姿态与图像域轨迹代理量；
- 用户主动填写的主观反馈。

未经人工确认的接触候选可以用于提示用户检查，不能直接成为确定性建议。低置信姿态、严重遮挡和不可比机位必须降低输出强度或停止评价。

## 3. 知识库所需知识范围

### 3.1 观察与术语知识

用于把确认后的事件转换为中性、稳定的描述，包括：

- 上点、离点、换手、匹配、重复触碰和脚点调整；
- 动作间隔、静止区间、最长停顿和连续动作段；
- 左右肢体使用比例和接触时长差异；
- 身体中点的图像域移动、横向摆幅和垂直进展；
- 二维关节角变化及其可见性限制。

这类知识只描述“发生了什么”，不自动判断好坏。

所有术语必须映射到稳定动作代码、起止时间、肢体和目标岩点。时间线、复盘建议和历史比较使用同一个动作编号，避免同一动作在不同页面被重复命名。

### 3.2 动作分析与改进知识

用于把观察转化为可以尝试的动作提示。知识不按“力量、协调、技术好坏”等抽象能力分类，而按一次动作的阶段组织：

1. **准备**：移动前是否已经形成明确的目标岩点和可执行顺序；
2. **支撑建立**：出手或抬脚前，相关手脚是否已有可见、已确认的接触；
3. **动作发起**：从静止到移动时，先发生了哪个肢体事件，是否出现反复启动；
4. **移动过程**：是否出现重复触碰、临时换点、明显中断或同一段的异常绕行；
5. **接触完成**：触点建立后是否很快离点、重新抓踩或继续调整；
6. **稳定与衔接**：完成一个动作后，是否能够进入下一动作，还是重新进入较长停顿或探索。

这六个阶段形成首版动作分析骨架。系统应优先指出“第几个动作、哪个阶段、出现了什么现象”，再给出一个调整；不能只说“节奏不好”“动作不流畅”或“协调性不足”。

“重心转移”“髋部靠墙”“直臂节省体力”等常见教练语言不能直接写入产品知识库。只有在定义了可观察代理量、适用条件、反例和来源后，才能改写成证据强度相称的建议。

### 3.3 首版动作问题分类

第一版优先识别以下可观察问题。这里的“问题”表示值得下一次验证的动作现象，不表示用户能力缺陷：

| 动作问题 | 视频证据 | 建议方向 | 下次验证方式 |
|---|---|---|---|
| 目标点或顺序准备不足候选 | 动作前长停顿，随后出现多次目标点尝试 | 攀爬前先确认该段一个目标点或两步顺序 | 同一位置的停顿或试探是否减少 |
| 接触不稳定候选 | 接触后短时间离点并再次接触，且事件经人工确认 | 下一次先确认抓踩位置，再进入后续动作 | 同一岩点的重复接触是否减少 |
| 手脚衔接中断候选 | 相邻手脚动作之间出现明显中断或反复启动 | 只练习这一段的动作衔接，不要求整条一次完成 | 中断是否减少，动作顺序是否更稳定 |
| 匹配或换手成本较高候选 | 匹配前后出现多次调整或较长停顿 | 预先确定换手后的下一目标，单独复现这一段 | 匹配后的下一动作是否更快进入 |
| 动作完成后未稳定候选 | 新接触建立后很快离点、反复调整或回到原点 | 下一次把目标设为“建立接触后先稳定，再继续” | 接触保持时间和后续衔接是否改善 |

每一类必须允许“这是探索、休息、线路要求或识别误差”的反例。知识库只提供可验证假设，不能把候选问题写成确定原因。

### 3.4 指标解释知识

知识库需要说明每个指标能表达什么、不能表达什么：

- 动作数减少可能代表路线熟悉或策略变化，不必然代表技术提高；
- 停顿可能是读线、恢复或犹豫，不能一律判为问题；
- 更快不等于更好，必须同时查看动作数、重复触碰、失控候选和主观反馈；
- 二维身体中点不是三维人体重心；
- 二维关节角不是三维关节角、关节负荷或肌肉力量；
- 左右差异可能来自线路结构，不能自动解释为身体失衡。

### 3.5 个体与情境知识

建议必须受到以下上下文约束：

- 同一用户、同一线路和相似机位；
- 攀爬阶段和当时可见的目标岩点；
- 用户填写的疲劳、RPE、疼痛或不适；
- 关键帧置信度、遮挡和出画情况；
- 当前记录是否经过用户确认或教练复核。

个体历史只能用于个体内比较。不同用户、不同线路和不可比机位之间，不生成优劣排名。

### 3.6 表达与交互知识

首版建议采用固定结构：

> 具体动作 → 可观察事实 → 一项下一次可执行的调整 → 下次验证指标 → 证据时间点

每次复盘最多给出三条建议。每条只处理一个问题，正文优先控制为一至两句；不使用综合分、人格化评价、夸张结论和教练权威口吻。建议必须能跳转到动作开始帧，用户可以标记“不准确”“不适用”或隐藏。

示例：

> 第 10 个动作前停顿较长，并出现两次右手试探。下一次先确认右手目标点，再启动这一步；复攀时看这段试探是否减少。查看 6.5 秒。

该例是产品表达模板，不代表“停顿较长”的阈值已经得到研究验证；阈值必须通过本项目数据和文献另行确定。

## 4. 评价边界

### 4.1 当前允许输出

- 经人工确认的事件事实；
- 对事实的中性解释，并同时给出可能的其他解释；
- 与一个具体动作或时间段绑定的低风险尝试建议；
- 同用户、同线路、相似机位下的描述性变化；
- 数据不足、画面不可见或结论不适用的明确说明。

### 4.2 当前禁止输出

- 综合攀岩水平分、天赋判断或跨用户排名；
- “标准动作”“错误动作”等没有任务情境的绝对判断；
- 真实肌肉力量、抓握力、关节力矩、冲击力、能量消耗和三维重心；
- 伤病风险概率、医疗诊断、康复处方或安全认证；
- 从表情、外观或单段视频推断意图、心理状态、性格和疼痛；
- 仅凭一次更快或动作更少就宣称“已经进步”；
- 把低置信度插值或模型猜测描述为实测事实；
- 没有证据时间点、没有适用条件或无法说明来源的建议。

### 4.3 延后到研究阶段的内容

- 自动脚滑、失控摆动、坠落和碰撞评价；
- 高速动作中的极端关节角与安全提示；
- 基于多机位三维运动学、IMU、压力或力传感器的负荷分析；
- 针对伤病、训练恢复和体能周期的个性化处方。

这些内容只有在专项数据集、事件级验证、专业顾问复核和合规审查完成后，才可从人工标记或研究模式进入产品灰度。

## 5. 知识条目结构

知识库不采用无结构文档直接生成建议。每条知识至少包含：

| 字段 | 含义 |
|---|---|
| `knowledge_id` | 稳定编号 |
| `title` | 人类可读名称 |
| `knowledge_type` | 术语、观察规则、指标解释、建议、禁止项或安全边界 |
| `action_phase` | 准备、支撑建立、发起、移动、接触完成或稳定衔接 |
| `action_name_codes` | 适用的基础动作、动作关系和技术标签代码 |
| `observable_inputs` | 可使用的事件、指标和主观输入 |
| `trigger_condition` | 触发所需条件；未验证阈值必须标记为待研究 |
| `exclusions` | 不适用场景、反例和冲突条件 |
| `evidence_requirement` | 必须关联的动作、时间点、置信度和复核状态 |
| `allowed_claim` | 可以表达的最强结论 |
| `forbidden_claim` | 不得扩大的结论 |
| `suggestion_template` | 一条直接、可执行的建议模板 |
| `next_attempt_change` | 下一次尝试只需要改变的一个变量 |
| `verification_rule` | 同线路复攀时如何判断改善、无变化或证据不足 |
| `source_ids` | 文献、教练审核或产品规则来源 |
| `evidence_level` | 证据等级 |
| `review_status` | 草拟、文献核对、教练审核、验证通过或停用 |
| `version` | 条目版本和生效时间 |

同一条目应将“观察事实”“研究解释”和“产品建议”分开保存，避免 AI 把相关性改写成因果关系。

## 6. 证据等级与准入规则

建议采用五级证据：

1. **E1 本项目已验证证据**：授权样本、双人标注、仲裁和达到门槛的事件级评测。
2. **E2 攀岩专项同行评审研究**：对象、任务和指标与条目直接相关。
3. **E3 一般运动科学或姿态研究**：可用于方法和限制，不直接证明攀岩建议有效。
4. **E4 教练共识与结构化审核**：可形成候选建议，但必须记录适用条件并进入验证。
5. **E5 产品表达规则**：用于字数、排序、证据跳转和不确定性提示，不作为运动科学事实。

准入原则：观察定义至少需要 E2 或 E3 支持；具体建议优先需要 E2，并经过 E4 审核；自动触发阈值必须获得 E1。只有 E4 或大众内容支持的技巧可以进入候选区，不能直接自动发布。

## 7. AI 生成与校验边界

推荐采用“规则检索 + 受限生成 + 输出校验”，而不是让大模型读取全部资料后自由评价：

1. 从人工确认数据计算事实候选；
2. 只检索输入条件匹配的知识条目；
3. 按固定模板生成不超过三条建议；
4. 校验每条建议是否有证据时间点、来源、适用条件和允许措辞；
5. 删除重复、互相冲突或证据不足的建议；
6. 保存所用指标、知识条目版本和生成模型版本；
7. 用户可反馈“不准确”或“不适用”，但反馈不会自动改写知识条目。

任何时候，只要证据不足，系统应优先输出“这段画面不足以判断”，而不是补全一个听起来合理的原因。

## 9. 文献纳入与排除标准

优先纳入同行评审论文、系统综述、公开数据集论文、正式标准和权威机构资料。每条来源必须记录研究对象、任务、样本、测量方法、可支持主张和不能支持的外推。

以下材料不作为自动评价依据：

- 未提供方法和证据的博客、短视频、营销文案和匿名经验帖；
- 只研究一般健身动作、但没有说明如何迁移到攀岩的材料；
- 仅凭精英与新手横断面对比就给普通用户下因果建议的研究；
- 只验证三维、多机位或高帧率方法，却被用来支持当前单目 4 FPS 输出的研究；
- 无法确认版本、作者、发表渠道或原始来源的二手摘要。

教练教材和协会资料可以进入 E4 候选层，但不得冒充同行评审证据。

## 10. 第一版知识库范围

第一版建议只上线以下五类动作改进条目：

1. 动作前的目标点与顺序准备；
2. 手点、脚点的重复触碰和接触后调整；
3. 手脚动作衔接、反复启动和动作中断；
4. 换手、匹配后的稳定与下一动作进入；
5. 同一路线复攀时，上述动作问题是否减少。

左右使用、停顿时长和二维路径仍然计算，但它们降为辅助证据，不再单独构成建议。每类先建立动作阶段、视频证据、反例、调整方式和复攀验证方法，不急于设置自动好坏阈值。完成文献核对、教练审核和本项目样本验证后，再逐项从“只描述”升级为“可建议”。

## 11. 动作改进闭环

一次复盘只选择一个主要动作问题进入闭环：

1. 系统在动作序列中定位证据最清楚、最值得复查的一处；
2. 用户通过原视频和动作图确认系统描述是否成立；
3. 系统给出一条下一次可以执行的调整，不同时修改多个变量；
4. 用户在同一路线复攀时主动尝试该调整；
5. 系统比较同一动作的事件、停顿、重复接触和完成情况；
6. 结果标记为“改善、无明显变化、不适用或证据不足”。

产品所说的“帮助进步”，首先是帮助用户形成这一可重复的学习过程，而不是一次分析就宣布技术已经提高。

## 12. 验收标准

- 每条建议均能跳转到一个或多个证据时间点；
- 每个经确认动作都有唯一编号、基础名称和命名版本；
- 技术标签与基础动作名分层显示，低置信标签不得覆盖基础名称；
- 每条建议均能追溯到知识条目、来源和版本；
- 未确认事件、低置信画面和不适用场景不会触发确定性评价；
- 一次复盘最多三条建议，用户不需要阅读长篇说明即可执行；
- 首要建议必须指向一个具体动作和动作阶段，不能只展示统计指标；
- 建议必须包含下一次尝试的验证方式；
- 同一路线复攀后，可以对该动作标记改善、无变化、不适用或证据不足；
- 禁止项通过自动测试拦截；
- 用户可以反馈、隐藏或撤销建议；
- 知识条目更新不会静默改写历史复盘；
- 教练审核与本项目验证结果分别记录，不互相替代。

## 13. 当前结论

本项目需要的不是“攀岩百科”或“指标仪表盘”，而是一个围绕具体动作建立的改进知识库。接触、停顿、顺序和二维路径是定位动作问题的证据；真正面向用户的输出应说明“哪一个动作值得调整、下一次做什么、怎样判断有没有改善”。风险、医疗、真实受力和综合水平评价不进入当前版本。
