# 照片线路电子岩板：本地可编辑草稿

2026-09-03，分支 `codex/photo-route-extraction`。本阶段已接入独立照片线路页面与本地文件存储；未推送、部署或连接 Supabase。

## 已实现

- 浅木色无外框岩板：30 列 × 20 行、孔距 200 mm，左/右/上外沿 200 mm、下外沿 100 mm，总尺寸 6200 × 4100 mm。A–AD、1–20 编号可切换，600 个孔点只作参考，不吸附。
- 选定对象联合边界等比适配至 X=200–6000、Y=100–3900 mm，空余方向居中。原始纹理和相对比例保留；界面明确这是设计尺度而非原墙实测尺寸。
- 整线移动/缩放、单对象拖动/旋转/缩放、层级、多个起终点、撤销/重做与恢复初始适配。变换后的外接边界不能越出墙面。
- 电脑滚轮缩放、方向键微调；手机整板总览、浏览/编辑模式、双指缩放和平移。底部展示对象属性。
- 原图与净化背景按来源位置对照，电子岩板变换独立保存。原图、净化背景、透明抠图、蒙版均单独保留。
- 停止输入或结束拖动两秒自动保存，使用版本号保护并发更新。409 冲突和 423 编辑权失效保留待保存副本；同一浏览器刷新或重新进入可恢复。可下载冲突副本，显式放弃后再载入服务端最新版本。

## 接口与存储

独立 `PhotoBoardSpec`、`PhotoRouteDraft`、`PhotoRouteObject` 合同，不进入旧 `BoardAsset`、标准板、完整性判定或 AI 流程。

| 接口 | 用途 |
| --- | --- |
| `GET /api/photo-routes/extractions` | 读取本机已登记提取包目录 |
| `POST /api/photo-routes/drafts/import` | 请求体为 `extraction_id`，按用户和提取包幂等创建草稿 |
| `GET /api/photo-routes/drafts` | 当前用户的草稿 |
| `GET /api/photo-routes/drafts/{id}` | 重开草稿 |
| `PUT /api/photo-routes/drafts/{id}` | 提交名称、颜色、原始难度、备注、对象和 `expected_version` |
| `GET /photo-route-assets/{filename}` | 经过账号及素材归属检查的只读素材 |

默认目录为 `backend/data/photo_routes`，可使用 `PHOTO_ROUTE_DATA_DIR` 指定服务器持久化目录。目录中包含 `drafts.json`、`extractions/`、`assets/` 和进程间锁文件；需要整体备份。素材按 SHA-256 命名并校验。草稿使用原子替换及进程间锁，更新接口不允许改写原始像素边界、素材引用或轮廓复核状态。目录已加入 `.gitignore`，浏览器恢复副本仅保存 JSON，不存图像。

所有写接口复用现有账号与编辑权中间件。手机与电脑连接同一项目服务器、使用同一账号即可读取相同草稿；本次仅验证本机浏览器跨会话往返，未进行真实手机或生产服务器验收。

Vite 和现有 Nginx 模板已增加素材代理路径。未修改运行中的 Nginx，也未执行部署。部署时须设置持久化目录并复制已登记提取包与素材；单纯 Git 同步不包含这些私有运行数据。

## 登记与导入现有证据

在 backend 目录中运行：

```powershell
.\.venv\Scripts\python.exe scripts/import_photo_route_evidence.py --source-dir 'D:\ai_climbing_code'
```

可选 `--data-dir` 和 `--owner`。默认创建本机 `owner` 的两条草稿；线上账号也可从“载入提取结果”创建自己的草稿。重复运行保留已有草稿及编辑版本，不覆盖编辑结果。导入工具检查来源照片、报告/复核指纹、对象蒙版指纹、图像尺寸及透明通道。

- 黄色：12 个对象，排除 `object-09` 贴纸，轮廓状态仍为暂定。
- 蓝色：10 个对象，包含 `object-06` 灰蓝小点；`object-03`、`object-07` 保留“轮廓待修正”。本阶段没有修复这两个分割边界。
