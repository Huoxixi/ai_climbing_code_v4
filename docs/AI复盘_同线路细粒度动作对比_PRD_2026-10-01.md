## 1. 产品问题与目标

用户反复尝试同一条线路时，可能用了相同岩点，却改变了手脚先后、重复调整或局部动作过程。总用时与岩点顺序不足以说明这些差异，普通视频回看又需要用户自行寻找对应时刻。

本功能帮助用户回答：**这次与上次在同一个动作阶段具体哪里不同？原片是否支持这个判断？**

首版目标：

1. 在重复动作、局部插入调整和不同节奏下，寻找可靠的对应事件。
2. 比较手脚启动先后、目标接触与另一肢体启动的先后、运动重叠及同点调整差异。
3. 让每项差异可返回两次原片，清楚保留未知、候选与本人确认的来源。
4. 通过独立对照验证方法是否减少错配或复盘负担，为参赛积累真实证据。

## 2. 用户与使用场景

首要用户是项目所有者本人及获准测试者。教练可作为审核协助者，不新增教练账号、协作平台或付费流程。

典型场景：用户有两次同线路录像；已完成基础分析，必要岩点和动作经过复核；想找到同一阶段、观察本次有无改变，并回看对应画面。

用户故事：

| 编号 | 用户需要 | 成功表现 |
| --- | --- | --- |
| US-01 | 两段视频速度不同，也能找到相同动作 | 选择一组对应动作，两段录像定位到各自真实时刻 |
| US-02 | 分清脚先动与脚先接触 | 两项判断分别展示，证据不足的一项保留未知 |
| US-03 | 知道同点调整是否变化 | 比较完整可见窗口中的调整；遮挡时不把未知当零次 |
| US-04 | 避免重复换点配错 | 显示前后事件与出现次数，歧义可局部核对 |
| US-05 | 修正误识别后结果及时变化 | 新比较引用新版本，旧结果失效，历史原片保留 |

## 3. 范围、优先级与版本

### 3.1 P0：首版必须完成

- 同一人、同一路线版本的两次记录选择与资格检查。
- 已有事件/接触事实/人工修正的只读适配与快照版本。
- 分肢体序列对应，保留重复、未匹配与有歧义的事件。
- 手脚启动先后、接触—启动先后、运动重叠三种关系。
- 同点调整出现位置与数量差异。
- 原片回看、会话内对应关系确认、已有动作修正与重新比较。
- 候选/未知/本人确认来源、结果失效和错误恢复。
- 算法对照、构造反例与真实先导评价。

### 3.2 P1：首版验收后深化

- 同一对应窗口的时间分布：可见静止、运动、接触后调整、未知。
- 原片支持的伸出—收回—再伸出过程；区分轨迹往返与离点再接触。
- 既有可靠躯干参考下的相对运动过程比较。

P1 每项必须另有完整证据和可测收益，不能为“识别更多”直接开放全部字段。

### 3.3 本需求不包含

跨人技术评分、跨线路/跨版本迁移、自动最优 beta、读线计划录入、专业技巧自动确认、受力或伤病判断、新姿态模型、专用模型训练、全片加密云分析、比较视频合成导出、教练平台和新增业务表。

这些内容不因本 PRD 自动获得实施授权。当前照片链、基础视频和用户确认的统一复盘框架继续沿用。

## 5. 核心概念与判断语义

### 5.1 事件与岩点身份

比较单元由肢体、运动事件、确认点身份、接触事实、证据时刻和可见范围组成。岩点需要映射到同一 `route_version_id` 下的确认 `saved_object_id`；两段视频各自的检测编号不能直接等同。

同点位置调整、原点重新抓握/踩放、离点再接回分别保留。相同证据重复引用需要去重；同点发生的不同真实事件不得去重丢失。

### 5.2 原片时间与边界范围

全部统计和算法使用原片时间。播放保持默认 0.75 倍速；裁剪偏移和媒体时间映射必须通过已有时钟适配处理一次。

每个关键边界保存估计时刻和证据支持的范围 `[earliest, latest]`。范围表达时间分辨率/定位不确定性，不是统计置信区间。原片帧率不能代替实际分析采样率；没有邻近证据或存在大缺口时，不制造精确边界。

### 5.3 三种手脚关系独立成立

- **启动先后**：比较两条运动链的启动边界。
- **接触—启动先后**：比较已核对目标接触边界与另一肢体启动边界。
- **运动重叠**：比较两条运动区间的可靠重叠。

脚先启动与运动重叠可以同时成立。边界范围相交表示先后无法确定，不自动表示同时。脚接触不能改写为踩稳、承重或支撑成立。

### 5.4 确定、候选和未知

身份、事件对应、边界和可见性分别存状态。机器局部核对不是独立人审，不能将 `locally_verified` 显示成“专业确认”。

产品展示保留三种来源：自动待复查、基于本人修正记录计算、本人确认对应关系。最后一种只确认事件配对，不连带确认接触、动作事实或算法准确率。

未知不是零次调整、没有动作或没有接触。无法比较的原因应具体到“岩点未确认”“对应有歧义”“时间精度不足”“脚部遮挡”等。

## 6. 用户流程与页面设计

### 6.1 正常流程

1. 用户打开一条已完成分析的复盘记录，在现有页面展开“同线路细节比较”。
2. 从同账号、同线路版本的已完成记录中选择另一次尝试，确认同一攀爬者及相似机位。
3. 服务端校验资格并取得有效快照；页面展示可比较事件、待核对事件和缺失材料。
4. 用户点击“比较动作细节”，获得对应阶段与差异列表；首次进入页面不自动生成分析或付费任务。
5. 选择差异卡片，按按钮回看两次对应原片，查看最少必要证据。
6. 有配对歧义时选择候选对应或标为“无法对应”；原动作错误则进入已有修正流程。
7. 修改原动作后取得新快照并重新比较；旧卡片标失效，不能继续当作当前结论。

### 6.2 信息布局

现有统一播放器、真人骨架/岩点、线路动作图、下方动作顺序保留。细节比较是页面内折叠区域，不另开新业务入口。

区域顺序：两次记录标签 → 可比较范围摘要 → 差异卡片 → 当前选中卡片的证据回看。未选中卡片不同时展开多个播放器。桌面可并排两段局部视频，手机纵向排列；每段显示自己的原片时刻。

差异卡片只展示：肢体/岩点、变化短句、来源状态、“回看两次”“核对对应”。技术字段、误差与完整上下文放入默认折叠的证据详情。

P0 不默认逐帧双视频同步播放。先提供两个对应片段的准确定位与独立回看，避免因速度不同产生错误同步印象。自动播放只由用户点击触发。

### 6.3 卡片与文案

构造例，不是实际分析结果：

- “这一段，左脚目标接触先于右手启动；上次顺序相反。”
- “对应窗口内，本次少一段已核对的右手同点调整。”
- “两次都经过 4→7，但重复段的对应仍需核对。”
- “脚部被遮挡，暂时无法比较接触先后。”

不输出“更省力”“脚已踩稳”“读线更好”“力量不足”等无依据评价，不因第二次更快自动显示绿色成功或能力分数。

### 6.4 交互与无障碍

键盘能完成选择记录、展开卡片、回看和确认；状态不只靠颜色区分。手机至少核验 360×800、390×844，桌面核验 1440×1000。列表长时先显示差异，仍可查看全部对应/未知区段，避免只展示漂亮结果。

## 8. 对应与细节计算规则

### 8.1 事件对齐

分别为四肢构建事件序列，以确认岩点和前后事件上下文寻找候选对应，采用允许未匹配的序列对齐。每个事件最多对应一个事件。

同肢体序列保持真实先后；不强制四肢共用全局动作顺序，因为跨肢体先后变化就是待检测对象。

对应成本优先使用身份、类型与上下文；时长不是主要匹配标准，以免把要比较的差异预先筛掉。持续时间与轨迹相似性如用于歧义消解，必须单独对照验证。

无身份锚点、等价最优候选或矛盾上下文应返回歧义，不以随机顺序选择。参数/阈值只在开发材料调整，独立评价前冻结。

### 8.2 时间关系

若事件 A 的启动上界小于 B 的启动下界，支持 A 先启动；反之支持 B 先启动；其他情况为先后未知。接触—启动关系使用相同区间规则，但接触证据必须另行合格。

运动区间的起止边界分别有范围。重叠下界取“最晚可能启动”至“最早可能结束”的交集；重叠上界取“最早可能启动”至“最晚可能结束”的交集。达到冻结最小有效重叠门槛的下界才确认重叠；只有上界可能达到时标未知。门槛来自现有合同与采样条件，不能看到结果后放宽。

区间两侧是否都具有有效证据必须单独检查，公式不能使遮挡区段自动合格。

### 8.3 同点调整

先建立前后共同锚点组成的对应窗口，窗口不得任意越过未知范围。在同肢体、同确认岩点、同定义的可见调整事件中计数。

仅位置变化不能确认原点重新抓握；离点—接回需各自事实。窗口内未观测范围使精确数量未知，可显示“至少观察到 n 段”，但不能参与精确数量差。

### 8.4 差异排序与来源

先按线路/动作进程展示可靠差异，再列候选与未知。排序不以“越快越好”或专业技巧标签为依据。修正或配对确认不自动进入训练数据。

## 9. 输入输出与接口设计

本节为拟议合同，字段和接口尚未存在。实现阶段 0 冻结名称后再编码。

### 9.1 输入快照

| 字段 | 说明 |
| --- | --- |
| `job_id / route_id / route_version_id` | 同账号记录与线路身份 |
| `comparison_input_version` | 基础结果、有效动作版本、修正版本、证据/媒体状态与适配版本的摘要 |
| `action_result_version` | 有效已保存动作版本；只读派生来源可为空 |
| `input_kind` | `saved_actions` 或 `derived_readonly` |
| `events[]` | 稳定事件引用、肢体、类别、映射岩点、边界、事实和来源 |
| `evidence_windows[]` | 原片可见范围、采样/配准缺口及证据引用 |
| `media_availability` | 两次原片与显示媒体分别是否可用 |

适配层对只读派生输入生成确定性比较摘要，不写回任务，不提供虚构 `result_version`。细节不足则保留基础比较并显示缺口，不能自动生成云动作分析来补齐。

### 9.2 拟议接口

- `POST /api/climb-replay/comparisons/fine/preflight`：读取两条记录的资格、快照版本、可用维度与原因；不写数据或触发云调用。
- `POST /api/climb-replay/comparisons/fine`：对指定快照计算结果。请求只传记录 ID、两个版本、同人/相似机位确认及有限会话配对覆盖；禁止客户端直接提交事实作为已确认输入。

会话配对覆盖包括确认对应或标记无法对应。校验同肢体、当前版本、合法事件 ID、一对一和同肢体非交叉。不允许覆盖接触事实、边界或机器质量成绩。

响应包括 `schema_version / algorithm_version`、两个快照版本、`status`、各维度覆盖、`matches / ambiguous_matches / unmatched_events / differences / unknowns` 及证据引用。状态为 `complete`、`partial` 或 `insufficient`，`complete` 只表示计算完成，不表示每个事实都经专业确认。

每个 `difference` 包含类别、两次事件引用、对应窗口、数值或关系、来源、证据状态、未知原因及允许展示的短句。证据引用指向账号隔离媒体接口，不返回本地路径、私密配置或原始媒体数据。

### 9.3 状态与错误

| 情况 | 拟议处理 |
| --- | --- |
| 未登录 | 401，提示登录 |
| 无权限或记录不存在 | 沿用既有账号隔离语义，不泄漏其他记录是否存在 |
| 同条记录、线路不符、同人/机位未确认 | 422，指出合法范围 |
| 分析未完成、源记录正在删除 | 409，等待或返回记录 |
| 版本不符、源结果变更 | 409 `comparison_input_stale`，清除旧结果，重新预检 |
| 授权撤回 | 沿用当前来源检查，暂停新比较，不要求重新上传私密材料 |
| 细节不足/局部遮挡 | 正常响应 `partial/insufficient`，保留具体原因 |
| 超出冻结事件上限 | 422 `comparison_too_large`，不静默截断或强制近似 |
| 服务暂时失败 | 保留记录选择和提示，用户可重试；无自动云端重试 |

## 10. 保存、版本、并发与兼容

P0 比较计算无新业务实体、不新增表、不修改原片/基础分析/人工历史。结果与会话配对覆盖默认只保存在当前页面内存；刷新可重新计算，界面明确这一点。持久保存比较批注属于后续独立需求。

每次计算读取一致快照；计算结束重新核对输入版本。基础重算、动作修正/撤销、岩点修订、线路版本、授权和删除状态变化使旧比较失效。页面在修正、返回前台及回看前重新预检；发现变化立即停用旧结论。

首版不建设跨请求磁盘缓存。若将来加缓存，必须按账号和所有输入版本隔离，并独立制定失效策略。

旧记录只读兼容：无有效细节时仍可使用旧分段比较；无原片时可回看已有派生媒体，但不得用于新事实确认。关闭细节比较入口即可回退，不需要数据回滚或清理真实记录。

## 12. 评价方法与准入

### 12.1 分层评价

1. **算法层**：固定人工核对事件输入，评价配对、关系和计数。成绩只说明比较算法。
2. **端到端层**：真实原片经过现有识别，评价最终差异及未知。记录识别误差与比较误差各自来源。
3. **使用层**：比较普通回看与本功能的定位/核对时间及修正负担。披露顺序、熟悉度和人工介入。

构造记录用于逻辑验收；少量真实材料用于先导；正式动作识别准确率仍遵循已有独立留出和两名审核者协议。单人先导不替代该协议，也不授予专业技术自动确认。

### 12.2 指标定义

- 配对精度：正确自动对应数/自动对应数；无输出为空，不能算 100%。
- 对应覆盖：正确自动对应数/人审可对应数；与精度同时报告。
- 关系精度：启动先后、接触—启动先后、运动重叠各自正确数/该类确定输出数。
- 调整差异：完整可见窗口中正确数量差/输出数量差；局部未知另列。
- 错误确定数：在遮挡、边界冲突或身份不足时仍输出确定结论的数量。
- 误差与负担：边界误差中位数/P95、配对修正数、关键片段定位与核对耗时。

每项报告分母、可判定机会、未知比例与来源。自动结果和人工覆盖后的结果分表；视频帧不作为独立事件样本。

### 12.3 首版验收条件

- 构造反例、账号隔离、版本失效、时钟和未知保护的硬条件全部通过；缺依据的确定放行在此验收集中为 0。
- 冻结同一输入与评价规则，对照现有起终点匹配、普通序列匹配和候选方法。配对精度不降低，并至少在重复错配、正确覆盖或人工核对负担一项得到实测改善；未改善时保留较简单方法，记录研究结果。
- 真实先导报告样本数和失败情况，不借用既有“95%”目标宣称本功能已达成。
- 缺少正式审核材料时，只交付标明“待复查”的本地辅助工具及研究报告；专业标签和正式识别准入不变。
- 新功能合格不等于生产发布；部署需另有用户明确任务，执行既有发布门禁。

## 13. 主要风险与应对

| 风险 | 处理与停止条件 |
| --- | --- |
| 细节来源不足 | 降为未知/旧比较；不自动付费补分析 |
| 重复序列天然不可区分 | 返回歧义并允许会话核对；不强制唯一对应 |
| 当前采样分辨率过粗 | 关系先后未知；局部加密列后续实验，不全片默认加密 |
| 自己审核造成偏差 | 先导标明单人；正式结果按已有独立审核执行 |
| 新方法比简单规则更复杂但无收益 | 对照失败即缩回简单方法，不叠加新模型 |
| 页面信息过密 | 默认短卡片、只展开当前证据、详情折叠 |
| 开发与其他窗口改动冲突 | 编码前复查工作区，按模块小步修改，保护用户已有改动 |
| 用户把变化当改进原因 | 文案只报告观察，不声称因果、力量或专业优劣 |
