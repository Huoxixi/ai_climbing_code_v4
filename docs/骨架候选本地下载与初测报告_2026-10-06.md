# 本地骨架候选下载与初测报告

测试日期：2026-10-06。基线：local-latest-2026.09.05.3 所在主开发目录。

## 1. 结论

电脑本地推理可行，CPU 与 Radeon 780M 核显都已跑通。本轮骨架推理没有调用付费云端 API。
在本轮真实攀岩画面中，RTMW 的二维骨架整体更贴近可见身体，值得作为本地候选继续验收。
InstantHMR 的已发布权重在部分伸臂、高抬腿和背身画面中明显偏移，建议暂时保留为三维研究候选。
这是视觉初筛，不是有标注真值的准确率评测，也没有与现有阿里云骨架做同帧对照；尚不能宣布优于当前正式方案。

## 2. 实际下载与测试范围

- 下载 InstantHMR、FreeMoCap、rtmlib 源码；下载 InstantHMR ONNX、RTMW 384×288 ONNX 和 YOLOX-S 人物检测权重。
- InstantHMR 权重固定 Hugging Face revision：3504446fc31e7f76fdb1cd7e463189e7cf0fdd0f，80,961,622 字节。主分支近期训练代码的变化不代表本轮测试了未发布的新权重。
- FreeMoCap 侧初测的是其生态使用的 RTMW 模型路线，直接通过 rtmlib 调用。FreeMoCap 源码默认配置包含较低分辨率的 rtmw-x-l_256x192；本轮测试用 384×288 版本。因此本结果不是 FreeMoCap 默认设置的整机速度或完整软件验收。
- FreeMoCap 完整图形界面、多机位录制、相机标定、三角测量及 Blender 导出尚未运行验收。现有素材是各自单视角视频，不能据此验证多视角三维准确度。
- GitHub 元数据接口限流，三个源码包记录下载时的 main 快照及压缩包 SHA-256，没有虚构固定提交号。下载清单包含来源、大小、摘要及模型版本。

## 3. 素材与方法

素材为首批十段的当前“浏览器兼容版”；每段选取约 20%、50%、80% 位置，共 30 帧。
先用共同的 YOLOX-S 检测，再人工核对全部 30 个攀岩者人物框，两种骨架输入完全相同。
另对每段约 80% 位置附近取 3 秒连续片段，按 4 Hz 抽样，共 120 帧。
连续片段使用框重叠率保持人物跟随，没有框丢失回退，最小相邻框 IoU 为 0.460；该方法仍是跟随启发式，不是身份真值。
30 帧与连续片段存在重合，不应合计为 150 个独立样本。

RTMW 保留 133 点及每点原始分数；对照图只画躯干和四肢，显示阈值为 0.3，分数不是已校准的可见性概率。
InstantHMR 保留 70 点二维与人体局部坐标三维输出。原模型没有逐点置信度，结果中明确记为 null；人物检测置信度不冒充关节点置信度。
二维腕点映射按源码使用 left_wrist=62、right_wrist=41。

## 4. 本机速度

硬件：Ryzen 7 8745H，Radeon 780M，系统可见约 19.81 GiB 内存。CPU 线程限制为 4。
Python 3.12.14、ONNX Runtime 1.20.1、NumPy 1.26.4；CPU/DirectML 环境分开，原应用环境未被替换。
下表是预热后相同 30 帧的单人骨架调用耗时，包含预处理与后处理，排除找人、视频解码、首次模型加载和渲染。

| 候选 | CPU 均值 | 核显 DirectML 均值 | 核显 P95 |
|---|---:|---:|---:|
| RTMW 133 点，二维 | 158.7 ms | 75.5 ms | 77.4 ms |
| InstantHMR 70 点，二维＋三维 | 152.3 ms | 67.9 ms | 72.6 ms |

核显已通过 ONNX profiler 确认有 DirectML 节点执行，同时有部分算子回退 CPU，不能说全部在 GPU 上运行。
CPU 与核显二维输出差异：RTMW 均值 0.000180 像素；InstantHMR 均值 1.68 像素，最大 20.67 像素。此项只是数值一致性，不是识别准确率。

连续片段中，找人均值 49.1 ms，RTMW 65.7 ms，InstantHMR 61.8 ms。
同时运行两个骨架加找人、读帧和目标框选择约 256.7 ms/帧，输出编码另计。
本轮没有测量单模型完整软件实时帧率，不能把骨架调用速度直接宣传为整段视频播放帧率。
CPU 30 帧测试进程峰值 RSS 979 MB，核显 575 MB；RSS 不含核显共享显存，也不是完整桌面应用总占用。

## 5. 可见问题与证据

- V013，23.70 秒：InstantHMR 腕点和部分肢体线偏离实际身体，RTMW 更贴近可见手臂与腿部。
- V081，10.77 秒：InstantHMR 腿部延伸到身体下方，未贴合实际屈膝和脚部位置；RTMW 更贴近当前画面。
- V082，15.40 秒：InstantHMR 的上举手臂明显偏移，值得作为后续验收样本。
- 多数普通站立与较简单的贴墙姿态两者能给出大致人体结构；RTMW 在遮挡处也有低分、漏画或可能的左右链混淆，不能直接用来确认抓握、踩实和受力。

上述结论来自对照图目视检查，不给出 PCK、MPJPE、准确率百分比或“全部视频正确”等没有真值支撑的结论。
三维输出可用不等于三维姿态已验证；肩髋转角、膝盖角度、身体离墙距离均未完成定量验证。

## 6. 外部服务与费用

| 部分 | 外部连接 | 是否需要额外推理费用 |
|---|---|---|
| InstantHMR 骨架 ONNX | 首次从 Hugging Face 下载模型；缓存后本地推理 | 本轮无需账号、API key 或按次收费 |
| RTMW / YOLOX ONNX | 首次从 OpenMMLab 下载模型；缓存后本地推理 | 本轮无需付费推理 API |
| FreeMoCap 完整软件 | 使用 skellypings 向 Google Cloud 发送使用统计；所下载源码在缺少配置时默认开启，可以在设置关闭 | 使用统计不是付费姿态计算服务；其云端托管费用属于运营该统计服务器的人 |
| InstantHMR 演示查看器 Rerun | 依赖查看器有匿名使用统计，可用 rerun analytics disable 关闭 | 本轮不安装或启动 Rerun；不需要付费云协作服务 |
| 项目原有阿里云姿态、百炼动作解释 | 现有代码仍包含云 API | 改为桌面软件不会自动免除这些费用，需分别替换或保留为用户授权功能 |

本轮只调用本地权重，Python HTTP/socket 在推理进程内被拦截，ONNX Runtime 统计关闭；所有测试记录的 Python 联网尝试数为 0，付费姿态和动作接口调用数为 0。
这不是操作系统全网络抓包，也没有验证 FreeMoCap/Rerun 完整应用关闭统计后的每一种联网行为。
视频仅在本地解码；十个输入文件测试前后 SHA-256 一致。

免费与分发许可是两件事：InstantHMR 代码 Apache-2.0，发布权重另有 SAM License；FreeMoCap 为 AGPL-3.0。之后给他人打包时应核对具体组件与权重条款并附带许可证，不能只凭“非商业”忽略许可。本轮未重新分发这些模型。

## 7. 建议后续工作

桌面迁移继续按已有计划搬迁功能，模型替换单独验收。
优先把 RTMW 作为可选本地姿态提供者，保留原始分数、来源、采样间隔和缺失状态；先做同帧人工标注、左右肢体、遮挡、连续轨迹及岩点关联验收，再决定是否替代正式骨架。
InstantHMR 暂时不驱动接触判定和精确三维动作评价。
FreeMoCap 多机位三维作为未来采集能力评估；若只有当前单视角素材，本地二维路线更直接。
没有修改正式应用、付费门禁、历史复盘、`.local/` 或生产部署。
