# 照片线路服务器隔离验证

用途：测量当前算法在目标服务器上的完整处理耗时、识别进程内存和真实输出。**这是实验验证包，不是生产发布包，不能将运行成功等同于验收通过。**

当前受限 SSH 通道只允许既有运维动作，不能上传/执行这类基准。需要有服务器控制台操作权限的人完成下面的隔离运行；无需放宽既有 SSH 权限或改动正式服务。

## 验证包

本机 `D:/ai_climbing_code/photo-route-evidence/photo-route-benchmark-v6-batch2-r2.tar.gz` 包含：两张原始样本（仅重命名）、本地 MobileSAM 代码及权重/许可证、独立识别代码、测量与计数脚本、逐文件 SHA-256 清单。无账号、凭据、业务数据、完整后端或前端。

推理用本地权重，不下载模型、不向外部识别服务上传照片。安装依赖时只下载公开软件包。若目标服务器不能联网安装，应先由运维准备离线软件包。

## 操作

将压缩包上传到服务器的独立测试目录，例如 `/tmp`，解压后进入 `photo-route-benchmark-v6-batch2-r2`。不要放进 `/opt/ai-climbing/current` 或 `/var/lib/ai-climbing/data`。确认测试时服务器没有重要写入/计算任务，并检查磁盘、内存与 swap 的余量；测试脚本不停止生产服务。

以下使用独立 Python 3.12 环境，不安装到生产虚拟环境：

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install torch==2.8.0+cpu torchvision==0.23.0+cpu --index-url https://download.pytorch.org/whl/cpu
.venv/bin/python -m pip install timm==0.9.16 numpy==2.5.1 pillow==12.3.0 opencv-python-headless==5.0.0.93
bash backend/scripts/run_photo_route_samples.sh
```

这些版本来自本机实测环境，Linux 安装和运行尚未在目标服务器验证。如没有可用安装包，请保留安装错误，再确认兼容版本；不要将不同运行环境当成同条件测试。

默认使用两个计算线程、每批两个提示点，顺序处理黄色及蓝色，单张最多 180 秒。结果写入新的时间目录。脚本不改变服务配置、生产代码、数据库、原图或既有实验输出。大幅内存压力可能影响同机服务；本机两批推理峰值仍约 1.4 GB，最终是否可运行须结合实际服务器余量决定。

## 交回的结果

交回 `results/<时间>/` 整个目录，至少包括 `hardware.txt`、两份 `performance.json`、对应的 `evidence/report.json`、蒙版、叠加图及失败日志。失败时也保留目录。

- `wall_seconds` 包含冷启动、导入、解码、模型推理、结果文件编码；不包含网络上传。
- `peak_resident_mib` 是采样到的识别进程树峰值驻留内存统计；不含其他服务、swap 和监督进程，不是整机内存安全证明。
- `timed_out`/`cancelled` 会终止推理进程树，不继续偷偷处理；硬超时与输入保留已在 Windows 测试，Linux 行为待此轮核验。
- `deployment_hardware_verified` 默认仍为 `false`，收到硬件信息和原始证据后人工核验，不能自动因为测量脚本在某台机器跑过就改成通过。
- 逐对象复核须绑定本次 `result_sha256`，蒙版变化后必须重新复核。不得套用旧编号或只填一个“耗时已验证”布尔值。

完整功能仍须等待轮廓质量、人工基准与服务器性能通过。当前蓝色大岩点含底座、黄色贴纸误选等缺口详见续接验证记录。
