## 1. 本质：真实接触位置不等于手腕或脚踝位置

用户能在原片看见手指抓到点、脚尖踩到点，算法却可能只检查手腕或偏移后的脚踝。此时骨架关节即使准确，接触也会漏判。因此目标不是扩大所有岩点的吸附范围，而是使用与真实接触有关的身体部位和过程证据。

亮点目标按用户“碰到应正确显示”的要求定义为：有可见证据支持手/脚与指定岩点接触。短暂碰触、持续使用和受力是不同概念；短触不能被稳定使用门槛直接抹掉，稳定使用另行统计，当前单视角图像不能保证抓握、踩实或承重。该定义用于设计和验收，改变运行规则仍须经过正负例验证；原来的 0.4 秒规则保留为现状基线。

## 2. 漏亮可能发生在不同环节

| 检查问题 | 结论与处理 |
| --- | --- |
| 岩点根本没进地图，或编号/轮廓错误？ | 先归岩点专项；接触规则不能凭空补岩点 |
| 手脚关键点缺测、错位或身份错？ | 先归骨架专项；不靠放宽容差掩盖定位错 |
| 指尖/鞋尖在点上，但腕/踝在外？ | 接触代表部位不对，需细部或区域证据 |
| 接触短于统一停留门槛，或细小抖动不断重置？ | 查事件定义与时序判定 |
| 接触数据已经存在，页面或导出没显示？ | 查源帧时间和渲染，不新增识别 |

当前 `_contacts` 使用手腕 9/10、脚踝 15/16，脚部固定下移 0.02，轮廓附近容差 0.02，持续约 0.4 秒才确认。同一组参数承担不同部位、不同岩点尺寸和不同接触时长，必须拆开验证。

## 3. 首轮实验：逐步替换输入，找到能恢复亮点的最小变化

对每个可人工确认的漏亮事件记录肢体、岩点、最早/最晚可支持时间、当前输入和拒绝原因。保留长时间稳定接触和短暂接触两组，含手指在外、脚尖在外、遮挡及相邻点。原片看不清的接触保持未知，不当成漏亮真值。

| 实验 | 输入和变化 | 判断 |
| --- | --- | --- |
| L0 现状 | 当前地图+当前骨架+当前规则 | 基线漏亮发生在哪一步 |
| L1 地图核对 | 仅替换为人工核对地图 | 岩点误差贡献 |
| L2 关节核对 | 在 L1 上仅替换为可见的正确腕/踝 | 骨架误差贡献；腕/踝正确仍漏说明规则有局限 |
| L3 接触部位 | 在正确地图上比较已有 wholebody 细部/可见手脚区域 | 真实接触部位能否提供额外证据 |
| L4 时间核对 | 固定空间证据，分离短碰与持续使用并检查源帧区间 | 门槛、采样缺口及闪断贡献 |
| L5 显示核对 | 固定已有事件，比对原片、页面、导出 | 判断是否只是没正确画亮 |

替换实验中的人工输入仅作诊断，不算全自动成绩。原因可能叠加，记录每步恢复了哪些事件，再验证同类事件能否由自动方法恢复。

## 4. 改进路线：部位证据优先，时间门槛随后

先在当前源帧统一手脚与投影岩点的二维关系，核对坐标/方向/缩放；相机变换不等于已测得真实深度。距离使用有清楚尺度的像素或人体/岩点尺度，不能直接用固定归一化偏移跨画幅套用。

首选核验已有 wholebody 中手指和脚尖能否可靠定位；低清不可靠时使用有图像支持的局部区域，并保留部位不确定性。接触区应与手脚实际可见部分关联，不简单取整个手脚包围框与岩点相交。证据仍不足时保留未知，不能只把范围扩到附近点。

随后分离接触开始、持续支持和离开。确认时间与接触实际开始时间分别记录：离线分析可以用后续证据核验早先接触，但不能无条件把所有候选开始时间倒填为确定接触。短暂接触不被持续使用门槛自动抹掉。

稳定接触的小量位置抖动，先复核该部位与同点的连续证据，再允许有限状态延续；遮挡、配准失败和另一点竞争时不强行延续。置信度变化不等同真实离点，真实离点也不能被“防闪烁”抹去。

## 5. 与误亮方案的共同约束

每次找回接触，都要检查非接触经过、相邻点和遮挡片段新增了多少误亮。若只靠增加空间容差或延长历史状态恢复漏亮，却带来等量或更严重误亮，则候选不采纳。

缺测和弱证据不是“确定未接触”，也不是“确定接触”。内部共同状态为无接触支持、接近、接触有支持和未知；原始数据、事件和显示分别核验。漏亮与误亮两份计划必须共用最终状态引擎、事件定义和时间合同，不开发两套互相矛盾的规则。

## 6. 验收方法

对人工可判读的正接触事件，按肢体+岩点+时间一一匹配，报告漏事件、漏亮时长、开始/结束偏差和时间交并比；短碰与持续使用分报。手/脚、小点/大点、遮挡/无遮挡分别列出。

当参考标注确认接触而系统输出未知，该事件仍是没有提供有效亮点，计入端到端召回缺口，未知数量另报；不能把系统不知道的正例从分母删掉。参考本身无法判断的区间才排除真值评分，并报告覆盖。

有效改善须提高真实接触恢复和时序准确性，满足误亮计划的负例约束，页面与导出一致。固定匹配及时间容差，不通过整体延长亮点来提高覆盖，也不拿“该点最终用过”代替正确过程时序。

## 7. 效果不足时的 GitHub 路线

腕/踝正确仍漏时，重点检索 `hand object contact`、`foot contact`、`temporal contact detection`、`climbing hold usage`，阅读接触部位和时序证据实现；不要继续只找全身骨架榜单。[MMPose](https://github.com/open-mmlab/mmpose) 可用于细部定位经验，[The Way Up](https://arxiv.org/abs/2505.12854) 可用于攀岩使用点及时序评价参考；后者不是已核验高星仓库。

按总入口规则筛选高星相关项目及作者代码，核验具体任务定义。有些论文预测的是承重、三维接触或室内物体互动，不直接适用于本场景。必须在同一漏亮集与误亮负例集共同对照；没有改进证据就保留原默认和失败记录。

## 8. 交付物与第一动作

第一动作是对真实漏亮事件检查“地图是否有点、关节是否正确、已有接触是否已经写出”，然后用 L1/L2 分离上游误差和接触部位问题。首轮交付漏亮来源、最小恢复条件、误亮副作用和时序误差；不能以重新识别整片代替因果定位。

实现涉及 `_contacts`、`add_attempt_source_times`、`replay_analysis_view.py` 和前端 `displayedHoldColors`。已有亮点记录、原片和手工轮廓保留；新版结果独立输出，本文尚未实施。
