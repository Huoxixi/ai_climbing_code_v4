# 岩点接触误亮：专项优化计划

2026-10-11 首轮已执行并独立验收：[实施与验收](接触误亮_首轮实施与验收_2026-10-11.md)。非法输入和显示区间修复通过，整体真实误报验收尚未通过；下文保留原计划。

日期：2026-10-11。状态：方案深化；误亮类型和真实改善尚未实测。共同实验约束见 [质量优化总入口](视频复盘_岩点骨架接触优化计划_2026-10-10.md)，对应反向约束见 [漏亮计划](岩点接触漏亮_专项优化计划_2026-10-11.md)。

## 1. 本质：画面上靠近不构成接触证明

手从岩点前经过、悬在其前方或骨架错位，都可能让二维坐标落进岩点区域。即使位置持续一段时间，也不足以直接证明抓握或踩实。误亮优化需要提高“亮起来所需的证据”，同时承认单视角中无法消除的歧义。

目标是让亮点成为有依据的观察结果，而不是最近岩点的自动吸附。弱关节、模糊边界和配准不稳都应降低判断确定性；不确定性越大，不应通过越大的容差获得越确定的接触。

## 2. 首先区分五类误亮

| 误亮来源 | 核验与首要处理 |
| --- | --- |
| 原骨架错位 | 原片叠加检查；进入骨架专项，弱或冲突关节不支持确定亮点 |
| 岩点轮廓/身份错误 | 核验粘连、错合并、相邻编号和配准；进入岩点专项 |
| 真实部位经过但没有接触 | 负例中检查进入—持续—离开及局部可见证据；修改接触定义 |
| 容差/偏移造成吸附 | 固定输入对照不同尺度、相邻点和边界；不能简单选最近中心 |
| 时序/显示残留 | 事件结束后继续亮、回拖亮未来点、页面与导出不同 |

最后一帧统一亮起历史使用点是现行产品行为，需与过程中的“当前接触”分别核验，不能把该汇总本身报成缺陷。若历史使用记录原本错了，仍应追查其接触证据。

## 3. 已确认的当前风险

`_contacts` 可使用分数 ≥0.15 的腕/踝，画面骨架通常要求 ≥0.5；两者可靠性口径不同。它使用统一 0.02 邻域和固定脚踝下移，存在多个候选时按中心距离选择，再用约 0.4 秒持续作为确认条件。

在 720×1280 画面中，归一化轴距离 0.02 分别对应约 14.4 和 25.6 像素；脚部下移也约为 25.6 像素。这个量可能大于小脚点的有效边界误差，且归一化二维距离与源像素距离不相同。它是需要实测的风险，不能据此断定所有误亮都来自该参数。

短时稳定的错误关节同样可以通过持续门槛。把关节分数整体调高可能减少误亮，但同时漏掉真实接触；分数高也不保证没有错误，因此不能只靠单阈值解决。

## 4. 首轮实验：固定输入检查亮点依据

建立人工可判断的负例：经过、悬空、离点、相邻点竞争、遮挡后错误恢复；保留稳定真接触及短碰正例作为反向约束。无法判断接触深度的样本列为歧义，不能硬当负例。

| 实验 | 只改变的条件 | 回答的问题 |
| --- | --- | --- |
| F0 现状 | 保存每次亮点的部位、候选、分数、距离和持续记录 | 到底是哪条证据让错误点亮 |
| F1 上游核对 | 使用人工核对地图与可见关节 | 输入正确时规则还会误亮吗 |
| F2 可靠性 | 固定位置，比较弱关节/冲突/缺测门控 | 有多少误亮来自不可靠位置，有多少真接触丢失 |
| F3 空间规则 | 固定序列，对照无固定脚偏移、尺度校准及多点歧义拒绝 | 扩大范围和最近中心贡献多大 |
| F4 时序证据 | 固定空间候选，检查前后运动与接触支持 | 能否区分经过、离点和稳定接触 |
| F5 渲染 | 固定事件数据，核对暂停、回拖、末帧与导出 | 误亮是否只是显示残留 |

F2/F3 是归因对照，不预设取消偏移或提高门槛就成为新默认。候选必须与 [漏亮计划](岩点接触漏亮_专项优化计划_2026-10-11.md) 使用同一正例集验证。

## 5. 目标方案：足够支持才亮，歧义保留为未知

接触候选应先通过岩点身份、该部位可靠性、坐标一致性及局部图像支持，再结合时间证据。人体轨迹、停留、接近方向等只能提供支持，不能独立证明受力。多点候选无法区分时，不按最近中心强行选一个。

空间距离统一到当前源帧的清楚尺度。位置误差较大时产生更宽的不确定区域，而不是扩大确定接触区；岩点间距和细部是否可判读共同决定能否接受指定点。不会因为点缺亮就倒推手应该在那里。

时序状态采用与漏亮计划共用的接近、接触有支持、无接触支持和未知。确认与离开条件分别核验；离点后无支持必须退出，缺测时不得无限沿用上一次亮点。用后续证据回核开始区间时也要保留支持，不自动把整段接近都写成接触。

前端只显示保存的已验证事件，并按原片时间绘制，不另起一套最近点判定。回拖不显示未来接触；末帧历史汇总和过程亮点规则分开。页面与导出都使用同一事件身份及时序。

## 6. 验收：降低错误确定性，同时保留有效信息

报告误亮事件数、误亮累计时长、每个肢体的错误点身份、离点后残留时间及负例触发率；零接触负例也必须纳入，不能只评估有攀爬动作的事件。发生同一时刻亮错相邻点时，对错点计误报、对真点计漏报，不能只计一个错误。

同时报告真接触召回、有效输出覆盖与未知比例。在同一冻结负例/正例集合中，候选误亮减少而不是把所有点关闭；参考可判断的正接触被转为未知仍计召回缺口。参考本身不确定的区间单列，不伪造负例。

以共同状态引擎的错误与覆盖曲线选择候选条件，不能分别在两份计划中选择互相矛盾的阈值。采纳要求误亮下降、正常接触保留、离开时序改善，并通过留出与页面/导出检查。不能把“看起来更少闪烁”当成“接触更正确”。

## 7. 效果不足时的 GitHub 路线

输入核对后仍误亮，专项检索接触辨别、负例建模、时序事件边界和不确定性处理，而不是继续换一个检测器。优先找高星相关项目中具体实现及已解决 issue/PR，并对照它们是否需要深度、力传感器或额外视角。

[The Way Up](https://arxiv.org/abs/2505.12854) 为攀岩岩点使用及时间标注提供相关研究入口，不等于这里已验证的高星实现。骨架可靠性经验可从 [MMPose](https://github.com/open-mmlab/mmpose) 核验。模型或项目须能对应具体负例失败原因，不能仅凭星数采用。

若同一二维可见证据支持接触与未接触两种解释，属于观测歧义：降低输出确定性，研究有无额外本地可用证据；不要把换模型当作必然恢复真实接触的承诺。新增视角/深度仅列研究路线，不强迫用户改变当前拍摄和操作流程。

## 8. 交付物与第一动作

第一动作是给错误亮点建立逐帧证据回溯，确认其由弱关节、固定偏移、最近点选择、时序延续还是显示造成。首轮交付 F0–F5 归因、负例与正例配对结果、未知覆盖和资源记录。

实现涉及 `_contacts`、前后端接触时间映射、`replay_analysis_view.py` 与 `displayedHoldColors`。与漏亮专项共用最终规则；旧记录和媒体保留，新结果另存。本文未实现或证明这些改善。
