# AI 攀岩复盘：骨架动作识别与同线路分段对比 PRD

版本：V0.2（2026-09-23，补充开源选型；产品决策待确认）
定位：现有[复盘总 PRD](AI攀岩复盘_PRD与使用权审核_2026-09-20.md)的专项需求，不改变照片线路默认识别流程。
关联词典：[动作命名体系](AI攀岩复盘_动作命名体系与标签词典_2026-09-21.md)、[攀岩动作中文总表](AI攀岩复盘_攀岩动作中文总表_2026-09-21.md)。

## 1. 已确认决策与产品目标

用户已确认：首版分析定点拍摄的攀爬视频，线路难度较小，但素材中的镜头移动不可避免；墙上岩点的轮廓应在墙面坐标中保持固定。只对有充分证据的动作显示专业名称，其他动作只显示基础换点。比较对象是**同一攀爬者上传的两段同一线路视频**，重点看相同两点间的动作耗时是否缩短。

用户已确认开源选型的费用边界：**不新增付费服务，现有阿里云姿态识别暂时保留**；不能因为引入新功能就默认扩大其调用量或改变授权范围。

产品目标不是“凭一个关节角给动作取名”，而是回答：

1. 这一步由哪只手或脚，从哪个已确认岩点移动到哪个已确认岩点？
2. 它经历了多久的准备、移动、落点稳定？证据能否追溯到视频帧？
3. 复攀同一线路时，同一动作段的耗时、调整次数和稳定过程发生了什么变化？哪些差异超出了测量不确定度？
4. 当动作证据足够时，使用攀岩行业术语描述其技术；不够时坚持基础动作名，绝不猜测。

首版面向训练复盘，不是裁判、教练诊断或伤害风险结论。“更快”是时间事实，不自动等于“更好”“更安全”。

## 2. 用户体验与边界

### 2.1 主流程

1. 用户选择本人已保存线路，上传第一次和第二次攀爬视频；两段必须是同一攀爬者、同一线路。允许同一视频先单独分析，第二次上传后形成比较。
2. 系统给出视频质量检查：人物全身可见率、岩点可见率、镜头运动程度、源视频帧率/时间戳、遮挡、是否能对应已保存的线路岩点。
3. 系统以**用户确认过的岩点 ID 与轮廓**为主建立墙面参考，在每帧估计摄像机相对墙面的运动。注册失败的时间段标为“镜头对齐不足”。
4. 系统提取四肢骨架与岩点接触事件，建立“基础换点”时间线；用户可修正岩点、肢体、接触起止和时间边界。
5. 仅在技术标签通过专属证据门槛时，基础名后附专业动作名及通俗说明；否则显示“动作 07 · 右手换点 H04→H09”。不在默认时间线显示“AI 猜测的高抬脚”。
6. 两段视频以同一物理岩点和相同动作锚点配对，展示并排视频、同步时间线、每段用时与不确定区间。用户可逐段确认或取消配对。
7. 系统只对可比动作段计算差值；不能对齐时显示具体原因，保留各视频独立复盘，不生成“进步/退步”判断。

### 2.2 范围

**首版包含**：室内单人攀爬、定点机位为主且兼容轻至中度镜头移动；可见的已保存线路岩点；四肢基础换点；同用户两段同线路的视频对比；高置信的少量技术标签；人工复核和修正。

**首版不承诺**：仅凭单目骨架测出真实受力、三维关节角或重心；识别全部专业动作；跨线路排名；判断动作对错或伤病风险；在遮挡严重、镜头剧烈旋转/变焦、墙面非近似平面时仍自动比较；以 4 FPS 可靠识别腾空、瞬时脚滑或快速摆荡。用户人工补标的技术名称须标明“人工确认”，不能伪装成系统识别。

## 3. 动作语义：基础事实、支撑状态、专业技术分开

基础动作以“肢体 + 接触关系 + 起终岩点”为主名称，延续现有左手、右手、左脚、右脚标签。技术名只是可选补充。攀岩术语并非全球完全统一，研究也把“身体位置与稳定等原则”和“特定技术动作”区分开；因此“支撑”是状态描述，不应当作为万能技术动作名。[术语体系研究](https://www.mdpi.com/2411-5142/11/1/103)。

| 用户口语 | 产品用语与通俗解释 | 自动显示需要的证据 | 首版策略 |
| --- | --- | --- | --- |
| “支撑” | **稳定支撑状态**：哪些手脚持续使用哪些岩点；不是特定招式 | 已确认的手/脚-岩点接触区间，身体相对墙面运动趋稳 | 可显示事实，不推断真实发力大小 |
| “支撑着伸手” | **锁臂（Lock-off）**：一侧手臂持续弯曲，维持该手点接触，另一肢体换点 | 手点持续接触 + 支撑侧肘部二维角度在一段时间内维持屈曲 + 另一肢体完成换点 + 关键点无遮挡 | 只有视角和接触均可靠时自动标；否则基础换点 |
| “高抬腿” | **高抬脚（High step）**：脚上到相对身体较高的新脚点，为后续起身提供位置 | 同一脚的新脚点确认 + 新脚点相对骨盆/躯干的归一化高度变化 + 抬脚全过程关键点可见 | 首批候选技术，阈值经标注集校准后才自动显示 |
| “踩高后站起来” | **脚上方重心转移（Rock-over）**：骨盆投影向高脚支撑侧移动并上升 | 高脚点持续接触 + 骨盆相对该脚点跨越/靠近并上升的连续轨迹 + 可见稳定结束 | 不与高抬脚混为一谈；视角不足时仅显示高抬脚或基础换点 |
| “两侧撑开” | **对撑（Stemming/Bridging）**：手脚向两侧相对面施压形成支撑 | 两侧接触和墙面几何可见；单纯双腿张开不够 | 首版人工确认优先 |
| “伸腿保持平衡” | **旗式（Flag）**：非支撑腿伸出以平衡身体 | 自由腿没有实际脚点接触 + 腿的延伸轨迹 + 身体旋转/稳定关系 | 视角与脚点证据足够时才自动标；前/后旗式暂人工确认 |
| “荡” | 需区分**主动摆荡换点（Swing move）**、**抓点后制摆（Swing catch）**、**开门摆动（Barn door）**；后者常指身体绕支撑侧旋开，不等于主动利用摆荡 | 连续轨迹、接触与释放次序、摆荡方向/幅度和是否有效接到目标点 | 4 FPS 单目首版不自动细分；只显示基础换点，允许人工标记 |
| “跳一下够点” | **动态点（Deadpoint）**与**跳跃（Dyno）**不能等同：前者强调到达运动轨迹速度最低的时机，后者涉及明显动态起跳/腾空 | 高帧率时序、支撑解除、身体/手轨迹与落点 | 首版不自动标；人工确认后显示。术语参考[英国登山协会词汇](https://www.thebmc.co.uk/en/climbing-how-to-talk-the-talk) |

同一动作可以有“右手换点”基础名，加一个高置信“高抬脚”作为该动作段的技术标签；标签不得替代基础事实。高级词典沿用现有编号，不在本 PRD 另造同义名称。

## 4. 识别证据与可计算指标

### 4.1 以四类联合证据判定

1. **岩点证据**：来源是用户确认的岩点 ID 和轮廓、视频多帧融合后的目标位置。颜色只辅助候选筛选，绝不是同一岩点身份的唯一依据。
2. **接触证据**：每只手/脚与岩点的开始、持续、结束；区分有效使用、经过时擦碰与遮挡未知。学术数据集采用岩点、肢体、使用起止与遮挡标注，本产品应保持同等级的事件字段。[The Way Up，CVPR 2025](https://openaccess.thecvf.com/content/CVPR2025W/CVSPORTS/html/Maschek_The_Way_Up_A_Dataset_for_Hold_Usage_Detection_in_CVPRW_2025_paper.html)。
3. **骨架证据**：肩、肘、腕、髋、膝、踝的二维角度区间及随时间变化；骨盆与手脚相对位置、移动方向、轨迹曲率和速度变化。二维骨盆中心仅作身体位置代理，不叫“真实重心”。
4. **时序证据**：准备 → 换点/主动作 → 新接触建立 → 稳定/衔接。技术标签必须覆盖它定义中关键的整个阶段，不能只靠单帧姿势。[攀岩动作三阶段研究](https://www.mdpi.com/2411-5142/11/1/103)；[骨架视频阶段分析研究](https://www.mdpi.com/1424-8220/23/19/8216)。

### 4.2 指标定义

- 二维关节夹角：对关节 B 及相邻点 A、C，`θ = arccos(((A−B)·(C−B))/(|A−B||C−B|))`。报告区间/变化，不把单一角度设成全人群通用动作定义。
- 高脚相对高度：在校正墙面竖直方向后，用`脚点相对骨盆高度 / 可见身体尺度`表示；与前一脚点高度及该动作前姿态比较。墙面角度、视角和身材会影响结果，阈值应由本产品标注数据确定。
- 锁臂证据：支撑侧手点持续使用、肘角在连续时段内处于相对屈曲区间且变化小，另一肢体完成换点。不能由肘角推断肌肉张力。
- Rock-over 证据：高脚点接触持续期间，骨盆相对支撑脚的水平位置和高度形成有方向的连续变化；若透视或遮挡破坏轨迹则弃判。
- 摆荡证据：骨盆/躯干围绕已确认支撑点的往返轨迹及接触顺序。单帧身体倾斜、相机晃动或两帧间大位移均不足以命名为摆荡。
- 任何速度、角速度、弧度变化只能根据**有真实采样时间戳**的连续点估计；大间隔缺帧不得用插值曲线当作被观测到的动作。

所有技术阈值都是**待校准参数**，而非现有文献已给出、可直接搬用的“标准角度”。已有骨架攀岩研究使用受控拍摄与更高采样率，其规则不可直接套用于本项目的单目低帧率视频。[研究原文](https://www.mdpi.com/1424-8220/23/19/8216)。

### 4.3 标签输出门槛

输出专业标签须同时满足：岩点 ID 可靠、相关肢体关键点在关键阶段可见、时间连续性足够、动作类专属规则成立、没有同等合理的相反解释、该类在独立验证集上达到预设精确率。任一失败即回退基础换点。详情页可显示“证据不足：脚被遮挡/视角无法区分”等原因，但默认时间线不出现低置信专业候选。置信分数只做内部校准，不把未经验证的 0.93 显示给用户当作概率。

## 5. 移动镜头与固定墙面岩点

岩点轮廓是**墙面坐标**中的固定物体，不是屏幕像素中的固定框。每段视频建立墙面基准帧；用墙面背景特征、用户确认过的岩点轮廓和多帧检测估计每帧到基准帧的变换；在墙面坐标中合并岩点位置并追踪接触。特征匹配 + RANSAC 单应变换是可验证的候选方法，但只在近似平面且匹配足够时使用。[OpenCV 单应变换文档](https://docs.opencv.org/4.13.0/d1/de0/tutorial_py_feature_homography.html)。

每帧记录匹配点数、内点率、重投影误差、岩点轮廓重合度和可见区域。出现快速转镜、变焦、近景人物遮满岩点、不同墙面深度造成视差、画面切换或明显非平面时，不沿用最后一个“好变换”硬推；进入重新捕获或人工选取对应岩点。墙面单应变换只用于墙面岩点，不能把离墙有距离的身体骨架强行投到同一平面；人体运动须另用相机运动补偿与二维可见度门槛。无论镜头对齐成功与否，二维人体角度都不因此变成三维角度；人物转体/出平面时相关标签降级。

两段视频间优先用相同的**已保存线路岩点 ID**配准；无法复用时由用户点选共同岩点。即使颜色相近，未经几何和人工确认也不得自动认定为同一物理岩点。

## 6. 两点间动作段与时间比较

### 6.1 统一的动作锚点

一个可比较的动作段由同一物理线路上的锚点 A→B 定义，并附肢体与阶段：

- **起点**：A 上的指定肢体已经建立稳定接触，且准备转移到 B；记录接触稳定时刻及允许误差区间。
- **终点**：指定肢体在 B 建立有效接触，随后达到稳定或进入下一动作；分别记录“首次有效接触”和“稳定完成”。
- **主指标**：A 稳定→B 稳定的总耗时；**辅指标**：准备时长、移动时长、落点稳定时长、同一段内原点调整/反复启动次数。
- 连续动作没有明显停顿时，不强行截出虚假的稳定阶段；终点使用“下一动作开始前最后可确认状态”，并标记阶段重叠。

两段视频只有在同一线路版本、同一物理 A/B、相同主导肢体与锚点定义、事件可见且镜头配准合格时自动配对。两次走了不同手序或脚序时，允许比较更粗的“共同节点间总耗时”，但**不**把不同技术动作逐一等同；界面明确写“路线区间可比，动作方式不同”。若 A/B 缺失、遮挡导致边界无法估计，显示“不可比”，让用户人工标注共同锚点后重新评估；仍不确定则不算差值。

### 6.2 计算与解释

每段用源视频真实播放时间戳（PTS）计算，而不是只用帧号除以名义 FPS。记首次视频用时 `T₁`、第二次 `T₂`，显示 `ΔT = T₂ − T₁`；负值表示第二次较短。百分比仅在 `T₁` 足够长且锚点可靠时显示：`(T₁−T₂)/T₁ × 100%`。短片段优先展示绝对差值和不确定区间。

现有复盘默认抽样 4 FPS，样本间隔约 0.25 秒，两个边界构成的单段耗时可能有约 0.5 秒量级的最坏采样误差；再比较两段视频，误差可能进一步叠加。这是**仅由采样间隔给出的保守量级**，实际还会受遮挡、接触判定和时间戳质量影响。首版不得对 0.1–0.2 秒差异给出“明确进步”。若差异落在总不确定区间内，显示“本次估计更快/更慢，但当前视频精度下无法确认变化”。

为使小段计时有意义，应在检测到动作候选后，从**原始视频**对该区间做较高时间分辨率的局部重分析，并在保留期内完成；源视频本身不足帧率时如实展示精度限制，不把插值当成观测。不得为计时擅自延长原视频保存期限或改变现有用户授权。

### 6.3 “优化”的安全表达

比较页先陈述事实：“H04→H09：第二次估计耗时缩短；落点稳定时间未缩短/无法判定”。若调整次数、反复触碰或稳定时间也改善，可说“这一段更连贯”；若更快但不稳定，不给单一“优化”结论。不能从视频代理指标推断更省力、技术更正确或受伤风险下降。停顿也可能是读线或休息，不能机械判负面。

## 7. 界面与可修正记录

比较卡片最少显示：线路及版本、两段视频、共同岩点 A/B、主导肢体、两次用时及估计误差、差值状态（较短/较长/无法确认/不可比）、落点稳定时间、调整次数、点击即跳转两次证据片段。默认按线路顺序排列，不按“进步最大”排序诱导误读。

时间线示例：`动作 07 · 右手换点 H04→H09 · 2.1 秒`；证据充分时附 `高抬脚（High step）`。人工更正后，视频叠加、动作名称、比较卡片和知识库索引同步更新，保留“自动/用户/教练确认”的来源和版本。对于未配对区间，标明是“不同动作方式”“看不到 B 岩点”还是“镜头配准失败”，并提供最小人工修复入口。

## 8. 数据契约与现有系统的衔接

不新增照片线路业务实体；本功能只属于独立的 AI 攀岩复盘。可在现有视频记录、岩点、接触与动作结构上扩充下列字段，具体表结构须在实施阶段审查迁移和隐私权限：

| 层级 | 最少字段 |
| --- | --- |
| 视频 | `attempt_id`、用户/线路 ID、线路版本、原视频时间基、质量状态、分析版本 |
| 岩点 | `route_hold_id`、视频局部检测 ID、用户确认状态、墙面坐标/轮廓、对齐质量 |
| 姿态样本 | PTS、关键点二维坐标及可见度、帧级墙面配准质量；不存“真实发力” |
| 接触事件 | 肢体、岩点 ID、起止时间及误差、有效使用/擦碰/遮挡未知、证据帧、来源 |
| 动作单元 | 动作 ID、基础名、A/B 锚点、准备/移动/稳定边界、技术标签及规则证据、用户修正版本 |
| 跨视频配对 | 两个 attempt/action ID、共同岩点与肢体、可比级别、时长及误差、失败原因、人工确认状态 |

当前 4 FPS 基础接触推断可作为起点，但不得把其输出直接包装为完整技术动作识别。本 PRD 的新增逻辑应先走离线验证与人工复核，再进入默认展示。

开源项目选型、授权边界及本地接入方式详见第 11 节；**本 PRD 不授权自动安装依赖、下载权重、调用第三方接口或上传用户视频**。

## 9. 分层交付与验收

### P0：动作事实和计时基础

复用已确认线路岩点；完善移动镜头墙面配准及失败状态；建立源 PTS、接触事件、基础换点和动作段；支持用户修正。单视频先可用。验收必须覆盖固定机位与真实手持轻/中度移动素材，且配准失败时不生成假接触；相同输入重复分析保持稳定动作 ID/时间定义。

### P1：同线路两次比较

同用户/同线路两个视频自动找共同岩点和锚点；自动配对可比段，不能比的明确拦截；支持并排证据、人工改配对、误差展示与局部高时间分辨率重分析。验收重点是配对精确率、人工修正成本、时间边界误差和“无法确认”正确拦截率，不以生成更多比较卡片为目标。

### P2：专业技术标签

先验证高抬脚、锁臂、旗式、Rock-over 等具备明确多证据条件的类别；每一类单独准入。不达门槛时仅显示基础名。动态点、跳跃、主动摆荡/开门摆动等先保留人工确认和研究入口，在源视频帧率、视角、标注量与验证表现足够后再讨论自动发布。

### 评测方案与发布门槛（目标值，非现有表现）

- 由至少两名有攀岩经验的标注者独立标注岩点 ID、四肢接触、动作边界和技术标签；分歧经仲裁，同时记录标注者一致性。建立定点、镜头移动、遮挡、侧身、颜色相近岩点、不同设备及速度的分层样本。
- 训练/调参/验收按攀爬者、线路与拍摄场景隔离，防止同一人的相邻片段泄漏到验证集。先测基础接触及 A/B 配对，再测时间和标签。
- 专业标签采用“精确率优先于覆盖率”：每类独立留出集精确率目标 ≥90%，并公布覆盖率、误判类别和人群/机位分层结果；未达到者不上默认时间线。该 90% 是产品发布目标，不是既有研究结论。
- 时间验收预先确定人工参考边界和容忍窗口，报告边界绝对误差中位数/P90、片段差值误差和不确定区间覆盖率；不得仅报平均误差。不同原视频帧率分别统计。
- 移动镜头验收报告“配准成功率”和“失败时错误比较抑制率”；不能通过牺牲失败检测来提高覆盖。
- 用户修正须可追踪和撤销，历史比较在修正后重新计算；不得悄悄改写原始分析证据或其他用户数据。

## 10. 仍需用户确认的产品决策

1. 若镜头移动/遮挡导致两段动作无法自动配对，是否采用“标为不可比，用户可手工确认共同岩点后重算”为默认？本稿按此保守方案设计。
2. “动作优化”首版是否除了耗时，也纳入调整次数与落点稳定时间？本稿把后两者作为辅指标，不把它们合成为不可解释的总分。

## 11. 开源项目筛选与复用方案

### 11.1 选型硬约束

1. **许可分层审查**：GitHub 仓库公开不等于可直接复用。分别核实项目代码、依赖、预训练权重、示例视频/训练数据、外部服务的权利；代码的 MIT/Apache-2.0/BSD-3-Clause 不自动覆盖其他层。复制或修改代码时保留版权、许可、NOTICE 与修改说明；固定使用版本并记录来源。最终进入发布包前做逐项依赖及媒体编解码许可复核。
2. **无新增付费服务**：生产运行和离线验证不调用 VLM Run、Roboflow 托管 API、付费模型网关或其他新增第三方计费接口；不将用户视频、帧或关键点发给这些服务。开源库自托管仍有服务器算力、存储和运维成本，不能称为“零成本”。已有阿里云姿态调用维持现有授权与预算边界，本功能不得默认提高采样频率或调用量。
3. **尊重现有系统**：优先使用本地复盘中已存在的 OpenCV、已确认线路岩点、视频多帧融合、基础接触和动作记录；开源项目仅填补缺口或作为离线基线。不开辟第二套照片线路生产识别链路，不替换用户确认数据。
4. **先离线、后接入**：下列“可用”表示按仓库明示许可**有代码复用路径**，不是已完成依赖审计、性能验收或生产授权。任何依赖/权重许可不明、无法本地运行、成本不可控或质量门槛不达标的部分均不进入生产。

### 11.4 明确排除的内容

- [vision-demos 的 VLM Run Gateway 接入](https://github.com/jeremyipark/vision-demos/blob/main/rock_climbing/README.md)：其示例要申请外部 API key 并经网关运行 `sam3.1`/`vitpose-plus-large`；即使**示例代码**为 Apache-2.0，也不代表外部服务免费或视频可在现有授权下外传。仅取本地可实现的接触/比较规则。
- 许可证尚未确认的攀岩个人项目（例如 [Dynalytix](https://github.com/Jolieabadir/dynalytix)、[Indoor Rock Climbing Assistance Tool](https://github.com/Laura05010/Indoor-Rock-Climbing-Assistance-Tool)）：可阅读其人工标注/路线校准经验，**不复制代码或权重**，直至仓库权利来源明确。前者关于“受力/伤害风险”的表述也不应进入本产品结论。
- [The Way Up 数据集论文](https://openaccess.thecvf.com/content/CVPR2025W/CVSPORTS/html/Maschek_The_Way_Up_A_Dataset_for_Hold_Usage_Detection_in_CVPRW_2025_paper.html)可作事件定义与评测参考；论文所述视频、标注和可能的权重与论文阅读权不是同一授权。在数据记录页逐项核对许可、影像来源和允许用途前，**不下载、不训练、不放入产品测试集**。
- 通用“动作分类模型”不得直接把某个角度映射为高抬脚、锁臂或摆荡。经此次筛选，没有发现已证明适用于本项目单目、移动机位、低帧率素材且权利/成本边界清楚的现成攀岩专业动作识别器；P2 仍按第 4、9 节逐类建立标注与准入门槛。

### 11.5 按 PRD 分层实施与验收

1. **P0 先用现有 OpenCV 链路**：列出现有墙面配准、岩点融合和基础接触的固定机位/移动机位表现；以 vision-demos 的岩点共识、接触迟滞/持续和漏点告警为对照，仅移植能降低误报的局部规则。`cruxes` 只做隔离原型对比，不因演示效果直接进生产。
2. **P0 时间与角度**：Sports2D 只校验二维计算和角度约定；计时先查源视频 PTS，PyAV 通过依赖/编解码许可门禁后才可能引入。现有骨架仍是 4 FPS 基线，局部加密分析须单独测调用成本和隐私授权，不自动扩量现有付费姿态接口。
3. **P1 两视频比较**：借鉴 vision-demos 的“统一物理岩点编号 + 漏点/漂移警报”，但以本项目已确认的线路岩点 ID 为主键；自行实现同一肢体、同一 A→B 阶段的配对、不确定区间和不可比拦截。原项目的整段序列对比不能直接替代“两个点之间耗时”的产品定义。
4. **P2 高置信技术名**：用自托管 CVAT 建立独立双人标注集，按第 9 节逐类评估。Sports2D 的角度只是输入证据；没有达到该类精确率门槛时，页面继续只显示基础换点。
5. **发布门禁**：生成第三方清单（固定提交/版本、代码许可、依赖许可、权重/数据来源、NOTICE、运行时是否外联、算力/存储成本）、本地样本评测报告与隐私复核结果。缺少任一项即回退本项目已有实现；本 PRD 不允许绕过现有发布流程直接部署。
