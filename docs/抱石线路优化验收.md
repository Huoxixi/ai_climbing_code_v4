# 抱石线路独立模块与岩板体验优化

> 历史记录。当前固定入口、简化流程和验收状态见 [抱石简化流程本地验收](抱石简化流程本地验收.md)。下文的临时 harness 和逐点确认流程已被替换。

日期：2026-09-05。实施分支：`codex/photo-v2-yellow-release`，基线 `b7bf923`。

## 已实现

- 桌面与手机导航均提供独立的“抱石线路”，资产分类仅含岩板、岩点。
- 入口页只有上传、线路库；上传后进入复核、线路编辑，完成保存后进入线路库。支持返回复核、保存草稿、恢复历史版本为新草稿。
- 两张真实参考照片随前端打包；选择样例和自行上传使用相同的上传、识别接口。
- 复核工具按颜色与对象、轮廓修正、孔位确认组织；逐个确认对象及孔位后进入编辑。四角标定明确要求点击 A1、AD1、AD20、A20 孔位。
- 编辑保留吸附、起终点、动作标签、备注、撤销重做；背景处理折叠展示，已完成版本可生成新草稿继续编辑。
- 保存失败保留输入并阻止切页；批量对象保存不会用较早的服务端响应覆盖其他待保存对象；保存中的请求串行处理。
- 抱石画布保持 6200×4100 mm、30×20 孔阵。标准板按各自物理尺寸适配剩余空间；孔点视觉缩细，保留独立点击区域。
- 修复手机板库预览容器收缩；下一步操作位于内容之后，不覆盖岩板。

## 接口兼容

沿用现有接口和数据表。岩板列表、详情增加可为空的 `latest_job`，包含最近一次识别任务的 id、kind、status、stage、progress、error、board_version_id、route_id，供页面恢复识别进度和失败重试使用。不返回内部任务参数，不迁移历史数据。

## 验证

- 前端原有测试：36 项通过；生产构建通过。
- 后端照片线路与背景处理测试：15 项通过，包含新增任务恢复字段及所属用户隔离检查。
- 浏览器集成：电脑 1440×1000、手机 390×844，两张照片均走真实上传和识别。通过图片哈希核对，未使用预置识别结果。
- 覆盖逐项复核、返回复核、编辑、503 保存失败保留输入并重试、完成保存、重新打开、历史版本生成新草稿、筛选、同板叠加、只读权限、标准板尺寸与细孔、页面横向溢出。
- 本地识别使用已有 `local-rules-v2-no-mobilesam` 路径。测试证明流程连通，不代表自动识别准确性已获人工验收；照片轮廓和孔位仍需用户复核。

测试服务 `backend/boulder_test_server.py` 使用独立临时目录，未读取或修改生产数据。浏览器入口 `frontend/e2e/harness.html` 装配真实页面、应用壳和画布组件；普通岩板使用标准尺寸测试数据。

复现：在安装项目测试依赖后，从 backend 启动 `python -m uvicorn boulder_test_server:app --host 127.0.0.1 --port 8002`；从 frontend 启动 `node node_modules/vite/bin/vite.js --config e2e/vite.config.js --host 127.0.0.1 --port 4174`，然后运行 `node --test e2e/boulder-flow.test.mjs`。截图输出至 `frontend/test-results/boulder/`。
